# 阶段感知的搬运流程异常安全设计

**日期：** 2026-07-28  
**状态：** 已确认设计，待实施计划  
**范围：** 1/2号线前后天车、机械手1、机械手2/3、研磨天车的自动搬运动作；业务主文档同步。  
**非范围：** 不改变 PLC/CNC 工艺地址、正常路径业务顺序、工艺参数计算或设备机械动作本身。

## 1. 问题与目标

现有流程中已有许多局部 `try/catch`，但异常语义分散：最外层通常依赖 `mag`、`holdingWorkpiece`、`placed...` 等临时变量判断现场状态。设备命令在“已发出但响应丢失”时，这些变量不一定已更新，因而可能把物理结果未知误判为未执行，并执行自动重试、缓存回退或下一步动作。

目标是让每个自动搬运任务成为一条阶段明确、工件所有权明确、异常结果明确的状态机：

1. 每个物理命令前后都有可追溯的阶段和命令确定性。
2. 只有确认的物理交接才能转移或删除工件缓存。
3. 未发送物理命令的读取/连接失败允许等待重试；命令响应未知、运动超时、非允许下压一律终止本动作并暂停所属引擎。
4. 下压仅在“Z 向下接近预定工位”且实际 Z 已到目标 `±5mm` 时可按到位继续；其它场景均为安全异常。
5. 动作退出且引擎暂停后，释放该动作实际持有的软件锁；保留工件账本、最后位置、异常任务牌和人工处置要求，不永久占锁。
6. 主页面异常、在制工件和《全线业务逻辑详解》能说明“当前在哪一步、板在软件账本的哪里、下一步人工要确认什么”。

## 2. 行为边界

### 2.1 可自动等待的情况

以下条件必须发生在尚未调用运动、磁铁或 PLC/CNC 写命令之前：

- 设备未连接、连接重建中；
- 状态/位置/X11/PLC 请求位读取失败；
- 设备尚未请求数据、目标位暂不可放、研磨机未就绪；
- 共享锁暂时不可取得。

这些情况不改变工件归属、不删除缓存、不暂停引擎；只记录限频等待日志，下一轮重新读取。

### 2.2 必须暂停的情况

以下情况无论现场随后是否恢复，程序均不能自动重发同一命令或进入下一步骤：

- `MoveAbsoluteAsync` 或微调超时；
- 已进入运动/磁铁/PLC/CNC 写调用，连接断开、超时或响应丢失；
- Z 下降发生下压，且实际坐标不在目标 `±5mm` 内或坐标读不到；
- XY、Z 上升、回零等非“允许接近”步骤发生下压；
- X11、磁铁反馈、下游缓存回调或 PLC/CNC 完成命令结果未知；
- 已确认持件后任何未被该步骤安全补偿完全闭环的异常。

暂停表示：取消当前动作令牌、停止本动作后续命令、禁止自动重试、记录人工确认任务。暂停不等于永久保留软件锁。

### 2.3 命令发出与响应未知

程序只能可靠判定“调用尚未开始”或“调用已经开始”。一旦进入写命令调用后异常返回，即使现场实际没有执行，也必须按“结果未知”处理；禁止根据异常文本推断“肯定没发出去”并自动重试。

## 3. 公共动作上下文

新增每次搬运动作独占的 `FlowActionContext`。它由动作方法创建，作为所有局部步骤、统一异常、finally、异常页面和人工恢复的唯一事实来源。

### 3.1 必备字段

| 分类 | 字段 |
|---|---|
| 任务标识 | `OperationId`、线体、引擎、设备号、动作名称 |
| 阶段 | `Step`、步骤开始时间、步骤说明、目标 XYZ |
| 命令事实 | `CommandState`：未发送/已发送待确认/已确认/响应未知 |
| 工件账本 | 工件身份、来源、目标、来源缓存键、所有权状态 |
| 现场证据 | 最后实际 XYZ、目标 XYZ、X11、磁铁命令/反馈、PLC/CNC 关键反馈 |
| 并发资源 | 本动作租约登记的锁集合、取消令牌、动作版本 |
| 结论 | 等待重试/已暂停待人工/已完整交接/已人工处置，以及原因 |

### 3.2 统一步骤枚举

实现可按设备细化名称，但必须覆盖下列语义：

1. `PreCheck`：尚未发物理命令。
2. `SourceReserved`：来源软件身份已保留、禁止其它任务消费。
3. `MoveXYToSource`、`FineTuneSource`。
4. `MoveZDownToPick`。
5. `MagnetOnSent`、`ConfirmPickup`。
6. `HoldingWorkpiece`、`MoveZSafeWithWorkpiece`、`MoveXYToTarget`。
7. `MoveZDownToPlace`、`MagnetOffSent`、`ConfirmPlaced`。
8. `TargetPendingHandoff`、`NotifyDownstream`。
9. `ReturnSafe`、`Completed`。

阶段必须在命令调用**之前**写入；调用开始时写“已发送待确认”；等实际位置、X11、PLC/CNC 或软件回调证明结果后才标记确认。

## 4. 工件账本与来源占用

### 4.1 来源缓存不提前删除

当前后天车等流程常在动作起点把来源缓存移出。改造后：

1. 调度选中来源时，缓存仍保留在原工位，只标记 `Reserved(OperationId)`。
2. 预约状态禁止其它动作再次选择同一缓存，但不会伪造“工件已被取走”。
3. XY、微调、Z 下降、充磁响应未知、X11 未确认期间，来源缓存依然存在。
4. 只有 X11=1 已确认工件被天车/机械手吸住后，来源缓存才正式移除，工件所有权转为 `OnCarrier`。
5. 目标位退磁和目标物理条件确认后，状态转为 `AtTargetPendingHandoff`；下游缓存/PLC/CNC 通知成功后完成交接。

这样，天车尚未确认取走就发生异常时，不需要“猜测是否恢复缓存”；来源身份天然还在，只是带有暂停的预约状态。

### 4.2 人工处置结果

对 `ManualResolutionRequired` 的动作，恢复入口必须显示完整上下文，并要求人工选择唯一结果：

| 人工确认结果 | 账本动作 |
|---|---|
| 工件仍在来源位 | 解除来源预约，恢复来源可派发状态 |
| 工件确认在天车/机械手上 | 保留 `OnCarrier` 人工任务，不能恢复来源、不能自动恢复引擎 |
| 工件已放到目标位 | 写/补目标缓存或下游交接状态；来源永久关闭 |
| 工件已人工移走/报废 | 显式作废该工件身份，并记录操作人和原因 |

不能提供“无选择直接清空所有状态”的成功路径。

## 5. 异常处理职责

### 5.1 局部 catch：步骤级、安全补偿

局部 catch 只用于本步骤已经具备明确证据的补偿；不能决定业务恢复，也不能启动下一步骤。

允许：

- Z 向下接近目标时捕获下压，读取实际坐标；仅实际 Z 在目标 `±5mm` 时确认到位并继续。
- 磁铁命令明确成功、X11 明确为 0 时，按既有次数执行退磁、下探、再充磁。
- 三次 X11=0 后，只有退磁成功且 Z 已确认到安全高度，才把工件继续视为来源位；动作仍暂停等待人工确认。
- 尚未发命令的读取/连接失败转换为等待结果。

禁止：

- 局部 `catch (Exception)` 后清报警并继续 XY/Z；
- 命令响应未知后自动重新发同一命令；
- 在局部 catch 清缓存、设设备 Idle、释放其它动作的锁；
- 用“没有抛异常”推断磁铁、PLC 或物理交接成功。

### 5.2 统一 catch：给动作下唯一结论

统一 catch 接收已标准化的阶段异常，依据 `Step + CommandState + WorkpieceOwnership` 只选择一种结果：

| 条件 | 结论 |
|---|---|
| 尚未发物理命令 | `WaitRetry`，保持缓存和正常循环 |
| 命令响应未知、运动超时、非允许下压 | `PauseManual`，位置/命令未知 |
| X11 明确未吸住，且退磁与安全 Z 已确认 | `PauseSourceReserved`，来源缓存保留且预约 |
| X11 已确认吸住 | `PauseOnCarrier`，保留在途身份，禁止恢复来源 |
| 已确认目标放料但下游通知失败 | `PauseAtTargetPendingHandoff`，保留目标待交接身份 |
| 已完整交接 | `Complete` |

统一 catch 必须：停止后续步骤、暂停所属引擎、记录上下文、创建异常任务牌、写结构化异常监控事件，并明确人工下一步。它不得再发运动、磁铁或 PLC/CNC 命令。

### 5.3 finally：确定性的资源收尾

finally 不处理业务判断，只做：

1. 完结动作版本，使旧 await 返回后不能再写状态或发命令；
2. 清理当前动作 busy 标志、完成信号和临时取消对象；
3. 动作已经退出且引擎暂停后，按动作租约释放自己登记的后天车锁、区域锁和位置锁；
4. 保留工件账本、异常任务牌和人工处置状态。

finally 禁止：移动、充退磁、写 PLC/CNC、猜测工件位置、恢复/删除缓存、把斜床或研磨机强制设为 Idle。

## 6. 后天车上料标准模板

后天车从中转架到斜床的迁移模板如下：

1. 核验中转架“物理有板 + 软件缓存”，创建来源预约。
2. 完成天车连接、XYZ、Z=0、X11=0 等前置读取；失败只等待。
3. XY 去来源位并微调。
4. Z 下降、充磁、X11 三次确认。
5. X11=1 后才移除来源缓存，写 `bed.Wp` 和 `OnCarrier`。
6. Z 升安全，XY 去斜床并微调，Z 下降放料。
7. 退磁、Z 安全、斜床 PLC/CNC 上料握手。
8. 握手确认后设置斜床加工中，完成目标交接。
9. 天车归位是独立阶段；归位失败不能倒退已确认的斜床交接。

1/2号线后天车采用同一模板，仅来源工位、斜床设备与位置锁不同。

## 7. 迁移顺序与验证

按风险和复用顺序实施：

1. 公共动作上下文、阶段异常、来源预约、任务牌/异常展示数据。
2. 1/2号线后天车上料。
3. 1/2号线后天车下料。
4. 1/2号线前天车与机械手1。
5. 动平衡 M2/M3。
6. 研磨天车上料/下料。
7. 同步更新 `Docs/全线业务逻辑详解.md`，逐步列出正常步骤、物件账本、等待条件、异常分类和人工恢复选项。

每个迁移步骤至少覆盖：动作前读取失败、XY 超时、微调失败、允许/不允许下压、充磁响应未知、X11读取失败、三次X11=0、退磁响应未知、下游通知失败、人工处置四种结果、锁释放、旧动作不能复活、成功路径不变。

## 8. 验收标准

1. 任意异常页面能够显示当前业务步骤、工件、来源/目标、目标和最后坐标、命令确定性、X11/磁铁证据、缓存所有权、人工处置要求。
2. 不再存在“命令可能发出但自动按未执行重试”的路径。
3. 不再存在“来源缓存先删、异常后只能猜是否恢复”的路径。
4. 不再存在下压恢复后未确认步骤状态就自动进入下一步的路径。
5. 每个暂停动作退出后不遗留软件锁；恢复前不会自动再次派发该工件。
6. 正常业务流程、PLC/CNC 地址和现有可确认交接顺序保持不变。
