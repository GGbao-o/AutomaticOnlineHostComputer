# 全流程状态悬停详情设计

## 目标

在既有“全流程状态”页面内，以鼠标悬停 Tooltip 展示工件和当前任务详情。页面保持原有简洁状态文字；鼠标停留约 1 秒显示详情，移出卡片立即收回。不新增独立加工看板页面，不新增数据库，不改变设备、队列、锁或流程调度。

## 范围

第一版覆盖以下只读详情：

1. 1、2 号线十台斜床：ST108~ST112、ST606~ST610。
2. 四台研磨机：ST701~ST704。
3. 六个中转架：ST105/ST101/ST106、ST016/ST017/ST018。
4. 五台天车：1 号线前后、2 号线前后、研磨天车。

不在第一版提供“已完成”历史。工件下料成功后既有流程会清除在途工件，页面只如实显示空闲、上料中、加工中、等待下料或下料中。

## 用户体验

### 斜床和研磨机

鼠标停留在设备状态区域 1 秒后显示：

```text
ST108 — 加工中
工件：版号=121 序号=5
直径：250mm    长度：1280mm
工艺：粗精一体倒角(2)
开始时间：10:31:12
当前状态持续：12分30秒
```

空闲设备显示“当前无工件”。如果设备处于运行状态而本地工件身份缺失，则明确显示“需人工补录工件信息”，不能显示为空闲或未知工件。

### 中转架

鼠标停留在现有中转架组卡片上，显示每个位的物理有板状态和软件工件身份：

```text
ST105：物理有板
工件：版号=121 序号=5，D=250mm，L=1280mm

ST101：物理有板，但软件身份缺失
ST106：物理无板
```

“物理有板、软件身份缺失”和“物理无板、软件缓存存在”均以异常不一致方式显示，不能把它们伪装成正常缓存。

### 天车

五台天车沿用现有实时状态卡片。悬停显示当前流程任务：

```text
1号线后天车 — 执行中
工件：版号=121 序号=5
阶段：中转架取料后，前往斜床 ST108
来源：ST105    目标：ST108
```

安全异常或人工应急暂停时保留身份：

```text
等待人工确认
工件：版号=121 序号=5
现场：X11 已确认持件，尚未放入斜床
```

只有正常动作完成，或应急操作明确完成“作废/恢复”后才能清除此身份。

## 架构

### 只读快照边界

流程引擎继续独占 PLC 通信、工件缓存、调度和安全锁。每个引擎只增加公开的快照读取方法，返回值为独立复制的数据，不暴露可变的内部上下文对象。

快照模型至少包括：

- `WorkpieceDisplaySnapshot`：版号、序号、直径、长度、斜床工艺。
- `CraneTaskSnapshot`：天车编号/名称、执行状态、工件、阶段、来源、目标、是否等待人工确认、更新时间。
- `ProcessStationSnapshot`：站号、状态、工件、状态开始时间、需人工补录标识。
- `TransferRackSnapshot`：站号、物理有板状态、软件工件、软件/物理一致性说明。

快照读取可以使用现有缓存锁或一个只用于快照字段的短锁；锁内只复制字段，禁止 `await`、设备通信、队列出入或写 PLC。

### 数据来源

- 1、2 号线前天车：前端引擎的前天车队列出队和 `ProcessCraneFrontAsync` 阶段。
- 1、2 号线后天车：后端引擎的 `DoLoad`、`DoUnload`、斜床 `Wp` 和当前动作租约。
- 研磨天车：研磨引擎的天车动作记录、目标研磨机和 `PendingWorkpiece`。
- 斜床：后端引擎私有 `SkewCtx`；增加状态变更时间记录和只读拷贝。
- 研磨机：既有 `GrinderContext.State`、`PendingWorkpiece` 和 `StateChangedAt`，通过只读拷贝输出。
- 中转架：前端 `DeviceStatus` 的物理有板位，加后端 `_wps` 字典的工件身份；两者组合后才输出页面信息。

### UI 刷新

`HomeViewModel` 继续使用既有状态同步路径更新展示属性；Tooltip 只绑定这些内存属性。

- 不创建新的 PLC/TCP 连接。
- 不增加设备轮询线程。
- 不新增数据库写入。
- 不从 Tooltip 事件读取设备。
- Tooltip 设置约 1000ms 首次显示延迟，鼠标离开 PlacementTarget 即关闭。

状态持续时间由 `DateTime.UtcNow - StateChangedAtUtc` 计算并格式化；仅在既有 UI 同步周期更新文本，不为 Tooltip 单独建立高频定时器。

## 状态时间与异常身份规则

斜床上下文需要记录状态变更 UTC 时间。状态值变化时更新时间；同状态的周期轮询不得反复重置时间。

前天车和后天车的“当前任务”不能只放在方法局部变量。开始动作时设置快照，阶段变化时更新；正常完成清除。以下情况保留快照并标记等待人工确认：

- X11 已确认天车持件，但未完成物理放置。
- 工件已经放入设备，但握手或后续安全动作异常。
- 应急取消后旧动作已退出、但尚未由人工完成作废或恢复确认。

应急清除流程成功完成后，按其真实结果清除或更新对应快照；超时或失败不得清除。

## 非功能要求

- 不改变任何现有运动指令、PLC 寄存器读写、队列先后顺序、锁获取顺序或暂停/恢复逻辑。
- Tooltip 数据失效或读取异常时显示“数据暂不可用”，不得影响引擎任务。
- 一次 UI 同步最多复制 5 个天车、10 个斜床、4 个研磨机和 6 个中转架的小型值对象，性能开销应可忽略。
- 现有全流程页面和导航结构不新增页面；所有信息在当前卡片悬停时显示。

## 验证标准

1. 静态检查确认新增展示代码没有调用设备通信、运动、磁铁、队列或控制方法。
2. 模拟快照可显示正常工件、空闲、软件身份缺失和人工确认四类状态。
3. 斜床和研磨状态持续时间仅在状态改变时归零。
4. 天车异常路径保留工件身份，正常完成和明确的应急成功路径才清除。
5. 项目构建无错误；现有警告单独记录，不作为本功能引入的错误。
