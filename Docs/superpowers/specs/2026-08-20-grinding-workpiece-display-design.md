# 研磨取料长度直径显示屏设计

## 背景与目标

研磨区域新增一台 Modbus TCP 显示屏。研磨天车准备从 ST709 取板时，上位机把当前工件的直径和长度写到显示屏，供现场查看。

显示屏只承担信息展示，不参与研磨机准入、工件身份判断、天车运动、PLC 握手或异常恢复。显示屏断线、连接超时、部分写入失败等情况不得阻止研磨上料，也不得改变任何业务状态。

## 通信约定

| 项目 | 约定 |
| --- | --- |
| 协议 | Modbus TCP |
| 默认 IP | `192.168.2.111` |
| 端口 | `502`，固定 |
| 站号 | `1`，固定 |
| 直径地址 | `100` |
| 长度地址 | `101` |
| 数据类型 | 单个 16 位保持寄存器整数 |

代码直接使用地址 `100` 和 `101`，不做 `-1` 地址换算。直径与长度采用现有研磨参数相同的转换规则：`Math.Round` 后转为 `int`。直径沿用主流程的 `> 0` 校验；长度沿用现有规则——原长度为 `0` 时必须由 D200 补成大于零的有效值。显示功能不额外改变研磨业务的数据校验规则。正常工件尺寸应不超过单寄存器可表达范围。

两个地址使用现有 `ModbusTcpClient.WriteAsync(int address, int value)` 分别写入。允许出现直径已写、长度写失败的短暂不一致；显示屏不参与控制，下一次成功写入会覆盖旧值。本需求不增加写后读回、重试或业务告警。

## 配置设计

在 `MotionConfig.GrindingSection` 增加字符串配置项 `WorkpieceDisplayIp`，默认值为 `192.168.2.111`。`Config/motion_settings.json` 的 `grinding` 节点保存对应的 `workpieceDisplayIp`。

配置页面“其他 → 研磨 & 动平衡”区域增加“工件显示屏 IP”输入框，并通过 `ConfigPageViewModel` 直接绑定共享配置对象。用户点击“保存到文件”后持久化到 JSON。修改后的 IP 从下一次显示屏写入开始生效，无需重启应用。

端口、站号和两个寄存器地址按本次设备约定固定在显示屏通信组件中，不暴露为页面配置，避免增加无实际需求的设置项。

## 组件边界

新增一个专用的研磨工件显示屏通信组件，职责仅包括：

1. 按当前配置 IP 建立或复用 Modbus TCP 连接。
2. 把直径写入地址 `100`，把长度写入地址 `101`。
3. 当配置 IP 改变时，释放旧客户端并在下次写入时连接新地址。
4. 将连接或写入结果返回给调用方，不触碰研磨机状态、缓存、`PendingWorkpiece` 或页面弹窗。

`GrindingFlowEngine` 负责选择调用时机和记录研磨日志。显示屏组件不直接引用 `GrinderContext`、FIFO 或天车服务，从而保持其旁路性质。

## 写入时机与数据流

显示屏写入放在 `ProcessWorkpieceAsync` 的 ST709 取料步骤内，顺序如下：

1. 等待目标研磨机请求数据。
2. 对 TypeA 研磨机完成磨石报警和联机状态二次确认。
3. 校验 `wp.Diameter > 0`。
4. 当 `wp.Length == 0` 时，从 MC65 D200 补长度；D200 必须大于零。
5. 将补长后的工件同步到 `grinder.PendingWorkpiece`。
6. 确认 ST709/M730 仍有板。
7. 读取 X11，确认研磨天车磁铁无残留工件。
8. 动作前再次确认 ST709/M730 仍有板。
9. 以当前最终 `wp` 向显示屏写入直径和长度。
10. 无论显示屏写入成功或失败，继续设置天车速度、确认 Z=0、移动 XY 到 ST709、下降并充磁取料。

这个位置保证显示屏收到的是补长后的最终参数，且写入发生在天车真正前往 ST709、充磁取料之前。显示屏写入不替代后续研磨机 PLC 参数下发；原有 `SendRollerParamsAsync` 和研磨握手顺序保持不变。

## 失败与恢复语义

显示屏连接和单次通信使用独立的 `3000ms` 超时，避免屏幕断线长期占用取料流程。以下异常全部在显示屏写入调用边界内捕获：IP 无效、连接失败、显示屏自身超时、地址 `100` 写失败、地址 `101` 写失败、设备断开及 Modbus 异常响应。若研磨引擎传入的取消令牌因停止或应急而取消，则保留原有取消语义并立即退出动作，不把业务取消误记为显示屏故障。

失败时只向 `grinding.log` 输出包含 IP、地址阶段、直径、长度和异常摘要的警告日志，然后继续研磨上料。不得：

- 向外抛出显示屏异常；
- 设置 `_paused`；
- 调用 `OnSafetyAlarm`；
- 弹出安全停机框；
- 修改研磨机 `State` 或 `PendingWorkpiece`；
- 增删、重排研磨 FIFO；
- 阻止天车继续执行本次取料。

显示屏写入完成后、首次充磁命令成功前，如果其他既有业务步骤发生异常，仍按当前研磨引擎规则将补长后的工件放回 FIFO 队头、把研磨机恢复为 Idle 并清空对应 `PendingWorkpiece`。显示屏曾经显示该工件不改变这一恢复逻辑。

首次充磁命令成功后的异常继续沿用现有“工件可能在天车上，暂停并保留在途状态”的安全策略；显示屏功能不改变物理归属判断。

## 日志

成功日志记录一次：显示屏 IP、直径、长度和两个地址写入完成。

失败日志记录一次警告并注明失败阶段，例如“连接”“直径地址100”或“长度地址101”。日志用于排查显示屏，不升级为安全事件或业务异常。

## 验证

实现阶段增加针对以下行为的测试或源码契约测试：

1. 配置模型、默认 JSON、配置页 ViewModel 和 XAML 均包含可编辑的显示屏 IP。
2. 写入使用站号 `1`、端口 `502`、地址 `100/101`，数值按 `Math.Round` 转为整数。
3. 调用点位于 D200 补长、X11 无残留和第二次 M730 确认之后，天车设置速度与前往 ST709 之前。
4. 补长后的长度写入显示屏，且 `PendingWorkpiece` 保持同一份最终数据。
5. 显示屏连接或任一写入失败不会传播异常，不会暂停引擎、触发安全弹窗或修改缓存状态。
6. IP 变更后下一次写入使用新地址。
7. 运行相关自动化测试，并构建主项目确认 XAML、配置序列化和业务代码均可编译。

## 非目标

- 不在页面显示显示屏在线状态。
- 不增加手动测试按钮、自动重试、写后读回或历史数据队列。
- 不修改研磨机 PLC 参数下发、M730/M731、天车运动、充退磁或异常恢复规则。
- 不把显示屏通信结果加入研磨机自动分配条件。
