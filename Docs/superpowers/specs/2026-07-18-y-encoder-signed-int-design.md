# 天车 Y 绝对编码器有符号 INT 读取修复设计

## 已确认范围

- D5020（Y 绝对编码器）和 D5021（Y 原点值）均按 PLC 单寄存器有符号 `INT16` 读取。
- 两者在 `CraneStatus` 中继续使用 C# `int` 保存，但赋值时使用 `(short)` 进行符号扩展。
- D5022（Y 显示坐标）保持现有无符号读取；X、Z 寄存器、PLC 地址、配置格式和微调规则不改动。

## 原因与结果

现状把 D5020/D5021 强制转换成 `ushort`。例如 PLC 原始 16 位字表示 `-751` 时，会被错误解释为约 `64785`，再与配置的负数目标计算，产生接近 `-65535` 的假偏差并触发微调超限。

改为 `(short)r[20]` 和 `(short)r[21]` 后，`-751` 会正确保存为 C# `int -751`。标定页“读 Y”保存的值和微调帮助器读取的值由同一个 `CraneStatus.YEncoderAbs` 提供，因此差值恢复为真实毫米差值；不需要对微调算法额外增加 16 位环绕补偿。

## 验证

- 静态检查 D5020/D5021 使用 `(short)`，D5022 保持 `(ushort)`。
- 构建主项目。
- 复核 `YEncoderAbs` 的标定页和微调调用仍读取同一状态字段。
