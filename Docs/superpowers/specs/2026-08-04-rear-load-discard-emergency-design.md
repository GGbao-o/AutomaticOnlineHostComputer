# 后天车上料异常：斜床应急放弃设计

## 目的

后天车向斜床上料出现已发物理命令后的异常时，现场默认处理是人工移走本次板、使天车回到安全位，然后恢复生产；不要求继续这根板。

本设计消除“目标待交接”快照在斜床应急后无法结案、进而阻止线路启动的情况。

## 范围

- 仅修改 1、2 号线后天车**上料到斜床**的斜床应急清理。
- 不改变 PLC/CNC/天车的正常上料信号、锁顺序、超时或自动动作。
- 不改变来源位冻结的候选跳过策略。
- 不修改后天车下料、前天车、机械手、动平衡、研磨的人工结案策略。

## 运行规则

### 继续本次板

当板仍在目标斜床且现场要继续加工时，保留现有“目标待交接结案”。它必须核对动作号、线体、目标斜床和内存工件身份；成功后不补发 CNC 握手，后端保持暂停供人工复核。

### 放弃本次板

当操作员已人工移走板并确认天车安全时，选择该线、该目标斜床执行既有“斜床应急作废”。在旧动作已退出、设备侧清零成功（或操作员明确选择仅清上位机软件状态）后：

1. 清该斜床的本地工件缓存、任务牌和软件状态；
2. 删除精确匹配本线后天车上料、目标为该斜床的 `PauseOnCarrier` 与 `PauseAtTargetPendingHandoff` 动作快照；
3. 不补发 CNC 上料完成、PLC 通知或任何天车命令；
4. 仅记录“已人工移走/放弃”的审计日志；不自动恢复引擎，由操作员按现有流程启动线路。

来源冻结 (`PauseSourceReserved`) 不由斜床应急删除，仍只跳过对应中转架；原因是 X11 未确认时板可能仍在来源位。

## 匹配边界

快照删除必须同时匹配：

- `FlowScope`：`1号线后天车上料` 或 `2号线后天车上料`；
- `Target`：当前被应急处理的斜床代码；
- `Disposition`：仅 `PauseOnCarrier` 或 `PauseAtTargetPendingHandoff`。

不得删除来源冻结、后天车下料、前天车、机械手、动平衡或研磨的快照。

## 失败行为

- 旧动作 6 秒内未退出：不清锁、缓存或快照，保持暂停；
- 设备侧清零失败：默认不清缓存或快照；只有操作员在既有确认对话中选择“仅清上位机软件状态”后，才按放弃规则清理；
- 选错线或斜床：匹配数为零，返回明确提示，原快照保留；
- 成功消息必须分别报告清除的持件和目标待交接快照数量，便于现场确认。

## 验证

1. 为 1、2 号线各增加/更新合同测试：斜床应急的匹配范围包含两种上料异常快照、不包含来源冻结；
2. 覆盖错误目标斜床不删除快照；
3. 覆盖设备清零失败不会提前删除快照；
4. `dotnet build` 与相关测试通过；
5. 更新异常处理和后天车/斜床业务文档，明确“继续本次板”和“人工放弃本次板”的区别。
