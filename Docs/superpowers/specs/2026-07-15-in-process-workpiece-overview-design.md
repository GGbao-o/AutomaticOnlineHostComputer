# 在制工件总览（当前内存）设计说明

## 1. 目标

新增一个只读的“在制工件”页面，把当前程序内存中能够确认身份的板件集中展示，帮助操作员在异常、应急和节拍等待时回答：

- 程序当前记得哪些工件；
- 每块工件由哪条流程、哪个缓存、设备上下文或在途任务持有；
- 哪些位置只有物理有板信号、没有软件工件身份；
- 哪些工件在多个位置同时留下记录，需要结合交接阶段人工判断。

页面只展示软件证据和已有物理信号快照，不自动恢复身份、不清缓存、不改变任务状态。

## 2. 页面位置与名称

主窗口导航顺序调整为：

`全流程状态 → 运行诊断 → 在制工件 → 异常监控`

页面标题为“在制工件总览（当前程序内存）”，明确区别于数据库历史履历。程序关闭后，页面中的当前内存信息自然消失。

## 3. 第一版展示内容

### 3.1 概览卡片

显示：

- 软件已知工件身份数；
- 总上料架全局待派发数；
- 1/2号线前端在途数；
- 中转架缓存数；
- 加工设备持件数；
- 物理/软件身份不一致数；
- 多处记录工件数；
- 最近刷新时间。

“软件已知工件身份数”按 `PlateNo + Sequence` 去重统计，只用于页面汇总，不改变任务去重或调度规则。`PlateNo` 为空的“未知工件”不参与身份去重，也不能因为多条未知记录而判定为同一块板。

### 3.2 当前工件明细

表格字段：

| 字段 | 含义 |
|---|---|
| 工件 | 版号和序号；身份缺失时显示“未知工件” |
| 所属流程 | 全局、1号线前端、1号线后端、2号线前端、2号线后端、动平衡、研磨 |
| 软件位置 | 全局FIFO、线路缓存、`_currentWp`、天车队列/任务、中转架、斜床、动平衡缓存/在途、研磨缓存/设备 |
| 当前阶段 | 等待派发、机械手/货叉在途、天车执行、等待加工、加工中、等待下料等 |
| 直径/长度 | `WorkpieceCache` 已有数据；缺失时如实显示“未记录” |
| 证据类型 | 软件缓存、活动任务、设备上下文、物理信号+软件缓存 |
| 状态 | 正常、交接中、信号不一致、证据不足、需人工确认 |
| 说明 | 当前证据、物理信号以及人工确认提示 |

### 3.3 筛选

第一版提供纯 UI 筛选：

- 全部流程 / 全局 / 1号线 / 2号线 / 动平衡 / 研磨；
- 全部状态 / 正常 / 交接中 / 信号不一致 / 证据不足 / 需人工确认；
- 版号或序号文本搜索。

筛选只作用于页面集合，不向引擎传递条件。

## 4. 数据来源

### 4.1 总上料架全局FIFO

在 `HomeViewModel` 内对 `_frontDispatchQueue` 使用现有 `_frontDispatchLock` 复制 `WorkpieceCache` 数组。复制后立即释放锁，格式化和分组在锁外完成。

### 4.2 1/2号线前端

两条前端引擎分别新增统一只读快照，组合：

- `_cachedList`：线路前端缓存；
- `_currentWp`：机械手、货叉和双头镗阶段在途身份；
- `_craneQueue`：等待前天车处理的队列；
- `GetCraneTaskSnapshot()`：前天车已出队后的活动任务。

每个集合只使用其现有锁或线程安全快照能力。新方法不得出队、入队、修改 `_currentWp` 或读取设备。

### 4.3 1/2号线后端

复用已有：

- `GetTransferRackSnapshots()`；
- `GetSkewStationSnapshots()`；
- `GetCraneTaskSnapshot()`。

中转架允许组合已有物理信号和软件工件缓存；斜床和后天车任务只声明为软件/任务证据，不推断现场一定有板。

### 4.4 动平衡

动平衡目前存在一个显示缺口：M2/M3从 `_balWps` 取得工件后会删除缓存，而动作期间的工件主要保存在方法局部变量中，页面无法读取。

第一版增加四个只用于展示的字段：

- `_m2DisplayWorkpiece`；
- `_m2DisplayStage`；
- `_m3DisplayWorkpiece`；
- `_m3DisplayStage`。

规则：

1. 在动作已经取得明确 `WorkpieceCache` 后设置；
2. 随现有大阶段更新展示阶段；
3. 在该次动作的 `finally` 中按动作版本清理，旧动作不得清除新动作的展示信息；
4. 应急取消后旧动作退出时正常清理；旧动作未退出时保留，作为人工核对证据；
5. 任何业务条件、锁、运动、握手和应急决策都禁止读取这些展示字段。

另对 `_balWps` 在现有 `_balWpsLock` 内复制缓存快照。

### 4.5 研磨

复用已有：

- `GetCachedWorkpiecesSnapshot()`；
- `GetGrinderStationSnapshots()`；
- `GetCraneTaskSnapshot()`。

不直接读取研磨机PLC或天车信号。

## 5. 多处记录与身份不一致规则

### 5.1 多处记录不是自动故障

`WorkpieceCache` 是结构体，在正常交接瞬间可能同时出现在来源快照、目标上下文或活动任务中。因此第一版不得把相同 `PlateNo + Sequence` 的多条记录直接判定为红色故障。

处理方式：

- 仅当 `PlateNo` 非空且同一 `PlateNo + Sequence` 出现多条记录时，显示黄色“多处记录，请结合交接阶段核对”；
- 保留所有原始行，不自动去重隐藏；
- 不自动清理任一缓存；
- 后续只有在定义了互斥所有权和持续时间后，才能升级为确定的“软件重复身份”报警。

### 5.2 可确定的物理/软件不一致

第一版只对已有可靠物理快照的位置判断：

- 中转架物理有板、软件无工件身份；
- 中转架物理无板、软件仍有工件身份。

这两类显示“信号不一致/需人工确认”。物理信号不可用时显示“证据不足”，不得推断有板或无板。

### 5.3 软件完全丢失的边界

如果一块实物板已经不在任何软件缓存、设备上下文或活动任务中，页面无法凭空恢复其版号和序号。页面必须明确显示：

> 本页只能展示程序当前仍保留的证据，不能替代现场确认，也不能修复已经丢失的身份。

## 6. 组件设计

### 6.1 快照模型

新增不可变的 `InProcessWorkpieceSnapshot`，只包含展示数据，不持有引擎、设备服务、锁、任务或回调。

### 6.2 引擎快照入口

前端、动平衡分别新增同步的 `GetInProcessWorkpieceSnapshots()`。方法只复制已有内存值，不执行 `await`、设备I/O、数据库或文件操作。

后端和研磨优先由 `HomeViewModel` 组合现有快照，避免重复增加接口。

### 6.3 页面聚合

`HomeViewModel.GetInProcessWorkpieceOverviewSnapshot()` 汇总所有来源。每个来源独立捕获异常；一个来源失败只生成一条“该来源快照不可用”，不能影响其他来源和生产流程。

### 6.4 页面ViewModel与View

独立 `InProcessWorkpieceOverviewViewModel` 负责筛选、汇总计数和集合更新。页面使用自身的 `DispatcherTimer`：

- 打开立即刷新；
- 可见时每1秒刷新；
- 隐藏或卸载立即停止；
- 不创建后台线程；
- 不订阅设备高频事件。

## 7. 性能和业务隔离

必须满足：

1. 不新增PLC、CNC、FANUC、Modbus、MC、文件共享或数据库访问；
2. 不修改分板、准入、状态机、动作顺序、锁顺序、超时和握手位；
3. 页面没有启动、暂停、清除、恢复、重试或移动按钮；
4. 快照锁内只执行小集合复制，不格式化文本、不更新UI；
5. 页面不可见时没有刷新开销；
6. 展示字段的异常不得向业务代码抛出；
7. 不写高频日志，避免每秒刷新形成磁盘I/O；
8. 不提交Git。

## 8. 文档更新

实现时同步更新：

- `Docs/整线技术手册.md`：增加页面字段、证据边界和刷新规则；
- `Docs/日志审查与故障定位手册.md`：增加异常前保存/核对当前工件证据的步骤；
- `Docs/03-设备交互流程/整线引擎流程总览_按代码.md`：补充各阶段工件身份的只读快照位置，明确快照不参与控制。

## 9. 验证标准

1. 完整构建成功，零错误且不新增项目警告；
2. 导航顺序为“全流程状态→运行诊断→在制工件→异常监控”；
3. 页面能展示全局FIFO、两线前端、两线后端、动平衡和研磨的已有工件证据；
4. 五台天车活动任务的工件身份能够显示；
5. M2/M3动作期间工件从 `_balWps` 删除后，仍能通过展示字段看到身份；
6. 中转架物理/软件不一致得到突出显示；
7. 相同身份多处出现只做黄色提示，不自动判错或清理；
8. 页面隐藏后定时器停止；
9. 静态扫描确认新增页面、ViewModel和快照模型没有协议或控制依赖；
10. 差异审查确认现有动作条件、状态迁移、锁和设备写入没有改变。

## 10. 第一版不实现

- 数据库存储和跨程序生命周期历史；
- 根据页面结果自动恢复或自动清缓存；
- 把多处记录直接升级为红色安全报警；
- 根据日志反推工件位置；
- 修改现有异常恢复业务逻辑；
- OEE、节拍、停机时间和历史轨迹报表。
