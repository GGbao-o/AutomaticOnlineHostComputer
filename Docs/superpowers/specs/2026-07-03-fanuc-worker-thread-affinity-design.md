# FANUC FOCAS 单线程会话修复设计

## 目标

解决两类通信层问题：

1. 离线 FANUC 斜床连接等待远大于配置值，造成页面连接状态更新缓慢。
2. 同一 FOCAS 句柄被轮询线程和业务线程交替使用，频繁出现 `EW_HANDLE(-8)`，随后重连又暂时恢复。

## 设计边界

- 每台 FANUC 设备仍使用一个独立 `FanucSkewBedService` 和一个独立 FOCAS 句柄。
- 每台设备的连接、断开、宏变量读写、状态读取及轮询全部排入该设备自己的 Worker 线程执行。
- 保持所有 public 接口、宏变量地址、三次重试、参数写后校验、握手顺序和异常传播方式不变。
- 不修改 1/2 号线后端引擎的任务派发、运动流程、暂停策略或应急逻辑。
- FOCAS `cnc_allclibhndl3` 的 timeout 参数按官方定义直接使用“秒”，默认 3 秒。

## 线程模型

业务线程只提交命令并等待结果，不直接调用 `FanucSdk`。Worker 在处理业务命令之间每 500ms 刷新一次 #1001~#1005 快照；连接失败沿用指数退避，最大 30 秒。每台离线设备只阻塞自己的 Worker，不影响其他机床和 UI 线程。

## 日志

重连、重试和最终失败日志包含 `IP:Port`、Worker 线程号、FOCAS 句柄（存在时）、操作名称和尝试次数。正常业务宏变量日志保持原有内容，避免改变现场判断依据。

## 非目标

- 不减少 #1003 的业务轮询频率。
- 不改变任何 CNC 宏变量含义。
- 不改变设备启停、工件缓存、锁或异常弹窗逻辑。
