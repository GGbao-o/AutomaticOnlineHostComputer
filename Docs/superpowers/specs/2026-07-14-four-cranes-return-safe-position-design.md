# 四台天车一键回安全位置设计

## 目标

在主页面现有的“天车移动”手动窗口中增加“4台回安全位置”操作，供操作员在启动自动线前一次性将1号线、2号线的前后天车回到配置的安全 X 坐标。

本功能只覆盖天车1、2、3、4；研磨天车5不参与。

## 范围与明确不做的事

- 这是手动操作入口，不检查或改变1、2号线引擎的运行、暂停、队列、缓存、锁、PLC握手或工件状态。
- 不自动让任何天车 Z 回零；Z 未满足条件时仅拒绝本次整批操作并提示人工先回原点。
- 不读取或处理 X11、磁铁工件、共享碰撞区锁。操作员仍需按既有手动操作规范确认现场安全。
- 不移动研磨天车5。
- 不更改既有单台“确认移动 X 轴”行为。

## 界面

修改 `Views/Home/Dialogs/CraneMoveDialog.xaml`：在现有天车移动窗口中增加按钮“4台回安全位置”，并增加一行批量操作状态文字。

执行期间禁用窗口内的单台移动、刷新、选择和批量按钮，避免同一窗口重复下发命令；完成、拒绝或异常后恢复。无额外确认弹窗：通过全部预检后直接开始回位。

## 目标坐标

不硬编码目标值，读取当前共享 `MotionConfig.CraneHomeX`：

| 天车 | 归属 | 当前配置值 |
|---|---|---:|
| 1 | 1号线前天车 | 1000 |
| 2 | 1号线后天车 | -5000 |
| 3 | 2号线前天车 | 1000 |
| 4 | 2号线后天车 | -5000 |

配置窗口保存后的最新值应立即作为本次操作目标。

## 预检：全有或全无

点击批量按钮后，先依次连接并读取天车1~4的实时状态。仅当四台均成功读取且 `abs(Z) <= 5mm` 时，才允许开始任何 X 轴移动。

任一台读取失败或 `abs(Z) > 5mm` 时：

1. 不向任意天车写入移动目标或触发命令；
2. 汇总弹窗列出失败天车及实时 Z（或读取失败原因）；
3. 明确提示“请先将 Z 轴回原点（0±5mm）后重试”。

这保证不会出现“其中三台已经移动、最后一台才发现 Z 未回零”的半完成状态。

## 执行顺序

四台通过预检后，按固定顺序串行执行：

1. 天车1 X → `CraneHomeX[1]`
2. 天车2 X → `CraneHomeX[2]`
3. 天车3 X → `CraneHomeX[3]`
4. 天车4 X → `CraneHomeX[4]`

每台执行前使用现有速度配置并调用既有 `CraneService.MoveAbsoluteAsync(targetX, -1, -1)`，因此仅移动 X 轴，Y/Z 保持不动，复用既有连接、手动模式、超时、到位轮询和触发复位逻辑。

不采用四台并行下发。现有自动流程的前后天车在同一线的打号机、中转架、斜床1附近存在相邻碰撞区，而现有手动窗口不接入这些锁；串行能避免这个新入口额外制造同线并发横移。

## 成功、失败与取消

- 每台成功后更新窗口状态，显示已完成天车和目标 X。
- 某台连接、设速、移动或到位复核失败时，立刻停止后续天车，不自动重试、不反向移动已成功的天车；弹窗明确列出已完成天车、失败天车和异常原因。
- 操作窗口关闭时不取消已经发出的 PLC 动作；执行期间禁用关闭按钮，等待当前批量操作自然结束，以免窗口关闭造成“界面已消失、动作仍在执行”的误解。
- 不修改引擎业务状态；本功能只报告手动移动结果。

## 验证

1. 配置值读取：修改天车1~4归位 X 后，批量提示/日志使用新值。
2. 任一台 Z=6mm：四台均不下发 X 移动，弹窗指出该天车。
3. 四台 Z 分别为 -5、0、5、0：按1→2→3→4依次仅 X 轴回位。
4. 第 N 台移动失败：N+1 及后续不发命令，前 N-1 保持已回位状态并显示结果。
5. 执行 `dotnet build AutomaticOnlineHostComputer.csproj --no-restore -clp:ErrorsOnly`，确认无编译错误。
