# 全厂流程状态页可靠性设计

## 目标

在不改变生产状态机、设备命令、握手写入、锁顺序和派发条件的前提下，提高 `FlowStatusView` 的状态可读性与可信度。

## 改动边界

1. ST020、ST021 分别显示完整四握手位和软件缓存状态，不再挤在同一张窄卡片中。
2. ST103、ST402 双头镗完整显示 R6101/R6102/R6103/R6104/R6107/R6108。
3. 普通状态文字保留紧凑布局，同时提供完整悬停文本；关键长状态使用宽卡并允许换行。
4. 共享总上料架 ST001、机械手1 ST002 只生成一份确定性展示结果，避免双线刷新循环互相覆盖。
5. ST019/ST020/ST021 统一选择当前可用的前端或动平衡快照；所有相关引擎停止时明确显示“未启动”，不保留旧状态。
6. 双头镗增加只读快照有效标志。TCP 在线但本轮读取失败时页面显示“读取失败”，不再显示旧信号。
7. 状态同步异常写入日志，不再空 `catch`。
8. 流程大屏增加5台天车和3台机械手的只读状态带，直接复用现有页面轮询结果，不增加连接和控制命令。

## 明确不改

- 不修改 M/R/D 地址、Modbus/MC 通信方法和写入值。
- 不修改任何动作前置条件、流程阶段和优先级。
- 不修改天车、机械手、货叉、双头镗、斜床、动平衡或研磨的运动行为。
- 不增加页面侧设备连接；页面仍只消费引擎和共享连接缓存提供的状态。

## 验证

1. XAML 可以由 XML 解析器加载。
2. 所有 `StationCards[...]` 绑定均有预建卡片。
3. 两条线的双头镗分别绑定 ST103、ST402。
4. ST020/ST021 分别显示正确的四个位和对应缓存键。
5. `dotnet build AutomaticOnlineHostComputer.csproj` 为 0 错误。
