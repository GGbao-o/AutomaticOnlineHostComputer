# 页面数据可信度与操作防护修复设计

## 目标

以最小改动修复六个已确认的页面问题：研磨机占位按钮误导、运行诊断 ST110/ST111 映射错误、暂停后旧快照被当作实时值、人工新增任务校验不足、M2/M3 异常显示身份被清除、应急中心允许重复操作。

本次修复优先保证“页面说的是真话”和“人工操作不会重复进入”。除拒绝非法人工任务输入外，不改变任何正常任务的设备准入、PLC/CNC 握手、运动顺序、缓存增删、锁获取释放、暂停恢复或异常处置规则。

## 方案选择

采用逐项小修复方案，不建立新的统一状态中心，也不缩短现有轮询周期。

- 不新增 PLC、CNC、MC、Modbus、FANUC 或数据库读取。
- 不为了页面显示清空既有 `Connected`、工件缓存或设备状态。
- 页面通过快照采集时间判断“实时/最后已知/过期”，不把暂停等同于断线。
- M2/M3 只调整显示上下文的清理时机，控制流程不得读取显示字段。
- 应急窗口只增加页面级防重入，底层应急方法保持不变。

## 一、研磨机占位按钮

### 当前问题

设备总览的四台研磨机显示“急停”和“清除报警”，但 `GrinderCardViewModel` 中两个命令没有设备写入，只打印占位日志。按钮外观会让操作员误认为命令已经执行。

### 设计

保留两个按钮的位置，但明确显示为不可用：

- 文案改为“急停(未配置)”和“清报警(只读)”；
- 命令改为始终 `CanExecute=false` 的只读不可用命令；
- Tooltip 说明“当前点位表未定义写入地址，请使用现场设备操作面板”；
- 不增加任何虚构地址，不调用现有空实现。

其余研磨调试握手按钮保持原状，本次不扩展真实急停和清报警协议。

## 二、运行诊断 ST110/ST111 映射

### 当前问题

1号线后端实际床位数组顺序是 `ST108, ST109, ST111, ST110, ST112`。运行诊断把 `Skew3Connected` 标为 ST110、`Skew4Connected` 标为 ST111，与全流程页面和后端数组不一致。

### 设计

只交换 `HomeViewModel.GetRuntimeDiagnosticsSnapshot()` 中两项显示映射：

- ST111 读取 `Skew3Connected`；
- ST110 读取 `Skew4Connected`。

不修改后端床位数组、`DeviceStatus` 字段、全流程卡片或设备连接。

## 三、暂停与旧快照的数据质量

### 当前问题

前后端、动平衡和研磨引擎暂停后在循环顶部跳过采集，但之前的 `Connected` 和物理信号仍保留。运行诊断可能继续显示绿色“已连接”，在制工件页面可能继续把中转架旧信号当作实时物理证据。共享 ST001/ST002 还可能固定优先1号线旧快照而忽略2号线较新的快照。

### 数据模型

在1/2号线前端和后端的页面状态对象中增加只读展示时间：

```text
SnapshotAtUtc：最近一次完成本轮页面状态维护的UTC时间
```

该字段只由现有采集循环更新，不触发额外通信，也不得参与动作准入。页面统一使用5秒作为第一版过期阈值。

### 显示规则

| 条件 | 页面状态 | 颜色/证据语义 |
|---|---|---|
| 引擎运行、时间未过期、Connected=true | 已连接 | 绿色，当前证据 |
| 引擎暂停 | 暂停/最后已知 | 黄色，不视为当前物理证据 |
| 引擎运行但快照超过5秒 | 数据过期 | 黄色，不视为当前物理证据 |
| 新鲜快照明确Connected=false | 断开/读取失败 | 灰色或红色 |
| 引擎未启动 | 未启动 | 灰色 |

运行诊断的通信项显示最近快照年龄。中转架在快照暂停或过期时将 `PhysicalSignalAvailable` 解释为 false，只显示软件身份和“物理信号为最后已知值”，不新增一致/不一致结论。

ST001/ST002 共享卡在两条线都有可用快照时选择 `SnapshotAtUtc` 较新的来源；若两者都过期则显示“数据过期”，不得继续固定优先1号线。

### 边界

- 不清除旧值，旧值仍可作为“最后已知”展示。
- 不让页面的5秒阈值进入任何引擎控制判断。
- 不在暂停状态额外读取设备。

## 四、人工新增任务输入校验

### 当前问题

ERP导入会校验长度、直径和左右堵厚大于0，人工新增任务没有同等校验。无效直径可能进入后续Z坐标公式和参数下发。

### 设计

人工入口补齐ERP已有规则，不增加新的工艺或线路规则：

- 长度必须是有限数且大于0；
- 直径必须是有限数且大于0；
- 堵孔只能为70或100；
- 左右堵厚必须是有限数且大于0；
- 继续保留现有锥度、圆角、工艺和中转架选择校验。

第一版在 `AddTaskDialogViewModel.Validate` 中补齐等价检查，避免为此扩大重构范围。斜床长度能力、线路选择和设备状态仍由既有派发流程判断。

## 五、M2/M3 异常显示身份保留

### 当前问题

M2和M3动作的 `finally` 无条件调用 `ClearM2Display/ClearM3Display`。当机械手已持件，或已把工件放到目标位但PLC握手/软件缓存尚未闭环时，引擎虽暂停等待人工确认，在制页面却失去最重要的工件身份与位置证据。

### 设计

每个动作增加一个仅控制显示清理的局部结果，例如 `keepDisplayForManualConfirmation`。该变量不得进入运动、握手、缓存、锁和暂停判断。

清理规则：

| 动作结果 | 显示处理 |
|---|---|
| 正常完成全部闭环 | 清除 |
| 明确未吸到工件、实物未离开来源 | 清除 |
| X11确认持件但尚未放到目标 | 保留，标“机械手持件，需人工确认” |
| 已放ST008但M711未闭环 | 保留，标“实物可能在ST008，M711未闭环” |
| 已放ST010但M721或研磨缓存未闭环 | 保留，标“实物可能在ST010，后续未闭环” |
| 应急动作退出超时或应急失败 | 保留 |
| 对应应急成功 | 由应急成功路径按动作版本清除 |

现有 `actionVersion` 继续保护新旧动作，旧动作的 `finally` 和旧应急不得清除新动作显示。正常成功仍必须清理，避免遗留假任务。

## 六、应急中心统一防重入

### 当前问题

前端应急已有 `_frontActionInProgress`，但斜床、动平衡、研磨按钮没有统一门闩。操作员连续点击或在执行期间切换目标，可能同时调用两个应急方法，或把结果记录到错误目标。

### 设计

应急窗口使用一个统一的 `_emergencyActionInProgress` 门闩，覆盖：

- 前端当前板继续；
- 前端当前板丢弃；
- 斜床应急；
- 动平衡应急；
- 研磨应急。

执行顺序固定为：

1. 把当前线体、床位或目标复制到局部变量；
2. 显示确认弹窗；
3. 原子获取统一操作门，失败则提示“另一项应急正在执行”；
4. 禁用所有应急执行按钮和目标选择控件；
5. 使用步骤1保存的局部目标执行、记录事件和刷新结果；
6. 在 `finally` 中恢复控件并释放门闩。

底层应急方法、6秒退出等待、设备侧清零、仅清软件二次确认和恢复规则全部保持不变。

## 错误处理与日志

- 所有新增显示判断失败时按“证据不可用”降级，禁止抛回生产流程。
- 页面防重入的门闩必须在 `finally` 释放。
- M2/M3 保留显示时记录一次明确日志，包含动作版本、工件身份、物理阶段和“等待人工确认”。
- 输入校验失败只弹出可读提示，不创建任务行、不写任何缓存。

## 性能边界

- 不新增后台线程、定时器或协议请求。
- 快照时间是现有循环中的一次字段赋值。
- 页面只做时间差和少量条件判断。
- 不缩短1.5秒、1秒、5秒等既有页面刷新周期。
- 不增加数据库表、文件持久化或历史记录。

## 验证

### 静态隔离检查

1. 搜索新增快照字段，确认只被展示聚合读取，不进入任何 `CanAccept`、派发、运动、握手、锁或缓存判断。
2. 搜索M2/M3显示保留变量，确认只控制 `ClearM2Display/ClearM3Display`。
3. 确认未新增设备协议调用和数据库访问。

### 功能场景

1. 运行诊断中ST111跟随Skew3、ST110跟随Skew4。
2. 引擎暂停超过5秒：通信项显示“暂停/最后已知”，中转架不再把旧信号当作当前证据。
3. 1号线快照旧、2号线快照新：ST001/ST002选择2号线新快照。
4. 人工输入长度0、直径0/负数、堵厚0：任务均不能创建；正常任务仍可创建。
5. M2/M3正常完成：显示清除；持件异常或目标位闭环异常：身份保留；应急成功后清除。
6. 连续双击斜床应急，或斜床应急执行中点击研磨应急：只有第一次调用进入底层。
7. 研磨急停/清报警按钮呈禁用状态并显示原因。

### 构建与文档

- 执行正式项目构建，确认0个编译错误。
- 更新整线技术手册、日志审查与故障定位手册及必要的流程文档，说明数据过期、最后已知值、M2/M3人工确认和应急防重入语义。

## 不做事项

- 不实现研磨机真实急停或清报警地址。
- 不建立历史报警数据库或工件履历库。
- 不调整自动线轮询周期、超时和重连策略。
- 不修改异常后设备自动恢复策略。
- 不新增操作员权限系统。
