# 后天车上料业务动作状态机设计

## 范围

本设计只覆盖 1、2 号线后天车从中转架取工件并放入斜床的上料动作。后天车下料、前天车、机械手和研磨天车复用同一模型，但不在本次变更中迁移。

## 目标

每个会改变现场状态的步骤都留下不可倒退的事实：命令是否尚未发送、已经发送待确认、已确认，工件归属在哪里，最后已知 XYZ/X11/磁铁状态，以及动作租约中真实持有哪些锁。发生异常时，系统不再用局部布尔变量猜测，而由这些事实统一给出等待或暂停结论。

## 数据模型

`FlowActionContext` 作为单次动作的唯一业务账本，包含动作标识、线路/设备、真实工件身份、来源/目标/来源缓存键、当前步骤、命令状态、工件归属、目标与最后已知位置、X11、磁铁命令状态、已登记锁、暂停原因和人工处置选项。

步骤在调用物理命令前进入 `BeginStep`；调用已开始时立即标记 `SentAwaitingEvidence`；只有位置、X11、目标接收或握手反馈已验证后才能标记 `Confirmed`。通信异常、超时或非容许下压不允许把命令回退为未发送。

## 工件账本

中转架工件先被 `Reserved(OperationId)`，但不会在取料开始时删除。只有 X11=1 已确认持件时才能提交取走，归属改为 `OnCarrier`。放入斜床并完成退磁/目标确认后改为 `AtTargetPendingHandoff`；CNC上料握手闭环后才为 `Completed`。

若命令结果未知，来源缓存保持预约，不允许新的自动任务选择。人工确认页面必须能依据动作快照选择“仍在来源位、天车持件、已在目标、人工移走”；该选择是未来应急入口的唯一账本转换来源。本阶段先记录并展示选择说明，不新增页面写操作。

## 异常结论

| 已知事实 | 结论 |
|---|---|
| 尚未发出物理命令的读状态/就绪失败 | `WaitRetry`，不暂停、不改归属 |
| 运动超时、响应未知、下压越界 | `PauseManual`，保留当前归属和来源预约 |
| X11明确三次为0，且退磁及安全Z均已确认 | `PauseSourceReserved`，保留来源预约 |
| X11=1 已确认 | `PauseOnCarrier`，保留在途工件和任务牌 |
| 已退磁放入目标但下游握手未闭环 | `PauseAtTargetPendingHandoff`，禁止恢复来源缓存 |
| 全部握手完成 | `Complete`，允许正常清理 |

局部 catch 仅可执行已证明安全的补偿，例如下压后的报警复位和已确认位置内的恢复。统一 catch 不发运动、磁铁或PLC命令，只根据动作账本暂停、建立任务牌、上报异常。finally 仅取消动作令牌、清 Busy 和释放本动作登记的锁；不移动、不充退磁、不回滚缓存、不把斜床改为 Idle。

## 可观测性

异常监控事件增加动作账本摘要：步骤、命令状态、归属、来源/目标、实际与目标 XYZ、X11/磁铁、持锁、暂停结论和人工确认提示。页面仍只读，不参与设备或缓存写入。

## 验证

针对两条线对称验证：来源预约、XY/微调/Z超时、下压容差内外、充磁响应未知、X11读取失败、X11三次为0、已持件异常、已放料但CNC未确认，以及正常完成。每种路径都断言不会将未知状态降级、不会误删来源缓存、不会进行自动重试，且最终事件含完整动作摘要。
