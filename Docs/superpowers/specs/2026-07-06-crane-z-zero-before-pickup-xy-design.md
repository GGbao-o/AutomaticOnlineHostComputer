# 指定取料横移前Z轴回零保护设计

## 1. 目标

在以下四个“新取料动作的首次XY横移”前，必须确认天车Z轴位于0±5mm；若不在允许范围，先将Z轴移动到0并再次确认，确认成功后才允许XY横移：

1. 1号线前天车新任务去货叉Pos3/ST713取料；
2. 2号线前天车新任务去货叉Pos3取料；
3. 研磨天车上料流程去ST709取料；
4. 研磨天车下料流程去目标研磨机取成品。

该保护用于避免上一次异常、急停或人工操作后Z轴仍停在低位，新任务直接执行`MoveAbsoluteAsync(X, Y, -1)`造成低Z横移。

## 2. 业务边界

- 只修改上述四个入口。
- 不修改`MoveAbsoluteAsync`的全局行为。
- 不修改打号机到中转架的特殊高度流程。
- 不修改斜床下料时低Z执行Y轴退让的既有业务动作。
- 不修改坐标、取放料Z公式、速度、磁铁、X11、锁、超时和后续动作顺序。
- Z轴已经处于0±5mm时不发送回零运动命令，直接继续原XY动作。
- Z轴状态读取失败、回零失败或回零后复核失败时禁止XY，并由原调用流程的catch处理；不得假定Z安全后继续。

## 3. 封装方法

在`Communication/DeviceServices/CraneService.cs`中新增公共方法：

```csharp
public async Task EnsureZAtZeroAsync(
    int tolerance = 5,
    CancellationToken ct = default)
```

执行顺序：

1. 校验`tolerance >= 0`；
2. 调用`ReadStatusAsync`读取实时状态；
3. 状态为空时抛出`InvalidOperationException`，禁止横移；
4. 若`Math.Abs(status.ZPos) <= tolerance`，记录“Z已在零位允许范围”并返回；
5. 否则调用`MoveAbsoluteAsync(-1, -1, 0, tolerance, ct: ct)`；
6. 运动完成后再次调用`ReadStatusAsync`；
7. 复核状态为空或`Math.Abs(verified.ZPos) > tolerance`时抛出异常；
8. 复核通过后记录实际Z并返回。

调用方只增加一行`await crane.EnsureZAtZeroAsync(5, ct);`，随后保留原XY移动。方法不获取业务锁，不控制X/Y，不控制磁铁，也不吞异常。

## 4. 插入位置

### 4.1 1号线前天车

在`ProcessCraneFrontAsync`中，完成连接、机械手安全等待和X11无板检查后，在首次去ST713的XY命令以前调用。只有回零确认成功才执行原`MoveAbsoluteAsync(f2xOff, f2yOff, -1)`。

### 4.2 2号线前天车

与1号线完全对称，在首次去本线货叉Pos3的XY命令以前调用同一个封装方法。

### 4.3 研磨天车上料

在`ProcessWorkpieceAsync`中，ST709信号与坐标确认完成后、首次XY去ST709以前调用。后续下降、充磁、X11和送研磨机流程保持不变。

### 4.4 研磨天车下料

在`ProcessUnloadAsync`中，门打开、目标研磨机坐标和速度准备完成后、首次XY去研磨机取料以前调用。后续下降、充磁、尾座松开、升安全高度和去ST710流程保持不变。

## 5. 异常语义

- 第一次状态读取失败：没有证据证明Z安全，立即拒绝XY。
- 回零运动抛异常或超时：不执行XY，异常继续传播。
- 回零调用返回但复核超过±5mm：抛出明确异常，禁止XY。
- 前天车在充磁前失败：沿用原逻辑，工件仍在货叉Pos3并回前天车队列等待重试。
- 研磨上料在充磁前失败：沿用原逻辑，工件仍在ST709并回研磨缓存。
- 研磨下料在充磁前失败：沿用原研磨异常处理，不清工件身份。

## 6. 日志

日志必须包含天车名称、调用场景由调用方原日志体现，并由封装方法输出：

- 当前Z、容差和是否直接放行；
- 当前Z不合格时开始回零；
- 回零后复核实际Z；
- 读取失败或复核失败的明确原因。

不在循环内重复刷日志；每次实际取料任务最多记录一次首次检查和一次回零复核。

## 7. 验证

1. Z=0：不发Z运动，继续XY。
2. Z=5和Z在允许边界内：不发Z运动。
3. Z>5：先回0，复核通过后XY。
4. 第一次读取返回null：XY不执行。
5. 回零运动超时/异常：XY不执行。
6. 回零后复核仍超过5mm：XY不执行。
7. 搜索确认只有四个指定业务入口调用新方法。
8. 搜索确认打号机到中转架、斜床低Z退让等特殊路径未被替换。
9. `git diff --check`通过。
10. 使用独立临时输出目录执行主项目`dotnet build`，要求0错误。

## 8. 验收标准

- 四个指定取料入口在任何XY横移以前均具有实时Z=0±5mm证据。
- 任一检查结果未知或回零失败时均不执行XY。
- 已在零位时不增加运动时间。
- 其他正常业务路径、特殊低Z横移和设备握手不受影响。
- 1/2号线使用同一封装方法，不复制回零判断逻辑。
