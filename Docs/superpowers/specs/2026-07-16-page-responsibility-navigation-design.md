# 页面职责与排障导航手册设计

## 目标

为上位机工程师提供一份单一入口文档，说明当前 SCADA+轻量 MES 系统中八个主导航页面分别负责什么、显示数据从哪里来、何时可以操作、出现问题时先进入哪个页面，以及如何继续追溯到源码和正式流程文档。

## 范围

- 覆盖主界面、机器管理、运动参数设置、设备总览、全流程状态、运行诊断、在制工件、异常监控。
- 排除当前已注释的天车管理、控制器管理和工艺管理菜单。
- 仅记录当前实现和安全边界；不修改 PLC/CNC 协议、流程引擎、数据库结构或页面行为。

## 文档结构

1. 先定义 SCADA 显示层、MES 轻量任务层与生产流程引擎的边界。
2. 提供按现象检索的排障总表，给出“先看页面、再看页面、再追踪文档/源码”的顺序。
3. 每个页面使用相同字段：定位、职责、关键显示内容、数据来源与刷新、允许操作、禁止误解、适用故障、继续追溯位置。
4. 对直接控制设备的页面增加显著安全提示；对只读页明确“显示不参与控制”。
5. 结尾提供源码追溯表，链接到 View、ViewModel、服务或流程引擎以及关键 Docs。

## 判定原则

- 页面刷新时间不等于底层设备数据采集时间。
- 引擎暂停只阻止后续派发或循环，不必然停止已经开始的物理运动。
- “清空状态”仅清上位机写入的设备输出；需要作废软件状态、释放动作锁或恢复流程时，应进入应急处理流程。
- 在制、诊断和异常监控是观察与定位入口，不是恢复或控制入口。

## 验收标准

- 工程师能从任一页面名称理解其责任边界和操作风险。
- 对“设备不动、工件去向不明、通信/快照异常、报警/应急、任务未派发”五类问题，文档给出明确的首选检查页面。
- 每页至少提供一个当前源码入口和一个相关正式业务文档入口。
