# 后天车上料通道占用时的下料让位设计

## 目标

当前天车在打号机阶段会长期持有 `ZoneMT`。若中转架已有可上料板，后天车可能先选中上料、持有后天车总锁后等待 `ZoneMT`，使本可立即执行的斜床下料长期无法派发。

本次调整使 1、2 号线后天车在“原压力策略选中上料”但上料通道暂不可进入时，优先执行不受当前区域锁阻塞的下料。没有实际可下料动作时，保持原上料等待行为。

## 范围与不变项

- 保留原有上料/下料候选、到达顺序、长度匹配和中转架压力计算。
- 保留 `ZoneMT -> ZoneTS` 的实际获取顺序。
- 不改变 `DoLoad`、`DoUnload` 的运动、PLC、X11、预约和握手步骤。
- 在创建上料任务、预约来源、写 `Loading`、获取后天车总锁之前完成让位判断。

## 调度规则

1. 先按现有 `RearSkewDispatchPlanner` 得到压力策略的基础决策。
2. 仅当基础决策为 `Load` 时，检查上料通道是否可立即进入：`ZoneMT` 和 `ZoneTS` 都必须空闲。
3. 上料通道被占且存在“立即可下料”候选时，将本轮有效决策覆盖为 `Unload`：
   - 普通斜床下料不依赖共享区，属于立即可下料；
   - 1号线 ST108、2号线 ST606 下料需要 `ZoneTS`，仅当 `ZoneTS` 空闲才属于立即可下料。
4. 覆盖为下料时，派发时必须复核并指定该立即可下料斜床；不能重新任取候选列表第一项。
5. 没有立即可下料候选时，不覆盖基础决策，维持现有上料等待。

锁当前状态只用于吞吐调度，不用作安全放行证据。实际动作仍在 `DoLoad/DoUnload` 内获取区域锁，状态发生竞争时继续沿用现有安全等待和异常处理。

## 验证

- 纯调度器测试：通道忙且存在立即下料时覆盖为下料；通道空闲或没有立即下料时保持原决策。
- 编译并运行相关测试。
- 更新《全线业务逻辑详解》的后天车调度和上料章节，明确前天车打号长期占用 `ZoneMT` 时的让位行为。
