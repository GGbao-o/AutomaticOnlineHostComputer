# 主页面设备内存状态复位设计

## 目标

在主页面现有“应急处理”和“清空状态”旁新增“恢复内存状态”按钮。它仅用于现场 PLC 已经回到可接收下一块板的状态、但上位机旧内存状态仍阻止候选派发的场景。

## 操作范围

用户在窗口中选择单台设备后，执行以下最小改动：

- 1号线或2号线任一斜床：`St = Idle`、`Wp = null`。
- 任一研磨机：`State = Idle`、`PendingWorkpiece = null`。

每次只复位一台设备；不提供批量复位。

## 明确不做的事情

- 不写 PLC、CNC、机械手或天车命令，不移动设备。
- 不清请求/反馈信号快照、`CompletionExported`、`WpRecoveryNeeded`、异常快照、动作账本或软件锁。
- 不取消、等待或释放任何后台动作。
- 不复用“清空状态”窗口；该窗口的语义是清设备寄存器/握手输出。

## UI 与结果

- 主页新增黄色警示按钮“恢复内存状态”。
- 弹窗按“1号线斜床”“2号线斜床”“研磨机”展示站号；点击站号后进行一次明确确认。
- 确认文字说明仅适用于“PLC 已正常请求、天车未派发，旧内存状态阻塞候选”的情况，并逐项显示将被改写的字段。
- 完成后显示站号、变更前后的内存状态和结果；不声称 PLC 或设备已经复位。

## 验证

- 为两条后端引擎和研磨引擎增加针对公开复位入口的契约测试：只变更上述字段，其他恢复标记不被复位。
