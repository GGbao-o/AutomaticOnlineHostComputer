# 异常监控页面设计

## 目标

新增一个“异常监控”页面，显示**当前程序生命周期**内需要人工关注的事件。程序关闭后内存数据自然清空；本功能不新增数据库、不修改设备协议、不驱动设备动作，也不改变引擎暂停、恢复、锁或任务的业务语义。

页面位于主页面导航栏“全流程窗口”之后，视觉样式沿用现有 WPF 页面卡片、颜色和导航模式。

## 纳入范围

仅记录以下人工关注事件：

| 类型 | 入口 | 等级 |
|---|---|---|
| 线体安全异常 | `HandleLineSafetyAlarm` | 红色安全异常 |
| 独立引擎安全异常 | `HandleStandaloneSafetyAlarm` | 红色安全异常 |
| 天车连续全零保护 | `HandleCraneZeroPositionAlarm` | 红色安全异常 |
| 后天车明确黄色警告 | `OnRearCraneWarning` 的主页面处理入口 | 黄色警告 |
| 前端在途、斜床、动平衡、研磨应急 | 用户执行后的成功、失败和“仅清软件”确认 | 应急操作 |

不记录普通轮询失败、连接探测、自动重连、正常启动/暂停、普通控制台日志或所有 catch 异常。这样页面不会退化为难以检索的完整日志副本。

## 设计

### 事件中心

新增线程安全单例 `AttentionEventCenter`，仅维护最近 500 条 `AttentionEvent`。每条事件包含：

- 发生时间（本地时间）；
- 类型：红色安全异常、黄色警告、应急操作；
- 来源：线体/设备/功能名称；
- 线体：1号线、2号线、动平衡、研磨或全局；
- 事件正文；
- 可选结果：成功、失败、仅清软件。

事件中心只执行轻量内存写入和 UI 可观察集合通知；不执行 I/O、数据库、网络或同步等待。写入采用短临界区，超过 500 条时删除最旧记录。业务线程不依赖页面是否打开；页面关闭或未创建时仍可记录事件。

### 页面

新增 `AttentionMonitorView`，复用现有缓存导航机制。页面包括：

1. 标题“异常监控（当前程序生命周期）”和说明“程序关闭后自动清空”。
2. 四张摘要卡：红色安全异常数量、黄色警告数量、应急操作数量、最近事件时间。
3. 类型筛选：全部、红色安全异常、黄色警告、应急操作。
4. 来源筛选：全部、1号线、2号线、动平衡、研磨。
5. 倒序事件表：时间、等级、来源、内容、结果。

页面只展示和筛选，第一版不提供删除、确认、清报警、恢复引擎或设备控制按钮，避免将 UI 阅读状态误认为现场故障已处理。

## 接入方式

主页面现有的安全告警处理方法是集中入口，应在现有暂停和弹窗逻辑保持不变的前提下追加一次事件写入。后天车黄色警告同样在主页面订阅处理处追加事件写入。

应急事件在应急中心 UI 的异步操作完成后记录：执行目标、结果文本和是否“仅清软件”。若应急接口抛异常，也记录失败事件，然后保持既有弹窗行为。

禁止通过截获 `Console.WriteLine` 或关键词分析构造事件，因为它会误收集高频日志、依赖不稳定文本格式，并增加无意义字符串处理。

## 性能与业务隔离

- 事件记录为进程内固定上限 500 条，不随运行时间无限增长。
- 不在轮询循环、通信底层或设备动作内部挂钩；只在已有的人工关注告警和应急完成入口记录一次。
- 不新增 PLC、天车、机械手、CNC、数据库或文件写入。
- 不修改现有 `Pause()`、`Resume()`、`catch/finally`、动作锁、任务缓存和报警弹窗的执行顺序。
- 事件中心内部异常必须吞掉并保持原业务路径继续，监控故障不得反向影响生产流程。

## 验证

1. 编译通过。
2. 触发或直接调用红色、黄色和应急记录入口，确认页面摘要和筛选结果正确。
3. 连续写入超过 500 条，确认仅保留最新 500 条。
4. 在页面未打开时记录事件，再打开页面确认历史事件可见。
5. 检查导航、新页面创建与事件写入不修改任何设备寄存器、任务状态或引擎暂停状态。
