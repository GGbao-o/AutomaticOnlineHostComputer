# 全流程状态研磨缓存悬浮明细设计

## 目标

全流程状态页的“研磨缓存”卡片继续显示缓存数量和原有前两件摘要。鼠标悬浮在整张卡片上时，显示研磨 FIFO 中全部缓存工件的明细，便于现场查看真实排队内容，而不改变研磨缓存、派发或机台状态。

## 范围

只修改全流程状态页“研磨缓存”卡片的显示和对应只读 ViewModel 格式化属性。

不修改：

- 研磨 FIFO 的入队、出队、排序、锁和并发控制；
- 工件数据的来源、持件事实、机台 `PendingWorkpiece` 或研磨状态；
- 其他线路缓存卡片的显示方式；
- 卡片内已有的“前两件”摘要规则。

## 数据来源与顺序

明细直接使用 `GrindingFlowEngine.GetCachedWorkpiecesSnapshot()` 的线程安全快照。快照数组沿当前研磨 FIFO 顺序排列，悬浮列表必须按该数组顺序逐行显示，首项即下一件待派发工件。

每次 WPF 绑定读取属性时重新生成文本；不在 UI 层缓存、排序或修改工件对象。

## 显示规则

1. 缓存为空时，悬浮提示显示“无缓存工件”。
2. 缓存非空时，每件工件独立一行，行首显示从 1 开始的 FIFO 顺序号。
3. 始终显示直径：`D={Diameter}mm`。
4. 仅当 `Length > 0` 时附带长度：`L={Length}mm`。
5. `PlateNo` 非空时显示“版号={PlateNo}”；`Sequence` 非空时显示“序={Sequence}”。二者均缺失时不显示身份字段。

示例：

```text
1. 版号=12，序=22，D=222mm，L=111mm
2. D=205mm
```

## 页面交互

- 给“研磨缓存”整张 KPI 卡片设置只读 `ToolTip` 绑定，而不是只给数量数字设置，确保鼠标容易命中。
- 数量继续显示 `GrindingCachedCount`。
- 卡片中的 `GrindingCacheDetail` 保持当前仅展示前两件的简洁摘要，避免缓存较多时改变卡片高度。
- `ToolTip` 自动换行显示，且不提供按钮、编辑、排序或清除动作。

## 异常与边界

- 引擎尚未创建、快照为 `null` 或队列为空时，页面显示“无缓存工件”，不抛出 UI 异常。
- 单个字段为空或长度为 0 只影响该字段是否显示，不能导致整行消失。
- 该功能完全只读；悬浮、刷新和格式化都不能影响研磨流程。

## 验证

1. 空缓存时数量为 0，悬浮提示为“无缓存工件”。
2. 仅有直径的工件显示 `D=...mm`，不出现长度标签。
3. 同时有长度、直径的工件显示两者。
4. 有版号/序号的工件显示身份字段；缺失时不显示空标签。
5. 多件缓存时，悬浮提示逐行显示全部项目，顺序与快照 FIFO 顺序一致。
6. 卡片内原摘要仍最多显示前两件。
