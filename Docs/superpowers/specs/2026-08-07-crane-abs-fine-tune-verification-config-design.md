# 天车 XY 绝对编码器微调验证节奏配置

## 目标

将绝对编码器微调的读取稳定性节奏从代码常量移入运行时配置，并在现有“X / Y 绝对编码器标定值”配置页面中可编辑、保存且立即生效。配置为所有天车共享。

## 范围与非范围

本次仅调整微调前、微调后的等待和稳定采样节奏，不改变 X/Y 目标值、绝对编码器偏差计算、微调量上限、反馈跟随判定、异常暂停策略或天车动作协议。

已明确不处理 ST714 的显示 X 值为 `-1` 时与底层“跳过 X 轴”哨兵值冲突的问题；现场确认此前天车显示 X 不应为负数，该问题不属于本次配置改造范围。

## 设计

在 `motion_settings.json` 根级新增共享段：

```json
"absFineTuneVerification": {
  "beforeReadSettleDelayMs": 1200,
  "stableSampleCount": 3,
  "stableSampleIntervalMs": 200,
  "stableRangeMm": 1,
  "afterMoveMinSettleDelayMs": 1200
}
```

`XAbsFineTuneHelper` 读取这组共享配置，替代以下现有常量：微调前 500ms 沉降、稳定窗口 5 次、采样间隔 200ms、稳定范围 1mm、微调后最短 600ms 沉降。微调后最长 2000ms、每毫米 30ms、最大读取 20 次、最多微调 2 次及其异常逻辑保持不变。

稳定规则仍为窗口内每个参与轴的“显示坐标范围 <= stableRangeMm 且 Abs 编码器范围 <= stableRangeMm”；不是要求每次读数完全相同。

配置页面在现有 X/Y 绝对编码器微调区域新增五个数值输入框。输入写入内存中的共享配置对象，沿用页面现有“修改立即影响运行中后续动作、点击保存写入 JSON”的模式。

## 默认与验证

部署配置的初始值采用上述值：PLC 刷新周期约 1 秒时，先等待 1200ms 避开跨刷新混读，再以 200ms 间隔读取 3 次确认稳定。小距离微调后同样至少等待 1200ms，避免保留当前 600ms 的相同问题。

代码为缺失或非法配置提供安全默认值与范围约束，防止手工 JSON 配置为零、负数或不可用的采样窗口。测试覆盖默认值、配置驱动延时/窗口、页面绑定及 JSON 往返保存；构建项目并执行相关定向测试。

## 取舍

未采用只把样本数从 5 改为 3、仍保持 500ms 的方案：它可能更快，但仍可能读取 PLC 刷新前的旧快照。也未采用等待 PLC 刷新序号的方案：它的正确性更强，但需要 PLC 提供新的版本/时间戳信号，超出本次软件侧的最小改动范围。
