# 取板探测次数与步长可配置

用户已要求把现有固定探测规则做成可调配置，并要求继续执行。保持当前默认3个位置、每次5mm；不新增独立累计距离输入，避免次数、步长与上限矛盾。

在`MotionConfig.Grinding`增加`PickupProbeCount=3`、`PickupProbeStepMm=5`，JSON字段分别为`pickupProbeCount`、`pickupProbeStepMm`。两项供5台天车和机械手1/2/3全线共用，沿用已有全线X11配置的分组和保存方式。旧配置缺少字段时使用默认值。

配置页面增加次数、步长输入及累计下降量预览：`(次数-1)*步长`。次数包含首次位置，次数1表示只探测首次位置，不补偿。次数和步长必须为正整数，乘积不得超过32位坐标范围；不把非法值静默改成另一套运动参数。每次取板开始固定不可变快照；正在执行的取板不会中途读取新的次数/步长，后续取板使用当前内存配置。直接编辑磁盘JSON不增加热重载。

14个生产入口显式传入快照；组件的循环、目标坐标、实际上界及日志/异常内容统一使用快照。补偿到位容差始终小于步长：步长1mm时使用0mm容差，其余保持1mm，避免未运动就当作到位。无板、未知反馈、充磁失败仍交原引擎严重异常收尾，不修改暂停、作废、缓存归属、设备清理、锁释放和已交接保护。

测试覆盖旧JSON默认值、JSON序列化、页面共享绑定、14入口、次数1/4、非5mm步长、非法参数/乘积溢出禁止运动、参数快照和1mm到位验证。保留用户已有配置值及其他未提交文件；Git只提交新增JSON两字段，不混入用户原配置差异。更新现行运维和配置文档，本地commit，不push。
