# 研磨目标位参数下发与XY并行设计

## 目标

缩短研磨天车5把已持工件从ST709送往目标研磨机的等待时间：目标研磨机XY绝对移动与最终加工参数下发并行执行；参数下发完成后立即发送“数据传输完成”3秒信号；XY、参数和数据完成信号均成功后，才执行目标位绝对编码器微调。

本设计只调整研磨上料流程中“持件离开ST709安全Z后，到目标位微调完成前”的执行顺序，不改变取料、请求上料、门开、Z下降、夹紧、退磁、上料完成、下料及FIFO规则。

## 当前顺序

当前 `ProcessWorkpieceAsync` 在确认ST709取料、Z安全回升及M731通知成功后，依次执行：

1. XY绝对移动到目标研磨机。
2. 写最终直径、孔型、长度。
3. 写数据传输完成3秒信号。
4. 等待请求上料、等待门开。
5. 目标位X绝对编码器微调。
6. Z下降和后续上料交接。

## 新顺序

1. 保持既有前提：工件已由X11确认持件、Z安全回升和M731通知均成功。
2. 创建XY绝对移动任务，目标为配置偏移后的目标研磨机X/Y。
3. 同时创建参数链任务：写最终直径、孔型、长度；该写入成功后立刻发送数据传输完成3秒信号。
4. 使用 `Task.WhenAll` 等待XY任务和参数链任务均成功完成。
5. 仅在第4步全部成功后，登记XY到位成功并执行目标位绝对编码器微调。
6. 微调成功后，保持既有顺序等待请求上料、等待门开、计算并下降到装料高度、通知锁紧、等待锁紧、退磁、Z安全回升和上料完成。

`Task.WhenAll` 的语义要求两个任务均已结束才继续，因此XY失败时不会在参数链仍处于3秒信号中途就开始清理；参数链失败时也不会提前进入微调。

## 异常处理

### 并行窗口和微调窗口

从参数链开始尝试起，到目标位微调成功前，任何XY、参数写入、数据传输完成信号或微调异常都进入新清理规则：

1. 自动调用目标研磨机的 `ClearEmergencyRegistersAsync`，清空该机上位机输出及最终直径、孔型、长度参数。
2. 自动清理完成后，继续走既有上料异常处理：研磨引擎暂停，工件保留在该机 `PendingWorkpiece`，状态保持`Loading`，不回研磨FIFO。
3. 自动清理本身失败时，仍暂停；日志和安全报警同时记录原始失败与清理失败，不能用清理异常覆盖原始失败。

工件在此窗口已经由X11确认持件，故不允许因为清参数而回FIFO；FIFO中不再出现同一块物理板，防止重复派发。

### 范围外异常

目标位微调成功后，后续请求上料、门开、Z下降、锁紧、退磁、Z回升和上料完成维持现有异常语义。本次不改变已经进入物理交接后的信号和参数清理规则，避免在工件已处于研磨机或目标待交接时误清PLC状态。

## 可观测性

新增控制台和 `OperationalLog` 记录：

- 并行XY与参数链开始、分别成功、汇合成功。
- 参数链开始后出现异常时的自动清理开始和结果。
- 清理失败时的原始异常、清理异常、目标机台、工件身份和“Pending保留、引擎暂停”结果。

## 验证

新增或调整合同测试覆盖：

1. XY任务与参数链在同一并行窗口启动，参数链内参数写入先于数据完成信号。
2. `Task.WhenAll` 成功后才执行目标位微调。
3. 请求上料和门开仍在微调成功后执行。
4. 并行窗口或微调窗口异常触发 `ClearEmergencyRegistersAsync`，并保留Pending、不回FIFO。
5. 微调成功后的后续交接异常不纳入本次自动清参数范围。

主项目构建和研磨相关合同测试必须通过；工作区存在的无关旧测试失败单独记录，不为通过测试修改现场配置或无关逻辑。
