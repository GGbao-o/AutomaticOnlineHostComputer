# 手动报警显示与动平衡运动超时告警设计

## 目标

在手动操作页面只读显示设备报警状态；动平衡机械手 2、3 已发出的 Y/Z 运动发生超时时，暂停动平衡并弹出该超时异常的原始信息。

## 手动操作页报警状态

- 复用手动页面现有的 `ReadStatusAsync` 状态读取，不增加 PLC 写入、清除、确认或业务联锁。
- 报警值来自同一状态块：`D5011` 伺服报警、`D5012` PLC 伺服指令报警、`D5013` PLC 报警。
- 三个值任一非零即显示红色“报警”；三者均为零显示绿色“正常”；未读到或读取失败显示灰色“报警状态未知”。
- 文案同时给出三个原始数值，便于现场按地址表排查。
- 切换设备或刷新开始时清为未知，避免旧设备结果覆盖新设备。

## 动平衡运动超时

- 只对 `CraneMotionTimeoutException` 作专门处理，覆盖机械手 2、机械手 3 的任何已调用 `MoveAbsoluteAsync` 的 Y/Z 超时。
- 专门处理只执行：保留异常原始消息、`_paused = true`、调用既有 `OnSafetyAlarm`。
- `OnSafetyAlarm` 已由主页面接入：暂停动平衡、写入关注事件，并显示错误弹窗。不得重新包装或掩盖原始超时文本。
- 原有 `finally` 的位置锁释放和 Busy 清理保持不变；它仅释放本趟已经取得的 M2/M3 锁。
- 不新增动作账本门禁、人工结案、来源状态写入、工作件缓存迁移、线路启动限制或自动恢复逻辑。

## 验收

1. 手动控制 VM 从 `CraneStatus.ServoAlarm`、`PlcServoAlarm`、`PlcAlarm` 生成可绑定的只读报警状态和包含三个值的文案；XAML 按正常/报警/未知呈现。
2. M2、M3 的既有通用 catch 识别 `CraneMotionTimeoutException`，暂停并把 `timeout.Message` 传给 `OnSafetyAlarm`，随后继续既有异常记录和 finally 清理。
3. 合约测试验证上述两项，同时明确不引入线路启动的动作账本检查。
