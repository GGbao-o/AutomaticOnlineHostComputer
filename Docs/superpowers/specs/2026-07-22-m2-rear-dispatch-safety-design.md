# M2来源缓存与后天车分流等待设计

## 目标

修复机械手2来源身份门槛、M817路径的双后天车安全区检查，以及1号线后天车持板分流到ST010时M720临时不可放料的错误暂停。

## 不变边界

- M817、M818、M720的位置锁与既有获取/释放顺序不变。
- M720通信读取失败、取消或其他设备动作异常仍按原有安全异常路径处理；只有成功读取到M720=0改为等待。
- ST020来源仍只需确认4号后天车；M817来源必须同时确认2号与4号后天车。
- 不改M3Flow对M720的异常处理。

## 设计

1. M2派发前同时取得`m817Cached`与`m818Cached`。M817来源必须满足`_m817 && m817Cached && !m818Cached`；M817有板但缓存未到时不占用busy、不拿锁、不启动M2Flow，只按主循环节流写等待日志。
2. M817来源派发前依次确认2号、4号后天车的`XPos <= RearCraneSafeX`；任一不满足时跳过本轮。ST020来源维持只确认4号后天车。
3. 1号线后天车已持板且已获取M817/M720锁后，M720二次读为0时在原地轮询等待。每10个轮询周期输出一次包含工件身份的提醒日志；读到1才继续XY、Z下降和放料。读异常继续抛出，保留原有暂停安全路径。

## 验收

- M817=1但无M817缓存时不出现`M2Flow`派发，日志为等待缓存。
- M817缓存就绪、2号或4号任一X超阈值时不派发；两台都安全才允许派发。
- M720二次读为0时不抛“禁止放料”、不暂停，持续保留锁并等待；恢复为1后正常继续。
- MC65读取失败仍走原有异常/暂停逻辑。
