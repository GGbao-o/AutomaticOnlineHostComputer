# 前端主循环低风险效率优化设计

## 目标

在不改变PLC/CNC握手、状态机阶段和安全二次确认的前提下，减少前端主循环重复通信，隔离UNC阻塞，并改善高频日志与慢轮诊断。

## 设计

1. `CenteringRackService.ReadAllStatusAsync` 暴露已经读取的M816第二字，两个前端不再紧邻重复读取M800~M831。
2. 货叉和双头镗状态仅在单次主循环内复用。取料前货叉确认、R6103紧轮询、机械手安全确认、锁内目的位确认和X11检查仍直接读取。
3. 写M911~M914后货叉快照立即失效；R握手后台写入不会允许写前快照推动新的业务阶段，下一轮重新采集。
4. 打号机共享目录由独立后台监视器单飞探测；主循环只读带时间戳的缓存。实际打标前的目录和文件检查保持原样。
5. 高频成功状态按“变化或10秒心跳”记录；动作、握手写入、异常和暂停日志始终保留。
6. 慢轮指标只计算业务IO，不包含正常轮询Delay，且告警节流。
7. 天车IP先按TypeName与Name精确匹配，再以Name-only兼容旧数据库并告警。

## 明确不做

- 不建立全局DeviceStateCache。
- 不修改轮询频率。
- 不改变AutoFlush日志持久化策略。
- 不合并1/2号线引擎，不调整锁顺序。

## 验证

- 编译通过。
- 四处主循环`ReadM816Async`调用消失，实时安全读取仍存在。
- R6102/R6104/R6108及M911~M914写入顺序不变。
- 正常镗孔、SkipBoring和打号机离线场景需现场联调。
