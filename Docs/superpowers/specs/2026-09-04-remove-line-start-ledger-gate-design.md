# 移除线路启动动作账本门禁设计

## 目标

允许操作员在已自行通过页面清除状态、将设备恢复为空闲后，直接启动或恢复 1 号线、2 号线；启动按钮不再因动作账本仍存在待人工确认快照而拒绝执行。

## 范围

仅删除 `HomeViewModel` 中线路启动/恢复前的“待人工动作账本”门禁调用。

保留以下行为：

- 天车 1/2 或 3/4 的 XYZ 连续全零保护；
- 每个引擎自身的暂停状态、斜床 `Loading`/`Unloading`/`Idle` 状态、工件缓存、任务牌和软件锁处理；
- 所有应急、清除状态和动作账本功能；
- 动平衡和研磨的独立启动行为。

## 设计

`Line1ToggleAsync` 与 `Line2ToggleAsync` 在用户从“未运行”切换到“启动/恢复”时，仍先调用 `EnsureCranePositionsReadyForStartAsync`。该检查只防止相关天车在掉电后连续两次读到 XYZ 全零时带着未知坐标重新派发动作。

通过坐标检查后，直接按现有分支调用对应前端与后端引擎的 `Start()` 或 `Resume()`，不再查询 `FlowActionManualRegistry`，也不显示“仍有物理动作等待人工确认”的启动拦截弹窗。

`EnsureNoPendingManualActionsForLine` 可以保留为未调用的诊断辅助，或连同其说明删除；最终代码不得再让它参与线路启动或恢复决策。

## 风险与边界

此变更不会自动清除旧异常状态。若操作员没有先正确清除相关斜床、缓存或任务牌，线路可能显示为运行但对应设备不会派发新任务；这是操作员选择手工处置后的现场责任。

本变更不允许绕过 XYZ 全零保护，也不允许在启动按钮中自动作废工件、写 PLC/CNC 或释放锁。

## 验收

1. 1 号线存在任意 `PauseOnCarrier` 或 `PauseAtTargetPendingHandoff` 动作账本快照时，点击启动不再显示账本门禁弹窗，并正常调用前后端 `Start()` 或 `Resume()`。
2. 2 号线同样适用。
3. 相关天车连续两次 XYZ 全零时，启动仍被拦截。
4. 当前应急和清状态入口的行为不变。
