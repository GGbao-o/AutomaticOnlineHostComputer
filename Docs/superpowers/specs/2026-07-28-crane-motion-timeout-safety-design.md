# 全体天车绝对运动超时安全暂停与恢复设计

## 目标

任一自动流程中的天车 X、Y 或 Z 绝对运动未在规定时间内到位时，统一进入可追溯的安全暂停，而不是把超时当作可自动重试的普通异常。此设计覆盖 1/2 号线前后天车及研磨天车；保持现有 `±5mm` 到位容差。

## 现状与问题

`CraneService.MoveAbsoluteAsync` 对 XY-only 调用默认等待 240 秒；带 Z 方向联锁的调用先以 `timeoutMs / 2` 等待前置轴，随后又使用完整 `timeoutMs` 等待最终到位。超时只抛出普通 `TimeoutException`，没有天车号、参与轴、最后坐标或未到位轴等结构化证据。

后端从中转架取料的 XY 超时发生在 X11 取料确认之前。现有通用 catch 会将工件缓存恢复、释放动作和碰撞区锁并允许下一轮重试，但天车的实际 XY 位置未知。这可能使其他设备进入仍被天车占用的区域。

## 方案比较

1. 在每个业务 catch 中单独识别 `TimeoutException`。改动分散，容易遗漏微调和后续新流程，不采用。
2. 由 `CraneService` 直接暂停页面引擎并弹窗。通信服务不知道调用来源、所属引擎和锁，职责越界，不采用。
3. 公共服务生成专用运动超时异常；各流程引擎使用统一安全分支暂停并上报；主页面复用既有安全告警入口。推荐。

## 统一超时规则

- XY-only：120 秒。
- Z-only：120 秒。
- XY 后 Z 下降：XY 前置阶段最多 120 秒；XY 到位后 Z 阶段最多 120 秒。
- Z 上升后 XY：Z 前置阶段最多 120 秒；Z 到位后 XY 阶段最多 120 秒。
- 同一动作的每个安全串行阶段独立计时；不再使用“240 秒除以 2 再追加完整 240 秒”的混合语义。
- 默认值写入 `motion_settings.json` 并由 `MotionConfig` 读取；调用点保留显式覆盖能力，微调使用相同 XY 超时配置。

## 通信服务职责

新增 `CraneMotionTimeoutException`，继承 `TimeoutException`，只描述事实：天车名称/编号、目标 XYZ、参与轴、容差、阶段名称、最后一次成功读取的实际 XYZ、尚未到位轴、已等待时间，以及停止命令的执行结果。

`CraneService` 在运动超时时：

1. 使用不可取消令牌复位 D4520/D4521/D4522；
2. 调用已批准的 PLC 安全停止路径（D4518 手动伺服急停）并记录成功或失败；
3. 读取一次最终状态作为证据；读取失败明确标记为未知；
4. 抛出专用异常；不读取业务缓存、不暂停引擎、不操作 UI 或锁。

下压保护 `PressureStopException` 的既有语义不改变；运动超时是独立的“位置未确认”事件。

## 引擎安全分支

所有自动天车流程在最外层动作 catch 中优先捕获 `CraneMotionTimeoutException`。分支必须：

1. 停止当前动作，禁止继续任何 Z、XY、磁铁、握手、缓存写入或下一轮派发；
2. 将所属引擎置暂停，并通过既有 `OnSafetyAlarm` / `OnRearCraneSafetyAlarm` 进入主页面红色弹窗与异常监控；
3. 保留工件身份和动作阶段为“天车位置未知、待人工确认”；不得基于“尚未 X11=1”自动恢复或删除来源缓存；
4. 记录专用结构化事件，包含异常内的最终位置、目标、超时轴、工件、动作阶段和锁状态。

适用引擎：`Line1FrontFlowEngine`、`Line1RearFlowEngine`、`Line2FrontFlowEngine`、`Line2RearFlowEngine`、`GrindingFlowEngine`。动平衡机械手不属于本次“天车”范围，保持既有异常策略；其后续统一运动策略另行评估。

## 锁与工件所有权

超时不等同于设备已离开区域，因此不能在 finally 中无条件释放 `ZoneMT`、`ZoneTS` 或其他覆盖当前位置不确定范围的碰撞区锁。

- 普通动作生命周期锁可结束，避免执行线程永久占有。
- 碰撞区锁必须转为同一引擎持有的“安全占用”，直到人工确认实际位置并明确释放。
- 工件缓存必须从“可分派”转为“在途待确认”或“来源已预占”。只有人工确认工件仍在来源位后才恢复可分派；确认天车持件或已人工移走时进入对应人工处置路径。

斜床应急在中转架取料前取消动作时，需要依据上述在途阶段恢复预占，而不是静默丢失 M817/M818/M821 缓存。

## 人工恢复

异常页面/应急处理需要显示：天车号、最后实际 XYZ、目标 XYZ、未到位轴、X11、伺服/PLC 报警、工件、当前安全占用和来源/目标站。

恢复前先实时读取上述状态。操作员人工确认后选择一个明确结果：

1. 工件仍在来源位：释放安全占用，取消预占，恢复来源缓存；
2. 天车持件：保留在途工件，进入对应天车/斜床应急处理；
3. 工件已人工移走或报废：记录作废，清理对应软件状态后释放安全占用。

任何选项都不自动移动天车、磁铁或工件；完成后仍需人工点击恢复引擎。
