# 源码事实优先的通信与设备交互文档更新设计

## 目标

以当前生产源码为唯一事实来源，系统复核并补全 `Docs/02-通信协议手册`、`Docs/03-设备交互流程`、`Docs/全线设备协议寄存器速查总表.md` 与 `Docs/全线业务逻辑详解.md`。本次只更新 Markdown 文档，不修改任何 C#、配置、PLC、CNC 或设备行为。

## 范围

覆盖以下设备和交接链路：

1. 汇川天车/机械手：手动模式、绝对目标、触发位、位置轮询、X2 下压、接液盘、超时和触发位复位。
2. 三菱 MC：MC63 总上料架/中转架、MC64 研磨下料架、MC65 研磨上料架/动平衡料架及按字单 bit 写入。
3. 货叉和双头镗：货叉状态、M912/M913/M914 与 R6101~R6108 握手、参数缩放和读回边界。
4. 研磨机：TypeA/TypeB 输入、输出、任务分配、磨石报警单机禁派发及下料闭环。
5. 锦州 Modbus 斜床、FANUC FOCAS 斜床、打标文件握手。
6. 03 设备交互流程中的跨设备顺序、软件缓存归属、PLC/CNC 确认点、锁与异常收尾。

## 写作与判定规则

1. 地址、端口、函数语义、数据类型、单位、缩放、读写功能码、轮询与超时均从当前源码提取；仅在源码不能决定的现场物理语义上保留“需现场/PLC 手册确认”。
2. 每个交接信号至少说明：谁写/谁读、触发值和复位值、软件成功条件、失败后代码实际处理及是否存在结果未知。
3. 明确区分 PLC 物理信号、软件缓存、触发命令和完成确认；不得把任一项表述为另一项的替代品。
4. 对当前源码已有的安全边界或缺口如实标注为“当前实现边界”；不把建议中的改进、人工规程或理想 PLC 行为写成当前已实现能力。
5. 文档间采用“总表索引 + 设备协议细节 + 交互流程 + 全线业务语义”的分层结构，避免重复且互相矛盾。

## 执行顺序

1. 建立源码—文档映射，逐份列出现有章节、对应服务/引擎和差异。
2. 先更新通信协议手册及协议速查总表，再更新 03 设备交互流程。
3. 最后把跨设备业务结论回写到《全线业务逻辑详解》，并检查术语、地址和异常描述一致性。
4. 使用 `git diff --check`、文档关键字/链接检索及源码交叉检索复核；若既有无关文档格式问题导致全量检查失败，单独说明其位置，不归入本次修改。

## 非目标

- 不修改生产代码、PLC/CNC 程序、运行配置或设备参数。
- 不根据日志、猜测或历史文档覆盖当前源码事实。
- 不宣称当前代码已解决任何仍存在的通信结果未知、下压恢复或并发调用风险。

## 验收标准

1. 所有 02 通信协议手册、协议速查总表和 03 设备交互主文档均有明确的源码依据和一致的术语。
2. 主业务文档能说明主要设备交接的缓存、握手、完成点和异常实际行为。
3. 更新后的文本不含把“命令已发送”误称为“物理动作已完成”、把“缓存存在”误称为“现场有板”的描述。
4. 本次涉及文档的差异经人工审读和格式检查；不产生任何源码变更。
