# 磁铁充退磁三次反馈确认与自动安全暂停设计

日期：2026-09-11

## 目标

统一天车和机械手的充磁、退磁反馈确认：充磁确认 X6=1，退磁确认 X7=1 且 X6=0。两类动作均最多三次、每次等待三秒，参数由同一份运动配置控制。

自动流程的充磁或退磁最终失败必须停止本趟动作、暂停所属引擎、弹出原始失败原因，并由既有 `finally` 释放软件锁。手动页面使用同一反馈校验，但仅显示本次手动命令失败，绝不暂停任何引擎。

## 一、配置

在 `motion_settings.json` 的 `safety` 段新增一组共用参数：

```json
"magnetFeedbackMaxAttempts": 3,
"magnetFeedbackTimeoutMs": 3000
```

- 两个参数同时用于充磁与退磁，所有天车和机械手共用。
- 配置无效（小于 1）时，代码回退为 3 次与 3000ms，避免配置误填造成不等待或无限等待。
- 清理既有未被 `CraneService` 使用的 `magnetOffMaxRetries`、`magnetOffRetryIntervalMs`，避免页面配置与实际行为不一致。

## 二、设备服务动作语义

### 2.1 充磁

每一次尝试严格执行：

1. 写 `D4510=2` 触发充磁。
2. 在 `magnetFeedbackTimeoutMs` 内轮询 X6。
3. 读到 `X6=1` 即为本次成功。
4. 无论成功、反馈超时或读取异常，都在 `finally` 写 `D4510=0` 收尾。
5. 只有“反馈有效读到 0 至超时”才进入下一次尝试。
6. 三次均未获得 X6=1 时，抛出包含设备名、充磁、尝试次数、最后 X6 状态的专用磁铁反馈异常。

### 2.2 退磁

每一次尝试严格执行：

1. 写 `D4511=2` 触发退磁。
2. 在 `magnetFeedbackTimeoutMs` 内轮询 X6、X7。
3. 读到 `X7=1` 且 `X6=0` 即为本次成功。
4. 无论成功、反馈超时或读取异常，都在 `finally` 写 `D4511=0` 收尾。
5. 只有“反馈有效但未满足 X7=1 且 X6=0 至超时”才进入下一次尝试。
6. 三次均未成功时，抛出同一专用异常，记录最后 X6/X7 状态。

### 2.3 通讯未知

X6/X7 读取抛出异常时不将其等价为 0，也不继续下一次磁铁触发；当前尝试收尾写 0 后，立即抛出状态未知异常。现场反馈未知时不能把重触发当作安全恢复。

## 三、自动流程失败处理

适用引擎：1、2号线前端、1、2号线后端、动平衡、研磨。

- 所有自动流程的 `MagnetOnAsync`、`MagnetOffAsync` 调用均通过专用磁铁反馈异常进入既有安全异常路径。
- 专用异常被动作异常解析器明确归类为 `PauseLineManual`，不依赖调用点是否已登记物理命令。
- 各引擎复用既有“暂停 + 安全弹窗 + 动作 finally”机制；弹窗包含设备、充磁/退磁、三次尝试、最后反馈状态和原始异常文本。
- 本趟动作不再继续执行 X11 判断、轴运动、PLC/CNC 握手或下一轮自动重试。
- 既有 finally 释放本趟软件锁，不能形成软件锁死；物理磁铁和工件事实保留，需人工确认后再恢复。
- 不新增动作账本启动门禁、来源结案、缓存迁移或 PLC 业务写入。

## 四、手动页面

- 手动操作页面仍调用同一 `CraneService` 充/退磁方法，因此也要求真实反馈到位。
- 三次失败或读取异常时，手动命令呈现失败文本；不调用任何流程引擎的暂停、任务牌、锁或弹窗回调。

## 五、实现边界与验证

- `CraneService` 新增磁铁反馈异常类型和动态配置提供者；两类连接缓存创建服务时传入配置提供者，因此运行中重新加载配置后下一次磁铁动作可使用最新值。
- `FlowActionExceptionResolver` 显式识别专用异常，保证所有自动动作统一走人工确认暂停结论。
- 审计六个自动引擎的磁铁调用点：不得吞掉专用异常后继续业务步骤。
- 更新 `Docs/全线业务逻辑详解.md` 及磁铁/运动配置相关说明。
- 新增契约测试覆盖三次配置、X6/X7 条件、自动异常暂停分类与手动页不触发引擎暂停；构建和聚焦测试必须通过。

## 自检

- 无占位项；默认值、失败边界、通讯未知与自动/手动差异均明确。
- 三次与三秒只存在于同一套 `safety` 配置，没有独立充磁/退磁不一致参数。
- 本设计不改变启动线路门禁或正常成功动作路径。
