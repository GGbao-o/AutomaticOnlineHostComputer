# 主页面单设备清空状态设计

## 目标

主页面“清空状态”窗口不再按设备组批量操作。1号线5台斜床、2号线5台斜床和4台研磨机分别提供独立按钮，点击哪个站号只清哪个设备中由上位机写入的数据。

## 清理范围

- ST108~ST111：10300~10305加工参数及10370~10374控制命令写0。
- ST112、ST606~ST610：#800/#801/#802/#909/#1101~#1105写0。
- ST701~ST702：R7311~R7318写0。
- ST703~ST704：40011~40014写0。

地址由 `ModbusSkewBedService`、`FanucSkewBedService`、`PlcGrinderService` 的 `ClearEmergencyRegistersAsync` 统一维护，页面不再重复硬编码。

## 安全边界

- 删除斜床/研磨机成组按钮和“一键清空全部”。
- 每次操作弹窗显示目标站号、IP和清理地址；用户确认后才执行。
- 同一时间只允许一个清理操作，防止误点多个按钮并行写设备。
- 只清设备寄存器，不清上位机任务、工件缓存、Pending、锁和引擎状态。
- 不写设备反馈/请求输入；不控制天车、机械手或机床物理运动。
- 对应引擎必须先停止或暂停，否则正常流程可能重新写入刚清除的值。
- 需要清软件状态或释放锁时继续使用“应急处理”，不由“清空状态”代替。

## UI

- 双头镗原有两个独立按钮保持不变。
- 斜床按1号线和2号线各显示5个独立按钮。1号线按现场物理顺序显示为 ST108、ST109、ST111、ST110、ST112，其中 ST111 是3号斜床、ST110 是4号斜床。
- 研磨机显示ST701~ST704四个独立按钮。
- 日志逐台记录开始、地址范围、成功或异常；操作结束恢复按钮。
