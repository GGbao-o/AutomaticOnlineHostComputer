# 研磨状态超时与上料优先设计

## 目标

将研磨引擎的统一卡死观察时间改为三个可配置的状态超时：上料中 10 分钟、等待下料 20 分钟、下料中 10 分钟；并将调度策略改为上料优先，上料不可派发时才尝试下料。

## 状态超时

`MotionConfig.Grinding` 使用三个以分钟为单位的属性：`LoadingTimeoutMinutes`、`WaitingForUnloadTimeoutMinutes` 与 `UnloadingTimeoutMinutes`。默认值依次为 10、20、10。旧的 `GrindingStuckTimeoutMs` 不再参与引擎判断，避免一个配置项表面可改、实际被硬编码下限覆盖。

引擎继续仅检查 `Loading`、`WaitingForUnload` 和 `Unloading`。每台研磨机保留既有 `StateChangedAt` 起算点；主循环按当前状态选取对应分钟数。配置值小于 1 分钟时，运行时按该状态默认值处理，避免异常配置导致立即暂停。

配置页面增加“研磨状态超时（分钟）”卡片，提供上料中、等待下料、下料中三个输入框。输入直接写共享配置实例，下一轮研磨主循环立即使用；既有“保存到文件”按钮将值持久化到 `motion_settings.json`。

## 调度优先级

主循环在完成扫描、超时检查和加工完成转 `WaitingForUnload` 后，先调用上料派发判断。只有没有启动上料任务时才调用下料派发判断。

上料可派发需同时满足：存在请求数据且空闲、服务已连接、无 Pending 工件且无磨石报警的研磨机；ST709 的 M730 有板；FIFO 有工件；研磨天车可取得。任一条件不满足时，才允许检查并派发下料。下料仍需 Pending 工件存在且 ST710 的 M720 允许放料。

上料和下料都沿用既有 `_craneLock`、`_grindingDispatchGate`、派发前位置校验、动作版本和应急二次确认。一个周期最多启动一个天车动作。

## 验收

1. 配置文件和页面显示三个默认分钟值 10、20、10，保存后重新加载仍保留。
2. `Loading`、`WaitingForUnload`、`Unloading` 分别使用对应配置，其他状态不参与超时暂停。
3. 上下料均可派发时只启动上料；上料缺少任一前置条件时，才允许派下料。
4. 配置为 0 或负数时不会导致即时暂停，运行时回退该状态默认值。
5. 既有天车锁、应急取消、人工结案和下料架 M720 安全门槛不变。
