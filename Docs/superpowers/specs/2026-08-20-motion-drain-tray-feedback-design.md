# 运动参数页接液盘控制与门反馈设计

## 目标

在“运动参数设置”页为 5 台天车提供接液盘打开、关闭操作，并在用户点击“刷新设备状态”时显示接液盘门开到位与关到位的实际 PLC 反馈。3 台机械手没有接液盘硬件，相关按钮和状态必须隐藏。

## 点位与读写方向

| 功能 | PLC 点位 | Modbus 地址 | 方向与协议 | 语义 |
|---|---|---:|---|---|
| 打开接液盘 | D4512 / M60 | 4512 | 上位机写，FC06 | 写 `2→0` 脉冲触发 |
| 关闭接液盘 | D4513 / M61 | 4513 | 上位机写，FC06 | 写 `2→0` 脉冲触发 |
| 门开反馈 | X0 | 63488 | 上位机读，FC01 | `1=门开到位`，`0=门开未到位` |
| 门关反馈 | X1 | 63489 | 上位机读，FC01 | `1=门关到位`，`0=门关未到位` |

## 界面方案

复用现有 `ManualMotionControlPanel` 和 `CraneManualControlViewModel`：

- “设备操作”区域继续使用现有“接液盘打开”“接液盘关闭”按钮及命令。
- 两个按钮仅在当前选择项属于 `ManualDeviceType.Crane` 时显示；选择任意机械手时隐藏，不占用可操作入口。
- 在现有“设备实际反馈”区域增加两个独立标签：门开反馈和门关反馈。
- 两个反馈标签同样仅在选择天车时显示；选择机械手时隐藏。
- 不合并为单一门状态，直接显示 X0、X1 的原始判定，便于识别未到位、双信号同时出现以及现场接线问题。

## 状态与刷新

门开、门关各使用独立的 `bool?` 状态：

- `true`：显示“门开到位（X0=1）”或“门关到位（X1=1）”。
- `false`：显示“门开未到位（X0=0）”或“门关未到位（X1=0）”。
- `null`：显示“门开读取未知”或“门关读取未知”；通信失败不能按未到位解释。

点击现有“刷新设备状态”时：

1. 保持现有坐标、X6、X7、X11、X2 刷新行为。
2. 当前设备为天车时，再读取 X0 和 X1。
3. 当前设备为机械手时，不读取 X0、X1，并保持接液盘状态为空。
4. 切换设备后立即清空两个接液盘状态；异步读取返回前再次核对选择项，避免旧设备结果覆盖新设备。
5. X0 或 X1 单项读取失败时只把该项置为未知，不影响坐标和其他反馈更新。

接液盘打开或关闭命令执行后不自动推断门已到位；实际结果仍以用户点击“刷新设备状态”后读到的 X0、X1 为准。

## 代码范围

- `Communication/DeviceAddresses/CraneAddress.cs`：补充 X0 门开、X1 门关只读线圈常量。
- `Presentation/ViewModels/Home/CraneManualControlViewModel.cs`：公开天车选择状态，增加两项可空反馈、文本与条件读取。
- `Views/Motion/Controls/ManualMotionControlPanel.xaml`：增加门反馈标签，并按设备类型隐藏按钮和标签。
- `AutomaticOnlineHostComputer.Tests/Presentation/ManualMotionMagnetFeedbackContractTests.cs`：覆盖地址、刷新读取、三态文本和天车专属显示约束。
- 通信协议及运动参数页面说明文档：补充 X0/X1 已接入手动页面刷新功能。

## 异常边界

- 本功能只增加手动页面显示，不改变自动运动中“Z 下降前开盘、固定等待 500ms”的既有逻辑。
- 本功能不把 X0/X1 接入自动 Z 轴运动互锁，也不改变自动引擎暂停策略。
- 手动写 D4512/D4513 失败沿用现有命令异常处理；读取失败显示未知。
- X0=1 且 X1=1 时两个标签会同时显示到位，用于暴露现场信号冲突，不在界面层替 PLC 猜测实际门位置。

## 验收标准

1. 选择任意一台天车时，可以看到并使用“接液盘打开”“接液盘关闭”按钮。
2. 选择任意机械手时，两个按钮和两个接液盘反馈标签均隐藏。
3. 天车状态刷新读取 FC01 地址 63488、63489，并正确显示 X0、X1 的 `1`、`0`、未知三态。
4. 切换设备不会残留上一设备的接液盘状态。
5. 接液盘单项读取失败不阻断坐标、磁铁、有板和下压状态的其他刷新结果。
6. 自动天车运动行为保持不变。
