# 卜松浩 C# 上位机简历重构设计

## 目标

将现有简历重构为面向校招和初级 C# 上位机岗位的 A4 两页单栏简历，在不夸大个人贡献的前提下，突出工业现场经验、设备通信、运动控制、多设备协同和跨专业联调能力。最终同时交付 DOCX 与 PDF，原简历保持不变。

## 受众与定位

- 目标岗位：C# 上位机开发、自动化设备软件、运动控制和工业设备集成。
- 候选人身份：2027 届软件工程本科生，两段经历均按实习处理。
- 核心印象：具有真实工业项目与现场联调经验，能够理解设备动作、PLC 信号和软件状态之间的关系，而非只做界面开发。

## 页面结构

采用 A4 纵向、两页、单栏结构，避免复杂侧栏和大面积装饰，兼顾招聘者阅读与招聘系统解析。

### 第一页

1. 姓名、联系方式、城市和求职方向。
2. 两至三行个人概况。
3. 教育背景。
4. 核心技能，按 C# 客户端、工业通信、运动控制和工程实践分组。
5. 青岛万美制版有限公司实习经历及无人化自动线项目。

### 第二页

1. 东莞三太自动化设备实习经历及激光打标和三轴运动控制项目。
2. 证书与荣誉。

不再单独设置与项目重复的“个人优势”和泛化“项目亮点”。

## 内容策略

### 自动线项目

保留五至六条高价值内容：

- 多类型设备与 Modbus TCP、三菱 MC、FANUC FOCAS、Syntec 等通信集成。
- 并发轮询、单设备超时、信号新鲜度和旧状态防护。
- FIFO、工件账本、来源预约、现场确认和提交机制。
- 分区资源锁、统一锁顺序和异常幂等释放。
- 通信结果未知时的流程暂停、工件归属保留和人工恢复。
- 对关键调度、握手和异常场景的 xUnit 合同或单元测试。

只有候选人确实参与的内容使用“参与”“负责模块”“协同完成”等措辞，不写“独立完成整线”或“主导 PLC 编程”。

### PLC 机械与外接信号联调

作为简历中的明确亮点，写明：

- 与 PLC 工程师共同确认寄存器点位、信号责任方、请求应答复位时序和报警条件。
- 与机械、电气及设备人员共同确认运动方向、机械干涉、动作先后关系和安全边界。
- 参与磁吸确认、下压保护、到位、回零、伺服报警等外接传感器或设备反馈信号的联调。
- 能结合 PLC 在线值、上位机日志、SDK 返回码、当前动作阶段和现场机械状态定位问题。

避免写成“负责 PLC 编程”或“负责机械设计”。

### 激光打标项目

保留厂商 SDK 接入、P/Invoke、EZD 模板和圆弧文字、三轴运动封装、状态机与日志追溯。将相近内容合并为四至五条，减少重复。

## 数据与措辞边界

- 删除“产量约为人工两班倒 75%”，避免负面理解及统计口径争议。
- “每日约 22 小时连续运行”改为项目运行情况，不表述为个人独立成果；仅在候选人确认该事实可对外使用时保留。
- Redis 和 Linux 不作为核心能力，不主动写“仅了解”类自我降级措辞。
- 日期统一为 `YYYY.MM–YYYY.MM` 或 `YYYY.MM–至今`。

## 视觉规范

- A4 纵向，左右页边距约 1.6 cm，上下约 1.4 cm。
- 姓名 22–24 pt，正文 9.5–10.5 pt，章节标题 12–13 pt。
- 黑色正文配深蓝章节标题，使用细线或留白建立层级。
- 使用微软雅黑或等价中文无衬线字体，英文和数字保持清晰。
- 不使用照片、技能进度条、复杂图标、文本框或双栏表格。
- 确保项目要点不被分页拆散，第二页页首显示姓名和页码或简短页眉。

## 输出与验证

- 输出 `卜松浩_CSharp上位机工程师_优化版.docx`。
- 输出同名 PDF。
- 原文件不覆盖。
- 使用可用的文档和 PDF 渲染链路检查全部页面；确认无文字裁切、重叠、异常换行、字体缺失和孤立标题后再复制到桌面。
