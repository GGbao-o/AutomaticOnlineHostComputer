# 未入线任务FIFO暂停重排设计

## 目标

主页面任务列表只对尚未进入1/2号线前端缓存的总上料架任务提供顺序调整：暂停任务时从总上料架全局FIFO移除，再次启动时加入队尾。页面“顺序”列始终反映真实FIFO取板顺序。

## 范围

本设计只修改主页面任务行、总上料架全局派发FIFO及对应显示。

不改变以下行为：

- 不暂停或恢复1/2号线设备引擎。
- 不取消已经开始的机械手、货叉、前天车、后天车、动平衡或研磨动作。
- 不移动已经写入线路前端缓存、人工中转架缓存或其他现场缓存的工件。
- 不允许直接编辑顺序数字；顺序完全由FIFO计算。

## 状态模型

任务行采用以下派发状态：

1. `NotQueued`：新增未启动或已暂停，未进入总上料架FIFO。
2. `Queued`：已经启动并位于总上料架FIFO中，等待M800、线路容量和其他派发条件。
3. `Dispatching`：调度器已经原子取得该队头，正在把工件写入选定线路前端缓存。该状态不可暂停。
4. `EnteredLine`：已经成功写入1号或2号线前端缓存；人工中转架任务成功写入对应后端缓存后也进入该状态。

页面映射：

| 派发状态 | 顺序 | 按钮文字 | 按钮是否可用 | 工件状态 |
|---|---:|---|---|---|
| `NotQueued` | — | 启动 | 是 | 待执行或已暂停 |
| `Queued` | 1、2、3…… | 暂停 | 是 | 等待派发 |
| `Dispatching` | — | 派发中 | 否 | 派发中 |
| `EnteredLine` | — | 已入线 | 否 | 运行中，后续由现场进度更新 |

## 启动与暂停

### 首次启动

1. 任务行把启动请求交给`HomeViewModel`，自身不预先修改运行状态。
2. `HomeViewModel`验证任务尚未入线且不在派发中。
3. 总上料架起点任务构造完整`WorkpieceCache`并加入全局FIFO队尾。
4. 任务转为`Queued`，所有FIFO任务重新显示连续顺序。
5. 人工中转架起点任务沿用现有现场信号和缓存校验；成功写入缓存后直接转为`EnteredLine`，不显示FIFO顺序。

### 暂停未入线任务

1. 任务行把暂停请求交给`HomeViewModel`，自身不预先修改状态。
2. `HomeViewModel`在`_frontDispatchLock`内查找并移除该任务。
3. 若移除成功，任务转为`NotQueued`、显示“已暂停”和顺序“—”；其余FIFO任务保持相对顺序并重新编号。
4. 暂停只删除尚未入线的全局派发项，不删除线路缓存、现场缓存或页面任务行。

### 再次启动

已暂停任务重新构造等价的`WorkpieceCache`并加入当前FIFO队尾。它不恢复原位置，顺序取新的队尾编号，从而实现人工调序。

## 调度并发边界

`_frontDispatchQueue`仍是唯一真实顺序来源。暂停、入队、调度取得队头、派发失败回队都由`_frontDispatchLock`串行化。

调度器取得可派发队头时，在同一个锁临界区内把该项从FIFO移除并登记为当前`Dispatching`项：

- 暂停先取得锁：任务已从FIFO移除，调度器不能再取得旧项。
- 调度先取得锁：任务已进入`Dispatching`，暂停请求不得改变它。

线路缓存写入成功后，清除`Dispatching`登记、设置`AssignedLine`并转为`EnteredLine`。写入失败时，清除`Dispatching`登记、恢复`AssignedLine=0`，并按当前既有业务规则把同一工件放回FIFO队头；任务重新转为`Queued`。

取消派发循环或出现未预期异常时，不允许遗留永久`Dispatching`状态：只要线路缓存写入尚未成功返回，就把原来的同一`FrontDispatchItem`放回FIFO队头并恢复为`Queued`；线路缓存写入已经成功返回时则转为`EnteredLine`，后续异常不得回全局FIFO。两种分支都必须记录明确日志。

## 顺序显示

`TaskRowViewModel`增加只读顺序显示属性。值仅来自`_frontDispatchQueue`锁内快照，不能使用`TaskRows`集合索引推算。

每次队列变化均执行：

1. 锁内完成队列变更。
2. 锁内生成`Row → 1起始顺序`快照并增加队列版本号。
3. 释放锁。
4. 回到WPF UI线程应用最新版本快照：FIFO内任务显示数字，其他任务显示“—”。

旧版本快照到达UI线程时必须被丢弃，避免后台调度和用户点击并发时出现顺序倒退或短暂错误。

主页面在“序号”列之后增加宽度适中的“顺序”只读列。

## 一键启动与新增任务

- “一键启动”只启动`NotQueued`任务，按照当前`TaskRows`显示顺序依次加入FIFO队尾。
- 已经`Queued`、`Dispatching`或`EnteredLine`的任务跳过，不重复入队。
- 开启自动启动后，新增加的总上料架任务直接进入FIFO队尾。
- 停止自动启动只关闭后续自动入队，不改变当前FIFO。

## 清除任务

- `Queued`任务清除时继续从FIFO移除并重新编号，然后从页面移除。
- `NotQueued`任务只从页面移除。
- `Dispatching`或`EnteredLine`任务的清除仍只隐藏页面，不取消派发提交或清现场缓存；确认提示必须明确这一点。

## 日志

至少记录：

- 首次启动/再次启动入队：工件身份、新顺序、队列数量。
- 暂停移除：原顺序、移除后队列数量、重新编号结果。
- 调度取得队头：原顺序、目标线路、状态转为派发中。
- 线路缓存成功：目标线路、状态转为已入线。
- 写缓存失败回队头：失败原因、新顺序。
- 暂停请求与`Dispatching`竞态时：拒绝原因，不修改任务和缓存。

## 测试

1. A、B、C依次启动时顺序为1、2、3。
2. 暂停B后A、C顺序变为1、2，B显示“—”。
3. 再启动B后顺序为A=1、C=2、B=3。
4. 暂停队头A后C、B前移且调度器不再被暂停项阻塞。
5. 调度器先取得任务后，暂停请求不能把`Dispatching`任务改成已暂停。
6. 暂停先移除任务后，旧派发快照不能将其出队或写入线路缓存。
7. 线路缓存写入成功后按钮显示“已入线”、禁用、顺序为“—”。
8. 写入失败时同一`WorkpieceCache`回队头，身份和进度回调不丢失。
9. 一键启动和自动启动保持TaskRows顺序依次入队，不重复加入已启动任务。
10. 人工中转架起点任务不进入全局FIFO，成功后直接显示“已入线”。
11. 队列版本较旧的UI快照不能覆盖较新的顺序。
