# 研磨线路启动回原点检查实施计划

**目标：** 按用户“研磨线路也进行加上去”的要求，沿用已确认的1/2号线方案。主页面启动/恢复研磨前，读取`_cfg.Grinding.CraneNo`所指天车（当前默认5号）的D5006/5007/5008，三个值必须严格等于1；非1、读取失败、超时均弹窗拒绝。删除研磨启动及上下料派发前的旧XYZ全零检查，不新增运行中回原点监控。

**设计：** 复用`LineCraneHomingGuard`的原始Word快照、只读读取和独立5秒超时，新增单台研磨入口；不把研磨当作第3条双天车线路，也不把编号硬编码为5。保留1/2号线行为。删除不再绑定的旧全零回调及主页处理，保留其他严重异常使用的软暂停方法，注释说明其历史名称。不修改派发锁、FIFO顺序、长度/机台准入、动作版本、异常作废、PLC输出或JOG。

**技术：** C#/.NET 8、WPF、xUnit；使用apply_patch，不用Python改源码。

## 验收

`CheckGrindingAsync`只访问传入编号一次；读到三值全1即放行，XYZ=0/0/0不拦截；任一为0/2/-1拒绝。失败报告包含“研磨线路”、实际编号和D5006/7/8实际值或未知及原因。检查失败不触发生产异常作废、不清FIFO/Pending、不写PLC、不自动回原点。没有任何仍接入的XYZ全零保护妨碍研磨后续派发。现场PLC联调不作为本地软件测试已完成的事项。
