# 天车统一异常裁决器：第一批修复实施计划

> **2026-10-11现行差异提示：** 统一裁决后的catch暂存不是最终状态；六条斜床/研磨动作finally会作废本机。主页当前已移除待确认动作账本启动拦截，不能根据此历史计划要求存在该门禁。 当前规则见[业务总文档](../../全线业务逻辑详解.md)与[现场处置](../../运维/异常弹窗与现场故障处置.md)。下文为历史记录，不覆盖上述现行说明。


> 范围：仅修复前天车物理命令响应未知自动回队、天车写命令盲重试、后天车下料 X11 未确认无主页告警三项问题；不改变 PLC 地址、正常动作顺序、锁顺序或人工结案接口。

## 目标

每一次已发物理命令后的最终异常只能得出“暂停对应线体并人工确认”的结论。该结论同时驱动动作账本、引擎暂停、异常事件、主页弹窗；不得自动回队或重发同一写命令。

## 实施步骤

1. 新增可单元测试的 `FlowActionExceptionResolver`，将 `FlowActionContext` 和异常映射为 `WaitRetry` 或 `PauseLineManual`；若命令已发且结论为暂停，负责写入响应未知和人工确认快照。
2. 将两条前天车最终 catch 接入裁决器：命令未发才允许回队；命令已发但响应未知统一暂停、任务牌和主页安全回调。
3. 将两条后天车下料通用 catch 接入裁决器：X11 未确认的物理命令异常同样建立待人工快照并设置 `pendingSafetyAlarm`，从 finally 走既有主页安全回调链路。
4. 修改 `CraneService`：读 I/O 保持三次“断开—重连—重试”；寄存器/DINT 写 I/O 仅在发送前连接一次，写调用抛异常后不重发，交由动作账本裁决。
5. 主页面启动/恢复前检查该线待人工快照，未结案时拒绝恢复并提示操作员。
6. 增加单元/源码契约测试；构建、全量测试、源码复查。

## 验收准则

- `SentAwaitingEvidence` 或 `ResponseUnknown` 的动作不能产生 `WaitRetry`，且会保留快照。
- 四条前/后天车实现均使用同一裁决器。
- 前天车只有 `WaitRetry` 才 `_craneQueue.Enqueue(wp)`。
- 后天车通用异常的人工暂停一定生成 `pendingSafetyAlarm`，最终调用 `OnRearCraneSafetyAlarm`。
- `WriteRegAsync`/`WriteDintAsync` 不再调用三次重放策略；读取仍使用该策略。
- 现有及新增测试全绿，构建无错误。
