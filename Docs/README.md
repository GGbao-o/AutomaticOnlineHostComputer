## 6. 文档维护规则

1. 地址常量或bit偏移变化：先更新 `02-通信协议手册`，再同步业务主文档和前置条件表。
2. 状态机或锁顺序变化：更新对应 `03-设备交互流程`，再同步《全线业务逻辑详解》。
3. 不再创建第二份“完整全线流程”；新增内容放入现有主文档。
4. M818/M821等历史缓存键必须明确区分“软件缓存键/锁名”和“PLC信号语义”。
5. 协议文档必须分别说明“谁写/谁读、触发或保持值、复位方式、软件成功条件、物理完成确认和通信结果未知时的处理”；不得把写调用成功、缓存存在或软件锁释放写成物理动作已完成。
6. `02-通信协议手册`记录设备地址与服务行为，`03-设备交互流程`记录跨设备顺序/缓存/锁，`全线业务逻辑详解`记录整线派发与异常业务语义。三层发生冲突时，先核对地址定义、设备服务和流程引擎，再同步修正文档。
7. 日志目录、路由、时间格式、保留期或降级策略变化：同步更新《整线技术手册》《日志审查与故障定位手册》《异常处理与人工恢复操作手册》；日志文件不能作为设备物理状态或解除暂停的唯一证据。
