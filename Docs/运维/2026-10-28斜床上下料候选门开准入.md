# 1/2号线斜床上下料候选：门开信号必须等于1

> 2026-10-28已实现。门开只新增为候选及派发前候选重扫的必要条件，不增加动作内持件等门或持续门联锁。

## 1. 设备及信号

| 线路 | 斜床 | 类型 | 门开确认条件 |
|---|---|---|---|
| 1号线 | ST108、ST109、ST110、ST111 | 4台锦州Modbus | 10359原始Word严格==1 |
| 1号线 | ST112 | 1台FANUC | #1006原始宏变量严格==1.0 |
| 2号线 | ST606、ST607、ST608、ST609、ST610 | 5台FANUC | #1006原始宏变量严格==1.0 |

原值0、2、-1等均不满足门开确认；不能使用“非0即true”。原其它请求/夹紧/尾座信号的解释规则保持不变。门开与尾座张开是两个字段：Modbus10358及FANUC#1005只表示尾座张开，不能替代10359/#1006。

## 2. 读取与内存快照

锦州`ModbusSkewBedService.ReadSignalsAsync`仍一次FC03块读，范围扩为10352～10359，共8Word；前五个返回字段顺序不变，新增第六个`doorOpen`。10359缺失或读取失败进入原设备读取重试，最终失败时该床本轮信号失效。独立`IsDoorOpenAsync`也按原始10359==1判断，通用Bool函数保持非0语义。

FANUC仍使用每台设备原专属Worker，按原策略读取#1001～#1006。`FanucSignalSnapshot.DoorOpen`和`Opened`独立；读全六个信号后才发布整份快照。#1006读取失败走原Worker错误快照/断开退避，Connected=false、DoorOpen=false，不沿用旧成功许可。显式`ReadSignalsAsync`同样返回六字段，并通过原SafeCallAsync在Worker执行，不从后端/UI线程直接调用FOCAS。

两条后端的`SkewCtx.DoorOpen`只存“已确认原值为1”的布尔结果。1号线按原ST112分支读FANUC，其余四台读Modbus；2号线全部读FANUC。门开与请求/夹紧信号一起通过原PollVersion校验后提交。每轮开始、未连接而跳过读取、读失败以及原应急/异常内存复位时，门许可同步清false；这些都是内存失效，不向10359或#1006写0。

日志使用“门开确认=1/0”，表示严格判断后的布尔结果，不冒充PLC原始值。例如原值2被解释为门开未确认，不表示原始寄存器变成0。信号无效时，上料不可用详情显示“门开确认=未知”。

## 3. 候选及复核顺序

上料：中转架物理板/缓存/来源状态符合原规则，斜床同时满足`Idle + Ok + SignalFresh + RqData + DoorOpen`，再执行原版长匹配及调度。某床门关时只将它排除，另一台门开且满足条件的床仍可参与；不调整原到达顺序、Active预约或版长能力配置。

下料：先完成原CNC请求下料对应的Machining→WaitingUnload同步，核对Wp并按原规则导出job2；导出成功后才筛选门开，再判断目的地和机械手报警、生成候选。因此门关不把床改Idle、不清Wp、不清CompletionExported，也不会让job2重复导出。

拿到后天车锁后，原TryDispatchLoadAsync/TryDispatchUnloadAsync继续调用同一候选扫描，自动包含门开条件；没有另写绕过门条件的快捷派发。如果候选复核不通过，本轮不启动DoLoad/DoUnload，由原finally释放后天车锁。

这次重扫仍消费本轮已提交的信号快照，不额外实时读PLC，不保证捕获尚未被轮询到的物理关门变化。FANUC现有快照年龄策略未改；DoorOpen不能解释为动作全过程的实时门联锁。

## 4. 不满足时的情景

| 情景 | 软件处理 |
|---|---|
| 空闲床请求数据，但门未确认打开 | 本床不上料候选，继续找其他合格床 |
| 请求下料、Wp存在，但门关 | 保留WaitingUnload/Wp；job2按原规则导出；本床不下料候选 |
| 旧门开为true，随后读失败或离线 | 门许可失效；不能以旧true继续生成候选 |
| 后续轮询门开原值恢复1 | 原其它条件也满足时，重新进入候选 |
| 门开，但尾座尚未夹紧/张开 | 不替代原动作内尾座握手，仍按原流程确认 |
| 动作已经派发后门变化 | 本次没有新增持续检查或自动退磁/回零/暂停规则 |

门开条件未满足本身不新弹严重告警、不暂停线路、不清工件/缓存、不自动开门，不增加持锁等门。已有严重异常收尾、机械手报警候选检查、分流机械手D5007门禁和主页面天车启动门禁保持原流程。
