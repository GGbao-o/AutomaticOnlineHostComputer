# 1/2号线后天车下料：分流前机械手Y位置及D5007检查

> 2026-10-24。按用户指定，后天车长短板分流在既有锁内等待中增加机械手2、3各自D5007必须严格等于1的条件。本说明覆盖此前只列实际Y阈值的分流放行说明。

## 放行条件及范围

| 被检查设备 | 同一轮必须满足 |
|---|---|
| 机械手2 | 实际Y < `balancing.m2ReleaseLocksBelowY`，且D5007 == 1 |
| 机械手3 | 实际Y < `balancing.m3ReleaseLocksBelowY`，且D5007 == 1 |

两台必须同时通过；任一不满足就继续等待。不使用“非0即完成”，D5007=2、-1等值同样不放行。实际Y=0也不能代替D5007=1，实际Y恰好等于阈值仍不通过。

| 后天车路径 | 已持有的位置锁 | 本次机械手检查之前已完成的目的地复核 |
|---|---|---|
| 1号线需动平衡板 → ST019 | M817 + M720 | M817=0空闲 |
| 1号线不需动平衡短板 → ST010 | M817 + M720 | M720=1允许放料 |
| 2号线需动平衡板 → ST020 | M818 + M821 | M818=1允许放料 |
| 2号线不需动平衡短板 → ST021 | M818 + M821 | M820=1允许放料 |

需动平衡包括长度达到原长板条件或任务强制动平衡；本轮不改变分流选择。机械手2、3两台均检查，不因本次目标由其中一台后续取料就省略另一台。

## 实际执行及等待

原顺序保留：分流区外确认本后端引擎未暂停 → 按原顺序拿两把位置锁 → 锁内确认目的地允许 → 本文的两台机械手Y及D5007检查 → 进入分流区放料。

1/2号线各自的`WaitManipulatorsClearOfRackAsync`通过`ManipulatorConnectionCache`读取机械手2、3，不会误用同编号天车连接。每台每轮仍只调用一次`ReadStatusAsync`，原FC03读取D5000～D5029已包含D5007和实际Y字段；从同一个返回快照取`YPos`及`YHomeCompleted`，没有额外写信号或回原点动作。

每轮读取前把Y及D5007都置为未知。返回null或读取异常时继续等待，不能保留上一轮D5007=1而只更新Y，也不能将未知当0/1。读取和延时仍传入原动作取消令牌。

任一机械手不满足时，保持后天车持件、安全Z、原位置和已取得的两把分流锁，不移动、不退磁、不暂停、不让锁或重新抢锁。原轮询间隔为`max(grinding.signalPollIntervalMs, 200)`毫秒；没有业务超时或次数上限。停止/应急取消仍按原取消路径退出，由外层finally处理该动作的锁，不将取消吞掉变成无限等待。

本等待不同于拿分流锁之前的“本线已启动”等待，后者仍使用`grinding.lineStartWaitTimeoutMs`（默认120000ms）和原超时作废分支；本轮没有改变该流程。1号线ST010的`Crane2St010Placing`仍在本等待通过之后、XY运动之前置位，避免等待期间持续影响研磨M731。

## 报警与日志边界

原机械手D5011、D5012、D5013报警检查在生成下料候选及后天车锁后的候选复核中；本次保持不变。现有锁内等待原本只读实际Y作为放行判据，本轮仅补D5007，不新增锁内持续报警监控。因此不能把本文两个条件解释为“运行中任何新报警都会被本等待重新拦截”。

进入等待时打印两台目标条件；首个未通过轮询及之后每10轮打印实际Y、D5007和未知/读取失败。通过时打印两台实际Y和D5007。例如假设两个Y阈值均为2000：

```text
│   [分流等待] 机械手2 Y=0(需<2000) D5007=0(需=1) 机械手3 Y=1000(需<2000) D5007=1(需=1)，继续等待；保持持件和位置锁
│   机械手2 Y=0(<2000) D5007=1、机械手3 Y=1000(<2000) D5007=1 均满足分流条件 ✓
```

2000仅为日志示例，不是新增配置默认值。复用原两个阈值，本轮不增加JSON或配置页面字段。
