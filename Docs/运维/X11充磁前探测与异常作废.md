# X11充磁前探测与严重动作异常作废

更新时间：2026-10-11。本文描述本次实现后的自动生产流程。现场已确认X11在放磁状态可以感应板；本次仅做软件验证，未连接生产PLC联调。

## 1. 适用入口

| 设备 | 引擎 | 取板位置 |
|---|---|---|
| 机械手1（两线共享） | Line1FrontFlowEngine、Line2FrontFlowEngine | ST007总上料架 |
| 前天车1 | Line1FrontFlowEngine | ST713货叉Pos3、ST107打号机取回 |
| 前天车3 | Line2FrontFlowEngine | ST714货叉Pos3、ST502打号机取回 |
| 后天车2 | Line1RearFlowEngine | ST105/ST101/ST106中转架、对应斜床下料 |
| 后天车4 | Line2RearFlowEngine | ST016/ST017/ST018中转架、对应斜床下料 |
| 研磨天车5 | GrindingFlowEngine | ST709研磨上料架、研磨机下料 |
| 机械手2 | BalancingFlowEngine | ST019/M817或ST020/M818 |
| 机械手3 | BalancingFlowEngine | ST021/M821或乱序上料M700 |

共14处调用共用的`PickupProbeHelper`；机械手2/3有多个来源，分别在各自的来源选择之后共用一个取板入口。手动页单独充磁/退磁、未接入主页的ProductionFlowEngine不采用自动下探。

## 2. 正常取板顺序

1. 保留原来的连接、工件、长度、门、目的位、锁和取料前残留检查。残留检查读取X11=0的位置是接近来源之前；到板面以后X11=1是正常的来源板探测结果。
2. 在首次取料下降前直接读X6、X7，必须成功确认X6=0、X7=1。未知或反馈不符立即失败，不为继续取板自动退磁。
3. 执行本入口原来的首次Z运动（机械手1使用原XYZ动作），读取并确认实际Z停稳。原数据库/直径/偏移公式只应用于首次目标；停稳读数记为Z0。
4. 等待本动作启动时快照的`grinding.x11StableDelayMs`，读取第一次X11。成功读到0才进入下一位置。
5. 补偿前读X2，压住则拒绝；读取实际Z并核对本次下探上界。第2/3位置指令分别为Z0+5、Z0+10。各次实际到位后再等稳定时间并读X11。
6. 任一位置X11=1：停止下探，调用一次业务充磁流程，等待其X6反馈确认；再独立等待稳定时间并读取充磁后的X11。
7. 只有充磁成功且充磁后X11=1才登记`OnCarrier`，继续原来的Z回升、来源消费、PLC取走通知及搬运握手。

| 位置 | 指令基准 | X11=0 | X11=1 |
|---|---|---|---|
| 第1位置 | 原首次取料目标，实际停稳Z0 | 检查后下探5mm | 充磁并确认持件 |
| 第2位置 | Z0+5mm | 检查后再下探5mm | 充磁并确认持件 |
| 第3位置 | Z0+10mm | 严重取板失败 | 充磁并确认持件 |

三个位置最多额外下探10mm；没有第4位置。充磁后的X11是额外一次持件确认，不算第4次探测。探测阶段不执行旧的“退磁、下探、再次充磁”循环。

### 2.1 到位、下压和偏移

补偿运动单独使用±1mm到位容差、10秒运动超时；共用组件再次核对实际Z，在10秒内取得两次间隔100ms、Z一致且满足目标容差的读数。不会因为全局默认±5mm容差而在未实际下降时提前读取X11。全局正常运动容差、原XY微调和首次下降规则保留。

以实际Z0作基准。例如首次名义目标110但正常接触后实际停在97，补偿目标为102、107，不是115、120，也不重复加数据库Z偏移。实际Z超过Z0+10或到位验证超时会尝试D4518停止并严重失败；停止响应失败单独记为未知。指令上限不能当作机械绝无超调的保证。

正常接触触发X2后，原服务可能按既有15mm正常接触容差成功返回；先读X11，有板便充磁。若无板且下次补偿前X2仍压住，禁止继续向下压。该15mm与ST007板长校验容差是不同配置项。

### 2.2 探测与持件证据

充磁前X11=1只证明探测到来源板：来源账本尚未消费，动作所有权仍在来源，监控不能标成已持件。充磁成功返回也不能独自证明吸到板。充磁后X11=0或读取失败立即失败，不再下探、不自动退磁、不提交来源取走。

共用组件只控制取板物理时序，不删队列、不写机床完成信号、不暂停引擎、不释放业务锁。各引擎负责异常策略及成功后的原交接顺序。研磨调用不再用外层`CraneOpAsync`重做整段取板/放料业务。底层通信及磁铁服务的原反馈尝试仍存在，因此“一次业务充磁”不表示底层协议只写一次。

## 3. 严重异常与正常等待

下列已分配动作失败统一暂停所属引擎、详细弹窗、作废本次软件任务：三个位置无板、X11/坐标/磁铁反馈读取失败、无法确认放磁、补偿被X2阻止、运动超时/非正常下压、充磁失败/响应未知、充磁后无板、动作内微调最终失败、持件搬运/放料/机床握手严重失败。研磨ST709的普通编码器读取不稳定或微调超差现在也属于此类，不能因`magnetOn=false`回FIFO。

目标暂时不允许、区域锁忙、无适合长度机床、TypeA取板前切单机/磨石报警等明确准入等待保留。TypeA准入退回可把同一板放回队头；旁路显示屏写入失败仍只记录。普通手动Pause/Resume、应急取消旧版本、未派发动作的后台状态扫描和独立FIFO超限不自动作废所有板。

事故收尾通常先暂停并显示“正在清理”，冻结原始工件/失败步骤，随后等待已启动的运动、参数及通知任务实际退出，清理本动作所属状态，删除本动作人工续搬入口，更新弹窗最终结果，按原租约/版本释放锁。软件暂停不是PLC急停，已经运行的另一趟动作不因暂停位自动停止。

## 4. 各入口清理范围

| 范围 | 本次严重异常作废 | 保护对象 |
|---|---|---|
| 机械手1交接前 | 匹配`_currentWp`及完整板号+序号来源残留，不回队；仍属本轮且无货叉握手执行时，尝试清M911～M914及R6102/R6104/R6108，相关前端阶段Idle/门闩关闭 | 另一线、其他缓存、前天车队列和已放行下游 |
| 前天车Pos3/打号/中转搬运 | 本趟任务牌、人工续搬快照、匹配队列残留；不重新入队 | 下一块`_currentWp`、独立运行的货叉/双头镗、已写入下游的缓存 |
| 后天车上斜床 | 本床参数/输出、Wp、请求快照等清理，回Idle；尚未消费的本次来源预约/缓存按动作号+到达代次+完整身份原子作废 | 其他床、其他来源、新到达同架位、已成功交付下游 |
| 后天车下斜床 | 本床参数/输出及Wp清理，Idle，本次任务牌及人工续搬入口删除 | 中转架其他任务，已交接动平衡/研磨缓存及通知 |
| 研磨上料 | 本板不回FIFO，只删除完整身份匹配残留；本目标机参数/输出清理、Pending清、Idle | 下一块FIFO、其他机台、已经交接的任务 |
| 研磨下料 | 本机参数/输出清理、Pending清、Idle，本次动作结案 | 后续ST709任务、ST710实物、MC64完成位 |
| 机械手2/3 | 本版本在途、展示、Busy及人工续搬记录清理；未消费来源按动作版本+来源代次+完整身份删除 | 提前放锁后新写入同键的板、另一机械手、已交接FIFO |

M700乱序来源没有可核对的完整板身份/缓存代次，不用“未知板”匹配删除M821或其他来源。动平衡没有机床Idle枚举，其空闲指本版本动作退出、Busy解除、对应在途/显示记录清空。

### 4.1 上位机下发清理地址

| 设备 | 尝试清零范围 |
|---|---|
| 锦州Modbus斜床 | 10300～10305、10370～10374 |
| FANUC斜床 | #800/#801/#802/#909/#1101～#1105 |
| TypeA研磨机 | 40011输出整字、40012～40014参数 |
| TypeB研磨机 | R7311～R7318 |
| 本轮机械手1前端 | 在归属守卫成立时，M911～M914、R6102/R6104/R6108 |
| 动平衡失败输出 | 仅已开始写但未成功返回的本动作M824/M826/M701/M711/M721，归属成立才按位清零 |

动平衡成功返回的通知不回滚；未发送不写0；源区域已放锁或动作版本改变时跳过相应位。按位操作保留同字其它位，仍受MC整字读改写与PLC扫描竞争的既有限制。研磨天车MC65 M731、MC64 M721不由本机清理回滚。

设备清理独立于原动作取消令牌，斜床/研磨/前端用10秒清理令牌，动平衡单项5秒；实际await写任务退出后才继续释放原锁，不用超时返回把写任务留在后台。多寄存器写非原子且无统一读回核验；失败/部分残留如实显示。设备清零失败时本次内存任务仍清、引擎保持暂停。软件Idle不表示请求数据被写成1，也不证明实体设备已复位。

### 4.2 已交接与空载回位

机械手1板已完整交叉并成功M801/门闩后，空载回待机失败保留货叉和板，清本次空载动作；位置未知会暂停两线新派发。在已确认任一安全Y端点的原警告分支保持继续，不升级为严重作废。

前天车成功放中转架并完成缓存交付后，末尾空载归位异常清本趟动作，保留下游板。动平衡来源早放锁后出现异常不删除新来源；已经成功写研磨FIFO也不回滚。斜床主动作已经Completed后finally侧退避才失败，床仍可能Machining/Wp存在，告警只代表空载退出有问题；不能套用“所有弹窗必清所有板”。

## 5. 弹窗与现场恢复

8台载具本次动作都使用统一详情：所属线路/独立引擎、设备编号、来源目标、完整板身份和尺寸、失败步骤、目标与最后坐标、探测位置/X11/磁铁历史、异常堆栈、最终设备/缓存/内存/锁收尾。机械手使用机械手连接信息独立读取，不能误读同号天车；M700没有可靠来源线号时显示未知。

现场采样用独立短连接，只读D5000～D5029及X2/X6/X7/X11，预算2秒，读取失败显示未知；各字段可能来自不同时刻。刷新不覆盖原事故历史，不发送运动/磁铁，不恢复线路。

恢复步骤：保持暂停并等弹窗收尾结束；核对本次失败板及已交接下游的区别；人工移走应丢弃的板，确认载具安全位置和实际放磁，核对机床夹紧/请求及参数残留；确认其他承载面和缓存身份相符后恢复对应引擎。后天车/机械手1/前天车所属1/2号线，动平衡和研磨独立恢复。Idle、请求数据=1仍需来源实体与软件身份、长度、联机/连接/新鲜度、门和锁等准入条件。

已经自动删除本板来源时，不再删下一块ST709队头或新到达中转架。板在打号机/机床/料架上，X11=0不能证明承载面空。已作废板不能靠重启恢复旧身份；若仍需制造该任务须重新导入。ST007拒板后仍需真实观察M800=0再放下一板。
