# 2026-10-14 前后天车X持锁准入

## 1. 目的与已确认策略

区域锁释放不代表对方天车已经退到允许进入的位置。现有前天车中转架交接后先释放ZoneMT/ZoneTS，再回X；后天车取板并升安全Z后也会先释放ZoneMT，再向斜床移动。本次在指定入口增加对方实际X检查。

按用户确认采用**持锁无限等待**，不是释放锁重试。成功读到但位置不满足不属于异常，不暂停、不弹窗、不作废本板。等待期间不发运动、充磁、放磁指令；人工判断并移动对方天车，实际X满足后继续原任务。

| 当前天车 | 读取对方 | 默认放行条件 | 检查入口 | 等待时持有的区域锁 |
|---|---|---|---|---|
| 1号（1号线前天车） | 2号实际X | X >= -14000mm | 原空位及暂停判断完成后，打号流程之前 | ZoneMT |
| 2号（1号线后天车） | 1号实际X | X <= 2500mm | 上料拿齐ZoneMT/ZoneTS后，原来源及目标机复核之前 | ZoneMT+ZoneTS |
| 3号（2号线前天车） | 4号实际X | X >= -14000mm | 原空位及暂停判断完成后，打号流程之前 | ZoneMT |
| 4号（2号线后天车） | 3号实际X | X <= 2500mm | 上料拿齐ZoneMT/ZoneTS后，原来源及目标机复核之前 | ZoneMT+ZoneTS |

总动作锁、后端预约和设备动作租约也仍按原流程保留。本次没有改变它们的持有和释放规则。

## 2. 配置文件与页面

`Config/motion_settings.json`新增独立配置节：

```json
"cranePeerXAdmission": {
  "crane1MinCrane2X": -14000,
  "crane2MaxCrane1X": 2500,
  "crane3MinCrane4X": -14000,
  "crane4MaxCrane3X": 2500
}
```

四项互相独立。模型默认值与上表一致，旧文件缺少整个配置节或缺少其中字段时使用模型默认。配置值为有符号整数，允许负数和0，均不是禁用哨兵；比较包含等号。

页面入口为**配置页面 → 其他 → 前后天车X放行条件(mm)**，位于“天车归位X”下面。四行直接显示“1号等2号 X ≥”“2号等1号 X ≤”“3号等4号 X ≥”“4号等3号 X ≤”。

页面绑定提交后更新引擎共享的MotionConfig对象；阈值使用volatile字段，在每次读取坐标后重新获取。因此页面编辑可以影响已经在等待的动作下一轮判断，不是整趟动作固定阈值。点击原有“保存”按钮后沿用MotionConfig.Save写入程序运行目录的配置文件。只编辑不保存，重启会丢失；外部修改磁盘JSON不热加载。保存沿用原有全配置保存行为，不是只写这四项。

这些阈值不是天车归位坐标，也不是ST108/ST606退避距离。实际X直接采用ReadStatusAsync返回的XPos，由D5018低字/D5019高字解码；不使用XEncoderAbs，不叠加设备偏移或退避距离。

## 3. 等待、取消与异常

每个入口立即读取一次对方X。满足条件则继续；不满足则异步Task.Delay(500, ct)，然后重新读坐标和阈值。没有业务超时和探测次数上限。500ms是两次读取之间的延时，实际一轮还包含PLC通信耗时。

示例：1号已经取得ZoneMT，2号X=-15000，默认不放行，保持ZoneMT等待。人工将2号移到-14000或更大，下一次成功读取后1号进入原打号流程。2号上料等待1号时，1号X=3000不放行，移到2500或更小才继续；3/4号同理。

组件复用对方天车连接，未连接时沿用服务ConnectAsync建立连接。读取返回null或抛通信异常时禁止放行，不把未知当作0、不使用上次坐标，异常交给调用位置原有catch/finally处理。该异常属于原异常收尾，不是正常的位置等待。

停止/取消仍响应原CancellationToken；后端同时沿用operation.ThrowIfInvalid，在读取前后检查动作租约，应急作废的旧动作不能放行。组件不自行释放锁、清板、改Idle或写PLC输出；这些仍由原引擎根据动作阶段和归属处理。正常位置等待保留锁不代表停止/取消/异常后也永远不释放。

第一次不满足、之后每20轮等待及满足时输出日志，避免每500ms刷屏。例如：

```text
[天车X准入] 1号读取2号：实际X=-15000mm，条件X>=-14000mm，未满足，保持区域锁无限等待
[天车X准入] 1号读取2号：实际X=-14000mm，条件X>=-14000mm，已满足，继续本趟任务
```

## 4. 实现位置与范围

- `Infrastructure/Config/MotionConfig.cs`：CranePeerXAdmissionSection，四个阈值及默认值。
- `Service/FlowEngine/CranePeerXGate.cs`：只读坐标轮询、即时阈值读取、日志、取消及未知坐标拒绝放行。
- `Service/FlowEngine/Line1FrontFlowEngine.cs`、`Line2FrontFlowEngine.cs`：打号前分别接1→2、3→4。
- `Service/FlowEngine/Line1RearFlowEngine.cs`、`Line2RearFlowEngine.cs`：上料拿齐锁后分别接2→1、4→3。
- `Presentation/ViewModels/Config/ConfigPageViewModel.cs`、`Views/Config/ConfigPageView.xaml`：配置输入及共享属性绑定。
- `AutomaticOnlineHostComputer.Tests/FlowEngine/CranePeerXGateTests.cs`：等待核心、配置及四入口回归验证。

只增加这四处入口，不增加后天车下料、前天车打号后拿ZoneTS等位置的X检查，不涉及天车5或机械手。原有空位检查、暂停等待、来源预约复核、设备握手、取板探测、退避和异常收尾顺序均保留。

普通暂停对在途动作的语义继续沿用原实现；本组件没有增加新的暂停判断或取消规则。单次入口的X条件成立也不表示后续所有位置或机械状态已经逐项验证。
