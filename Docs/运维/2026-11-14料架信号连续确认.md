# 料架信号连续确认

在配置页「其他 → 料架信号连续确认」可调整次数和间隔。保存对应 `motion_settings.json` 中的 `rackSignalConfirmation.consecutiveReads`（默认3，范围1～20）及 `rackSignalConfirmation.sampleIntervalMs`（默认100ms，范围20～5000ms）。后台候选沿原轮询周期取新样本，间隔为计数下限。动作内至少按配置间隔采样，默认首次读对后约再等200ms及通信耗时。

| 阶段 | 放行信号 | 复核及等待 |
| --- | --- | --- |
| 前天车放中转架 | 1号线MC63 M811～M813对应ST105、ST101、ST106；2号线M814～M816对应ST016、ST017、ST018。同一架位连续为0 | 打号前锁外等，拿ZoneMT后重采一组，未确认则释放ZoneMT再等。打号后用新采样选实际位置。若三架持续全满，走原异常及释放区域锁流程 |
| 后天车由中转架给斜床上料 | 同一来源连续为1，且软件缓存有效 | 候选只计前端后台采得的新样本。拿齐ZoneMT、ZoneTS后直接读MC63复核，未确认则保留缓存、解除预约、斜床回Idle并释放锁 |
| 后天车从斜床下料 | ST019 为MC63 M817=0，ST010 为MC65 M720=1，ST020 为MC63 M818=1，ST021 为MC63 M820=1 | 不足次数时该目标不产生候选。实际动作按原策略持件、安全Z、持分流锁等待，机械手退出后再确认一组，随后才发XY |
| 研磨下料到ST710 | MC64 M720=1 | 候选每轮只采一次。已持件、安全Z和X11通过后，从零开始重采，等待连续通过才去ST710 |

一次MC63块读包含多个架位，但每个架位单独计数。同一个快照的多次使用不重复计数。反值、读取失败或无效报文切断连续确认。候选读取失败跳过该目标。前天车打号前的首次锁外预检读失败时，保留持件，在锁外等后台恢复连接；拿锁后、释放ZoneMT后的复核或打号后读失败沿用原动作异常处理。未开始取板的后端复核失败按正常退出处理，已持件分流和研磨下料遇到有效反值继续等待，通信失败走原异常收尾。

日志示例 `[料架确认] ST710/MC64 M720 持件安全Z下料复核 第2次 实读=1 要求=1 连续=2/3 等待=105ms`。反值会显示计数清零，长期无变化时日志按采样次数限频。对照实际现场信号可区分抖动和持续占用。

## 通信排队与超时

两条线前后端通过 `McConnectionCache` 复用 MC63（192.168.2.63:9000）。缓存按 IP 和端口串行建立连接，通信客户端按连接实例串行发送请求和接收应答。MC64、MC65 使用各自的连接和通信锁。每次读完或读失败即释放本次通信锁，采样之间异步等待，期间同一 PLC 可以处理其他请求，界面也可以正常操作。

同一连接上的慢请求可能让其他请求排队。前天车的中转架位读设置 5 秒上限，后天车锁后取料、分流点位和研磨 ST710 的单次读取设置 3 秒上限，这些调用的限时也覆盖对应的通信锁等待。只有完整的成功报文才能累计。超时、断线和缺字都属于未知，不能把它们补成 `0` 计为空位。例如 `0、0、超时` 后恢复读取，重连后的第一个 `0` 从第 1 次开始计。

ZoneMT、ZoneTS、分流位置锁和天车动作锁控制设备能否进入现场区域。持件等待时按各路径保留相应的动作锁，其他设备仍能读写共享 PLC。采样间隔是单次连续确认的读数间隔，动作总等待时间还取决于现场位值、通信耗时及动作原有的锁策略。
