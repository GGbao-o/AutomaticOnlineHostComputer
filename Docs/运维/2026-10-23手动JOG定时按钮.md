# 手动JOG定时按钮

> 2026-10-23。仅新增手动操作，不接入线路、工件、机床调度、业务区域锁或生产异常处理。所有FlowEngine源码与修改前保持一致。

## 1. 页面与地址

“手动操作页面→设备操作”保留原12个按钮，下方新增3列2行：第一行JOG X+、Y+、Z+，第二行JOG X−、Y−、Z−。单击执行一趟，不要求按住按钮或再点击停止；机械手没有X轴，X按钮禁用，命令层也拒绝机械手X指令。

| 按钮 | PLC线圈 | Modbus十进制地址 | 十六进制 |
|---|---|---:|---|
| JOG X+ | M70 | 70 | 0x0046 |
| JOG X− | M71 | 71 | 0x0047 |
| JOG Y+ | M72 | 72 | 0x0048 |
| JOG Y− | M73 | 73 | 0x0049 |
| JOG Z+ | M74 | 74 | 0x004A |
| JOG Z− | M75 | 75 | 0x004B |

用FC05写单线圈：true编码FF00，false编码0000；用FC01回读确认。不能用FC06写D70～D75代替。本次无需FC0F，也不使用D4519间接触发。

## 2. 可配置持续时间

```json
"manualControl": {
  "jogPulseDurationMs": 1000
}
```

默认1000ms。配置页面“其他→手动JOG→持续时间”编辑共享MotionConfig，点击原保存按钮持久化到程序运行目录Config/motion_settings.json。旧JSON缺少配置节/字段时默认1000；外部直接编辑JSON不热加载。

每次点击固定本次时长，中途改配置只影响下一次。必须为正整数，0或负值在设备模式/线圈IO之前拒绝，不回退为另一时长。新JOG不沿用旧手动按钮5秒整趟超时，配置大于5秒仍按该时长等待；设备每次IO仍有超时。保持时间从写1成功返回后计，真实复位时点还包括通信耗时，不是PLC硬实时定时器。

本次不写D2507～D2509、D2516～D2518、D2525～D2527的JOG速度/加减速，使用PLC现场既有JOG参数。

## 3. 正常过程和互斥

1. 固定点击时选择的设备、缓存服务实例、方向线圈及配置时长。
2. 六个新JOG共用一个非排队互斥。已有JOG进行中，新按钮禁用，命令层也拒绝第二次请求，不排队补发。
3. 沿用手动模式准备D4001=2、D4500=2；已确认模式时遵守原服务缓存规则。
4. 对对应M线圈写1一次，检查FC05功能码、地址、值回显。
5. 异步等待本次配置时长。
6. finally对原设备、原线圈写0，然后FC01严格回读；读到0才报告完成。

切换设备或切换页面不会把旧动作OFF改写到新设备；命令持有原服务直到收尾完成。现有减速停止、急停等按钮没有因新增JOG互斥被禁用。这个互斥只约束六个新按钮，不改变原按钮或自动线路的并发规则。

## 4. 异常与复位

写1尝试放在try/finally内，写1返回异常、超时或取消时也执行OFF，因为PLC可能已经收到ON。ON只发送一次，不因响应未知重复启动；等待异常/取消同样进入finally。

OFF不使用原操作令牌，每次建立独立5秒清理令牌，最多3次“写0+回读”。写0异常、回读异常、回读仍为1都不算完成；允许重试幂等OFF，不重发ON。FC05回显不一致或FC01功能码/字节数/长度不合法都明确失败，不能解释为复位成功。

若ON或等待失败，但OFF已确认，页面显示原操作未完成，原异常保留。若OFF最终未确认，显示“JOG复位未确认”；同时保留原ON/等待异常作为证据。页面记住原设备/原线圈，此后点击任一可用JOG**只重试原线圈OFF+回读，不启动新动作**。复位成功后提示再次点击才可执行新JOG；设备下拉框切换不会改变这个待复位目标。

参数无效、已取消且尚未尝试ON、模式准备失败等前置拒绝不发送新的ON，不因此产生一个新的脉冲收尾任务。JOG复位确认只表示线圈回读为0，不是坐标或机械停止位置校验。

按用户确认，本次不增加断网/断电/强杀下的PLC看门狗、通信故障自动暂停线路或其他生产联锁，也不改PLC程序。
