## 2. 从catch到窗口的实际调用链

1. 原动作方法建立FlowAlarmPresentationContext，复制版号、序号、长度、直径、孔型。
2. 最终catch用RecordFailure保存第一次失败异常及动作快照；后天车/研磨有多类catch，原分支与回调时机不变。
3. 原安全回调进入HomeViewModel.HandleLineSafetyAlarm或HandleStandaloneSafetyAlarm；先同步暂停原来应暂停的派发门，再安排UI显示。
4. 当前异步链有展示上下文则TryShowDetailedSafetyAlarm；没有上下文或创建窗口失败则回落原MessageBox。只改展示，不重新裁决工件、不取消旧动作。
5. finally里的原设备作废与租约释放继续执行；RecordCleanup/只读收尾探针通过Changed更新已打开窗口。
6. 前天车内层退出时外层调度锁尚未释放，显示“等待调度层释放”；原_craneFrontLock.Release成功后RecordReleased更新最终结果；没有成功记录则显示未知/请核对。

详情按ActionId去重；窗口关闭后同一历史动作不立即重开，历史去重记录最多256条，超出旧记录会移除。旧式提示仍遵守原停机周期去重。详情关闭不会结案或恢复。

## 3. 布局各区域的含义

| 区域 | 内容 | 证据时点/局限 |
|---|---|---|
| 标题 | 线路、几号天车、动作名称 | 该次动作身份 |
| 异常原因与执行步骤 | 原异常原因、失败步骤、最后业务步骤/最后成功步骤、动作号与发生时间 | 首次最终失败冻结；文件步骤可单独显示，不改业务Step |
| 工件与流向 | 当前阶段、版号、序号、长度/直径mm、孔型、来源目标站号及名称 | 初始工件复制值；缺失显示未知；前天车按阶段覆盖展示流向 |
| 故障时记录 | 最后登记运动目标、最后确认XYZ、业务X11/充磁、所有权和命令状态 | 历史证据，不是当前反馈；文件失败的运动坐标可能是上一条命令 |
| 现场状态 | X6/X7/X11/X2、显示XYZ、AbsXYZ、D5029及故障/报警字、采样时间/错误 | 异常后独立读取；不能当作故障瞬间数据 |
| 最终收尾 | PLC参数/输出清理、内存、来源/下游缓存、软件锁及完成时间 | 原流程实际返回或登记结果；固定告警文案不覆盖清零失败 |
| 完整异常（可展开） | Exception.ToString及原告警报告 | 保留内部异常与堆栈，便于定位；历史固定文案需结合最终结果 |

前天车阶段来源示例：货叉取料为ST713/ST714→ST107/ST502；打号文件握手为打号位→打号位；取回为打号位→中转架（尚未选择）；选定架位后才显示ST105/101/106或ST016/017/018。缓存交接与空载归位单独显示。不能一直把打号取回的来源写成最初货叉。

## 4. 刷新到底读什么

CraneAlarmSnapshotReader创建独立短连接，不共用生产CraneService；总预算2秒，关闭窗口会取消采样。读取D5000起30字，以及FC01线圈X6=63494、X7=63495、X11=63497、X2=63490。X11按八进制编号换算；不能读63499。

X来自D5018/5019、Y来自D5022、Z来自D5025；AbsX来自D5014/5015、AbsY来自D5020（有符号INT16）、AbsZ来自D5023。还显示D5009故障、D5010运行条件缺失、D5011/12/13报警及D5029持板字。

各输入独立读取，不保证同一瞬间。位置失败不伪造零；某个X点失败不抹掉其它成功结果。首次自动采样与“刷新现场状态”均只更新现场区域；故障身份/原因/步骤不跟着刷新改变。复制复制当前整份详情；关闭只关闭窗口、取消读取，不控制设备。

## 5. 具体异常情景与最终状态

| 情景 | 方法退出后软件情况 | 现场与恢复要点 |
|---|---|---|
| 机械手1取板/送叉交接未闭环异常暂停 | 本块任务作废，不回本线缓存；清匹配current及完整板号+序号来源残留，保留其他任务 | 人工移走本板，确认机械手/货叉安全和退磁再恢复；软件清理不能证明板位置 |
| 机械手1已放行货叉后回待机位置未知 | 原共享安全保护暂停两线，已交接货叉/下游状态保持 | 不能套用ST007未取料作废；按货叉实际阶段和前端应急处理 |
| 研磨ST709下降/取板、持件或放机后异常暂停 | 本板不回FIFO；按完整身份删本板残留，目标机参数/输出尽力清，Pending清、Idle | 等旧动作退出，移走本板并确认天车安全；已自动删本板时不要再清下一块ST709队头 |
| ST709取料前普通编码器读取不稳/微调超差 | 本次动作退出，A回队头；不主动暂停、不安全弹窗；记录异常监控，条件满足可能重新派发 | 本次修复保留此行为；若人工丢弃原板，应先暂停并核对清理旧FIFO身份 |
| 机械手1在ST007发现板长差>容差 | _currentWp清空，同身份缓存残留清理，不回队；本线暂停；原板长提示 | 机械手未移动/充磁，板仍ST007。拿走旧板，等日志观察M800=0，再上新板/重新导入任务 |
| 前天车Pos3取料运动超时、充磁/X11失败 | 原阶段人工快照/任务牌保留；不按六流程作废清货叉或双头镗 | 核对Pos3、磁铁、XYZ；处理旧板后恢复，下一块货叉状态不能随意清Idle |
| 前天车打号B文件1小时未生成 | 本线前后端暂停，保留旧板身份；ZoneMT按原finally释放 | 板可能在打号位，X11=0不表示打号位没有板；处理文件残留与实物，不凭文件回执认定取回 |
| 前天车中转架退磁成功但缓存通知失败 | 不回Pos3队列；显示真实架位和通知未确认；前天车仍保留人工状态 | 清来源床无意义；现场核对架位、旧缓存/新身份，必要时目标结案 |
| 后天车上斜床异常发生在CommitPickup前 | 目标床最终Idle/Wp=null；来源缓存/冻结可能保留 | 板仍来源则来源结案“仍在来源”；移走则“已人工移走”。只启动会跳过冻结架位 |
| 后天车上斜床已持件、已放床或已发启动后失败，尚未Completed | 目标床参数/输出尽力清，Wp清、Idle；匹配上料持件/目标待交接注册快照清理 | 实体板必须从真实所在位置处理，CNC收到启动并不等于后续失败不作废 |
| 后天车下料分流前本线暂停超过上限 | 专用catch及未Completed finally作废床；天车可能仍持板 | 放磁处理实物；门禁只看_paused，重新启动不替代安全位置/目标允许复核 |
| ST108/ST606上料已Completed，finally退避失败 | 可新增暂停告警，但床仍Machining/Wp存在：作废判断先于退避，已跳过 | 查实际收尾与床状态，固定“已自动作废”尾句不证明清理；先处理天车安全，不盲清正在加工板 |
| 后天车已放下游但缓存/完成位失败 | 来源床最终Idle/Wp清；下游缓存不回滚；目标待交接快照可能保留 | 核对ST019/010/020/021及M819/821/721/FIFO部分结果；不假定整链数据已清 |
| 研磨上料准备XY/参数/微调失败 | 内层日志可能Pending保留；最终未Completed finally清Pending并Idle | 内层保留不等于最终保留；实际持板不能回FIFO补一份身份 |
| 研磨下料ST710已放但M721/完成/Z归位失败 | 本研磨机作废Idle/Pending清；ST710与MC64不清 | 人工确认ST710无残留及下游身份；X11互锁不能检测板架残留 |
| 研磨独立状态观察超时/FIFO超限 | 可暂停但保留状态/FIFO，未必执行动作finally | 看告警来源，不能套用“任何暂停已清Idle” |
| 动平衡机械手2/3异常 | 原Busy/在途身份/快照策略保持 | 原应急/结案按实际位置处理；本次详情优化未扩展它们 |

六动作清理的准确快照筛选与不清对象见[主文档第15节](../全线业务逻辑详解.md)。清零写失败后软件仍可能已经Idle；最初显示“等待收尾”也不能认定清理失败或已成功。

## 6. 重新启动的真实边界

当前主页启动1/2号线只调用坐标连续全零保护，**不调用EnsureNoPendingManualActionsForLine**。该方法虽存在，但不是有效门禁。Resume只打开暂停位，不清工件、队列、预约、PLC或锁。

因此“按钮允许启动”不等于“所有事故已经处理”。六动作放弃工件并收尾后，可在现场安全与数据条件恢复后启动对应引擎重新派发。研磨要点研磨独立启动；机械手1交接前异常暂停已作废本板，交接后独立回位保护、前天车、来源冻结和已交接下游缓存仍按原规则。请求数据=1还需Idle、信号新鲜、来源实体与缓存匹配、可加工长度等其它条件。
