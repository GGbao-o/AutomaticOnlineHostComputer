# 异常弹窗、调用入口与现场故障处置

更新时间：2026-10-12。已同步先探测X11再充磁、可配置位置数/补偿步长及严重动作作废实现。完整算法和清理归属见[X11充磁前探测与异常作废](X11充磁前探测与异常作废.md)。软件验证未连接生产设备。

## 1. 统一详情覆盖

| 动作 | 设备 | 调用入口 |
|---|---|---|
| 两线ST007取板/送叉、板长异常 | 共享机械手1 | Line1/2Front.ProcessManipulatorPickupAsync异常catch及已交叉空载回位保护 |
| 两线Pos3/打号/中转搬运 | 天车1/3 | Line1/2Front.ProcessCraneFrontAsync及其内层区域catch |
| 两线斜床上/下料 | 天车2/4 | Line1/2Rear.DoLoad/DoUnload严重catch和finally最终安全回调 |
| 研磨ST709上料/研磨机下料 | 天车5 | Grinding.ProcessWorkpieceAsync/UnloadFromGrinderAsync严重catch及finally更新 |
| 动平衡取板/搬运/放料 | 机械手2/3 | Balancing.RunM2Async/RunM3Async当前动作异常catch及finally |

货叉独立状态机故障、无动作上下文的独立扫描/FIFO告警等仍按原提示/窗口。1/2号线及研磨旧XYZ全零检查已于2026-10-23删除。不是每个内部catch都弹严重窗口：成功恢复的读取重试、旁路显示屏失败、准入条件暂时不满足保持原策略。本次ST709普通微调/动作通信错误已升级为严重暂停作废。

2026-10-23新增1/2号线启动/恢复前双天车回原点检查：本线两台D5006/5007/5008必须六值全==1；研磨后续同步接入，要求配置天车（默认5号）三个值全==1。任一非1或读失败/超时都显示完整实际值/错误并拒绝启动。该弹窗不属于搬运严重异常，不清当前工件、FIFO、Pending、锁或设备参数，也不自动执行回原点。规则和原XYZ保护删除范围见[线路启动回原点状态检查](2026-10-23线路启动回原点状态检查.md)。

Home收到安全回调暂停所属引擎并取得FlowAlarmPresentationContext快照；机械手详情识别ManipulatorNo，用机械手数据库连接；天车用天车缓存连接。机械手2来源ST019关联1号线、ST020关联2号线，机械手3ST021关联2号线，M700缺乏可靠来源线号显示未知。不会拿机械手2编号去读天车2。

## 2. 窗口信息与三个时间

| 区域 | 内容 | 含义 |
|---|---|---|
| 标题/异常 | 线路或独立引擎、载具编号、动作号、时间、原因、失败步骤与最后成功步骤 | 故障冻结事实 |
| 工件/流向 | 版号、序号、长度、直径、孔型、来源/目标及当前搬运阶段 | 清内存前复制，未知不编造 |
| 业务记录 | 最后目标与确认XYZ、X11/磁铁、所有权、命令发送/响应状态 | 事故历史，非当前反馈 |
| 现场读取 | X2/X6/X7/X11、显示XYZ、AbsXYZ、D5029及报警字、采样时间与错误 | 异常后独立读取，各项非同一瞬间 |
| 最终收尾 | PLC/CNC参数输出实际清理、内存/来源/下游、锁、完成时间 | 先显示进行中，真实退出后自动补充 |
| 完整异常 | Exception.ToString、内部异常与原报告、带时间的探测历史 | 可以展开/复制，不能用旧固定尾句替代实际收尾 |

探测记录包含首次名义Z/实际Z0、补偿位置、X2、X11和累计下降；充磁前有板标为来源探测，充磁后才确认持件。故障发生在文件/并行操作时，业务最后运动步骤与实际文件失败步骤分别表示。

CraneAlarmSnapshotReader创建独立短连接，预算2秒，只读D5000起30字以及FC01输入点X6=63494、X7=63495、X11=63497、X2=63490。X11按八进制换算，不是63499。读取失败显示未知/错误，不能补0。关闭窗口取消采样，刷新只更新现场区，不改变历史，不发设备命令、不清缓存、不恢复线路。

## 3. 分场景处理

| 场景 | 程序最后处理 | 现场要核对 |
|---|---|---|
| ST007读取X11/D100失败、尺寸非法、板长超差 | 本次严重暂停、清匹配current/来源残留，不回缓存；详情保留原板信息 | 板通常仍ST007；移走本板，真实观察M800=0后换下一板 |
| 任一载具配置的全部放磁探测位置无板 | 不充磁，不超过配置位置数；默认3个位置、累计补偿10mm；暂停、按本次归属作废 | 核对本次日志配置、板/位置/感应器，移走失败板，安全及实际放磁确认 |
| 探测次数/步长小于1或累计距离溢出 | 组件不读取设备、不下降；抛严重异常，所属动作暂停作废 | 修正配置；确认本趟板已按最终收尾处理，不能直接沿用旧身份 |
| 充磁前X11读失败或X2仍压住 | 立即停止本轮探测，未知不当作0 | 位置/下压/通讯与板，不能继续向下强压 |
| 充磁响应未知、后X11=0/读失败 | 不再下探、不通知来源取走，暂停作废 | 可能已充磁且板位置未知，不能按未持件直接处理 |
| 机械手1送叉未完整闭环失败 | 清本板current/来源；归属守卫成立才清货叉/双头镗输出与前端Idle | 旧板可能在机械手/货叉，处理本板并核对门闩/请求 |
| 机械手1已交叉后的空载回位位置未知 | 两线新派发暂停，仅清本次回位动作，保留已交付货叉板 | 不把货叉正常板当成失败板；机械手安全位置由人工确认 |
| 前天车Pos3、打号文件、打号取回失败 | 清本趟任务牌/续搬记录/匹配队列残留，不回队；保护下一板货叉周期 | 本板在Pos3/打号机/天车；清旧实物与文件残留，不能清下一板current |
| 前天车中转缓存交付后空载归位失败 | 清本趟动作，保留成功下游身份 | 下游正常板保留；只恢复天车/碰撞区域安全 |
| 后天车上料CommitPickup前严重失败 | 本床清参数输出/Wp并Idle；匹配来源预约+到达代次+身份原子作废 | 移走本板后无需再删新来源；清理跳过表示归属变化须核对 |
| 后天车上床/下床运动、握手、分流失败 | 本租约严重作废床状态及本次续搬入口，保护成功下游 | 板可能在床/天车/下游，请求数据不由上位机强写；确认安全/夹紧 |
| 斜床Completed后finally空载侧退避失败 | 可能Machining/Wp仍在，保护已交付板 | 不能说“所有弹窗都把床清Idle”；看实际收尾 |
| ST709编码器不稳、微调超差、动作通信失败 | 现在暂停、弹窗、本板不回FIFO；本目标机Pending/Idle及输出参数清理 | 已自动清旧身份，不再删下一队头 |
| 研磨目标XY/参数并行失败 | 收束实际子任务后清本机；中间Pending暂存不代表最终保留 | 核对清零失败残留和实体位置 |
| 研磨下料ST710放料后通知/回位失败 | 清本机、本趟动作，保留后续FIFO、ST710及已成功通知 | 检查ST710旧板/数据；X11=0不能证明架空 |
| M2/M3取板或持件/交接严重失败 | 清本版本Busy/在途/显示及匹配来源代次；仅未确认归属输出按位清 | 保护提前放锁后新板、成功通知/FIFO；M700匿名不清其他来源 |
| TypeA取板前切单机/磨石报警 | 明确准入退回同一板到FIFO，不暂停整个研磨 | 保板等待符合准入的机器，无须丢板 |
| 普通Pause、独立FIFO超限/状态观察异常 | 保持各自原策略，不自动作废所有板 | 看告警来源和实际动作是否退出，不套用动作严重作废 |

## 4. 恢复前步骤

1. 保持引擎暂停，等原异步动作实际退出且弹窗收尾结束，核对清零成功/失败、来源是否删除或因归属变化跳过、锁是否释放。
2. 根据冻结板号/序号和阶段定位本次失败板。人工移走应丢弃的实物；已完整交付下游的板保护，不能把它或下一块板随手拿走。
3. 确认载具安全位置、实际放磁及碰撞区域安全，机床联机/报警/门/夹紧/请求和输出参数恢复正确。软件清零不自动放磁或回原点，Idle不能证明机器实体空。
4. 来源已经自动清旧板不再清下一ST709队头/同架位新板；如果是旧遗留/部分成功下游身份，按实际设备、完整身份和应急返回结果对账。
5. 恢复所属1/2号线，或研磨/动平衡独立引擎。新上料除Idle/请求数据=1，还需来源实体与软件缓存、长度、连接/信号新鲜、门、锁等准入。

主页Line1/2Toggle当前没有调用EnsureNoPendingManualActionsForLine；Resume只打开暂停位，不代替人工事故处理。已经自动作废的旧板不能靠重启或旧弹窗续跑。设备清零失败仍软件作废，但设备可能部分残留，应先核对其实际状态。
