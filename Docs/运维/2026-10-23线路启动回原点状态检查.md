# 1/2号线及研磨启动与恢复：天车回原点状态检查

> 2026-10-23。按用户确认，将1/2号线及研磨启动检查统一为D5006/5007/5008严格等于1，并删除这些线路原XYZ显示坐标全零保护。研磨为本日后续扩展，本文覆盖此前“研磨仍保留XYZ全零保护”的说明。

## 1. 放行规则

| 主页面操作 | 读取设备 | 必须同时满足 |
|---|---|---|
| 启动/恢复1号线 | 1号线前天车1、后天车2 | 两台D5006、D5007、D5008共六个值全部==1 |
| 启动/恢复2号线 | 2号线前天车3、后天车4 | 两台D5006、D5007、D5008共六个值全部==1 |
| 启动/恢复研磨线路 | 配置`grinding.craneNo`指定的研磨天车，默认5号 | 该台D5006、D5007、D5008三个值全部==1 |

三个寄存器为独立Word，分别对应X/Y/Z回原点完成状态。本次启动要求**恰好为1**；0、2、-1等其他值一律不通过。不是“非0就通过”，也不使用显示XYZ坐标是否为0判断。

点击暂停时沿用原暂停流程，不做这项启动检查。点击启动或暂停后的恢复时，必须先完成本线两台读取，确认全满足，再执行原前/后端Start或Resume并更新页面运行标志。不是先启动前端、再检查后端；任何一台不合格，本次两个引擎均不调用Start/Resume。

研磨同样先检查、再Start/Resume及设置IsGrindingRunning=true；只读取配置中的一台，不额外检查天车1～4，不硬编码5号。普通研磨暂停仍调用原PauseAsync，不改其急停发送和页面刷新流程。

## 2. 实时读取与失败处理

通过共享天车连接缓存取得对应服务，调用ReadStatusAsync实时读取D5000～D5029，取XHomeCompleted/YHomeCompleted/ZHomeCompleted三个字段。复用连接不等于使用上次页面缓存；每次点击都会重新读取，结果保存为本次三个原始值的快照。

1/2号线两台异步并行读取，各自最多5秒；一台读失败仍保留另一台结果。研磨单台共用相同5秒超时和快照规则。返回null、连接/读取异常、超时都拒绝启动，不能用0代替未知，也不能沿用旧“读取异常交给后续流程”的放行行为。超时后迟到的成功响应也不会改变已经拒绝的本次结果。

这是一轮启动前快照检查，不是运行中持续轮询回原点标志；通过后原流程继续。软件不自动执行回原点、不写1到完成标志、不清报警或PLC输出。

## 3. 拒绝启动弹窗

失败显示一个启动检查弹窗，列出线路、前后角色、天车编号、三个寄存器实际值及通过/不通过标记。读失败时显示错误原因和三个“未知”，不编造值。例如：

```text
1号线不能启动/恢复：天车回原点完成标志未满足。

1号线前天车（1号天车）
  X D5006=1  ✓
  Y D5007=0  ✗（必须等于1）
  Z D5008=1  ✓

1号线后天车（2号天车）
  X D5006=1  ✓
  Y D5007=1  ✓
  Z D5008=2  ✗（必须等于1）
```

这属于启动准入失败，不创建搬运动作严重异常，不调用作废/清机床收尾。现有工件、队列、Pending、锁和设备输出保持原状；本轮不启动/恢复，不等于取消已经存在的在途任务。人工核对状态后再次点击会重新读取。弹窗不要求程序自动移动设备。

研磨弹窗标题为“研磨线路不能启动/恢复 - 回原点状态未满足”，内容列出实际天车编号，例如“研磨天车（5号天车）”，以及D5006/7/8逐项值及通过/失败标记。5号天车D5008=0时显示该实际0；通信失败时三个值显示“未知”并附读取失败原因。本轮不调用研磨Start/Resume，不清FIFO、研磨机Pending或状态，也不发送PLC复位输出。

手动页面原回原点状态显示仍按协议“非0为完成”，本轮未改该显示规则。因此读到2时手动页可能显示已完成，而启动检查仍按用户指定的严格==1拒绝，以弹窗中的原始值为准。

## 4. 删除的旧XYZ全零规则

1/2号线已删除以下入口：

- 主页面启动/恢复时两台天车的XYZ全零检查。
- Line1Front/Line2Front前天车任务出队前的连续两次XYZ全零检查。
- Line1Rear/Line2Rear后天车斜床上料和下料派发前的XYZ全零检查。
- 四个引擎不用的OnCraneZeroPositionDetected回调字段、后端专用检查方法及主页对应回调绑定。

因此本线六个回原点值全1时，即使显示XYZ=0/0/0，也不会再因为这项旧规则在启动或后续派发时被拦住。没有删机械手安全位置、正常Z回零、目标到位、下压保护或其他业务信号条件；这些与“XYZ三个显示值同时为0”是不同检查。

研磨后续扩展一并删除以下内容：

- 主页面研磨启动/恢复的旧XYZ全零检查。
- GrindingFlowEngine上料出队前和下料派发前的旧XYZ全零检查、专用助手及回调字段。
- HomeViewModel旧坐标检查助手、全零告警处理和最后一条研磨回调绑定。
- 已无调用方的`Service/FlowEngine/CraneZeroPositionGuard.cs`及旧告警/坐标快照类型。

因此研磨三个标志全1时，XYZ=0/0/0也不会再因旧规则拦截启动或派发；运行中不会新增长期轮询这三个回原点Word。其他安全位置、运动到位、正常Z回零、X2下压保护和业务信号仍按原流程执行。

`GrindingFlowEngine.PauseForCraneZeroPosition()`保留历史公共方法名，因为主页其他研磨最终安全异常仍使用这个软暂停入口。其行为仍为设置暂停位、不发送D4518、不清FIFO；注释和日志改为通用安全异常说明，不能将方法名理解为仍有XYZ全零判断。严重动作失败的清机床/作废收尾没有修改。
