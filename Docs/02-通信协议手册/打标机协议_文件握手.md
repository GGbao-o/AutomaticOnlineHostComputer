# 打标机通信协议（基于文件交换的握手）

## 核心机制
上位机与打标机通过监控共享文件夹内的文件实现状态同步和任务触发。不使用标准工业协议。

> 当前两条生产前端流程直接实现 `3.txt/A.txt/B.txt` 协议；`FileHandshakeClient` 的通用 `cmd.txt/ack.txt/error.txt` 协议没有接入这两条前端生产链路。现场排障必须先确认正在运行的是哪一种，不得混用文件名或完成语义。

## 共享文件夹
- **1号线路径**：`\\192.168.2.67\1`（网络共享，用户名 `ggbao` 密码 `123456`）
- **2号线路径**：`\\192.168.2.74\1`（网络共享，用户名 `ggbao` 密码 `123456`）
- **权限**：双方均需读写权限

## 交互流程

```
1. 没版 → 天车将工件放到打标位 → 退磁 → Z升到安全高度

2. 上位机读 `3.txt` 确认打标机空闲（内容 `1`）
   生成文件 `A.txt`：
     第一行: 刻印内容（版号等文本）
     第二行: 工件直径（mm）

3. 打标机检测到文件 A.txt → 开始打标；上位机同时等待天车 Z 回到安全高度

4. 打标完成 → 打标机生成文件 `B.txt`

5. 上位机每500ms轮询检测到文件 B.txt 存在 → 本轮文件握手完成

6. 天车下降充磁取走工件 → Z升安全高度

7. 天车取回且 X11 确认有板、Z升安全后，上位机删除文件 B.txt（清理本轮回执，准备下一轮）
```

## 文件清单

| 文件 | 用途 | 谁生成 | 内容 |
|------|------|:---:|------|
| `3.txt` | 状态标识 | 打标机 | 0=有版(忙), 1=没版(空闲) |
| `A.txt` | 打标任务 | 上位机 | 第1行: 刻印内容 / 第2行: 工件直径(mm) |
| `B.txt` | 打标完成信号 | 打标机 | 任意内容（上位机只判断文件是否存在） |

## 上位机伪代码

```csharp
// 1. 天车放好工件、回到安全高度
await crane.MoveAbsoluteAsync(markerX, markerY, markerZ, ct: ct);
await crane.MagnetOffAsync(ct);
await crane.MoveAbsoluteAsync(-1, -1, safeZ, ct: ct);

// 2. 生成打标任务文件（路径 \\192.168.2.67\1）
var taskPath = @"\\192.168.2.67\1\A.txt";
await File.WriteAllTextAsync(taskPath, $"{markingContent}\n{diameter}");

// 3. 等待打标完成（轮询 B.txt）
var donePath = @"\\192.168.2.67\1\B.txt";
var deadline = DateTime.UtcNow.AddHours(1);
while (!File.Exists(donePath) && DateTime.UtcNow < deadline)
    await Task.Delay(500);

if (!File.Exists(donePath))
    throw new TimeoutException("打标机超时：1小时(3600s)未生成文件 B.txt");

// 4. 天车取走工件
await crane.MoveAbsoluteAsync(-1, -1, markerZ, ct: ct);
await crane.MagnetOnAsync(ct);
await crane.MoveAbsoluteAsync(-1, -1, safeZ, ct: ct);

// 5. 清理
File.Delete(donePath);
```

## 超时与异常

| 场景 | 超时 | 处理 |
|------|:---:|------|
| 等 B.txt 出现 | 1小时（3600s） | 抛 TimeoutException，前端引擎暂停并弹窗，人工检查打标机和前天车 |
| A.txt 写入失败 | 立即 | 当前前端动作抛异常；不能据此假定打标机未读取部分或全部内容 |
| 网络共享断开 | 立即 | 当前前端动作抛异常；共享目录探测线程不会代替本次文件操作重试 |

## 与前端异常状态的关系

打标机等待超时发生时，工件通常已经被前天车放到打标位并退磁，或者处在打号/取回的中间状态。上位机会暂停本线前后端并弹窗提示人工确认；软件锁会按各自 `finally` 释放，但释放锁不代表工件已经离开打标机或前天车已经处于安全位置。

前天车异常和打标机超时不得把货叉—双头镗状态机强行复位为 `Idle`。因为前天车处理的是已经离开货叉 Pos3 的上一块板，货叉可能已经回待机并开始下一块板的 R6101/R6103/R6107 阶段。恢复时应先处理打标机处的旧板和前天车安全位置，再启动线路；货叉阶段按保留状态继续。

## 当前实现边界

- `B.txt` 的存在是文件回执，不是相机、激光头或工件实体的二次确认；取回仍必须执行磁铁/X11/Z安全流程。
- 写 A、等待 B、取回 B 删除三个动作之间若发生网络响应未知或人为改文件，代码无法仅凭文件系统重建物理状态，必须现场对账。
- 文档中的共享用户名和密码属于现场部署信息，不构成源码硬编码协议常量；部署变更以实际运行配置和共享权限为准。
