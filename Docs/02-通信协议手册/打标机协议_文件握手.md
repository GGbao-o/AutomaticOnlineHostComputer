# 打标机通信协议（当前生产文件握手）

> 核对日期：2026-10-11；依据两条前端的打号步骤与 MarkerShareMonitor。1号线工位ST107，2号线ST502；ST102是1号线后天车信息站号。

## 共享目录及连接

两条前端的生产共享目录分别是 `\\192.168.2.67\1`、`\\192.168.2.74\1`，由引擎常量指定。当前共享连接凭据也在代码中指定，并非配置页修改motion_settings.json即可改变；此处不重复凭据。部署迁移需核对引擎常量、监控器初始化、Windows共享权限与实际程序版本。

MarkerShareMonitor独立后台探测共享可达性，约5秒单飞探测，用于页面在线状态。它不替代动作中的目录检查、文件写入和回执等待。

## 文件与消费关系

| 文件 | 生成方 | 当前源码的实际处理 |
|---|---|---|
| 3.txt | 打标机约定状态文件 | 只声明路径，生产前端没有读取内容；没有3.txt=1空闲准入检查 |
| A.txt | 上位机 | ASCII两行：MarkingContent、Diameter，行间为CRLF；写前删除旧B |
| B.txt | 打标机 | 只检查存在，不读取内容；取回工件X11确认且Z回升后删除 |

通用FileHandshakeClient的cmd.txt/ack.txt/error.txt不接入这两条生产前端，不能拿通用示例文件名排障。

## 实际顺序

1. 前天车持ZoneMT，XY到打标工位，必要XY绝对编码器微调后Z下降，退磁放板。
2. 启动Z上升到打标退让高度，与写A任务并行；退让高度按markerZ−300叠加天车Z偏移计算，不应统一写成Z=0。
3. 文件任务实时检查目录；必要时尝试Windows共享连接，连接异常最终由目录是否可访问判断。删除旧B，再按ASCII写A。
4. Z上升与文件任务两者均成功后，按500ms轮询B，最长1小时。
5. B出现后执行打标位取回XY/微调、Z下降、充磁、X11确认、Z回升。
6. 删除本轮B，再进入中转架交接。源码没有本轮完成后主动删除A的统一步骤。

## 异常边界

| 场景 | 程序行为 | 现场判断 |
|---|---|---|
| A写失败/共享断开 | 当前前天车动作抛异常，按既有物理阶段裁决 | 可能已经放板；不能推断打标机未读到A |
| B一小时未出现 | 抛TimeoutException，既有暂停回调与统一异常弹窗 | 检查打标工位旧板、实际加工、天车位置 |
| B旧残留 | 写A前尝试删除 | 不是清打标机内部任务，也不是清实物 |
| B出现但取回失败 | 磁铁/X11/运动异常路径 | 文件回执不证明磁铁持件 |
| 取回后删除B失败 | 动作仍可能失败 | 板可能已在天车上，避免把旧回执与新板混配 |

文件没有持久化动作号校验，也没有异常后一律删除A/B的自动补偿；人为改文件或网络响应未知时须核对实物及身份。前天车异常不执行斜床/研磨六流程自动作废，不自动回退货叉阶段；货叉可能已处理下一块板。
