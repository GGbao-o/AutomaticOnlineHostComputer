# 沈阳斜床协议（FANUC FOCAS 宏变量）

> 依据 `FanucSkewBedAddress.cs`、`FanucSkewBedService.cs` 和两条后端引擎整理，更新时间：2026-07-03。

## 1. 适用设备

| 线路 | 工位 | 数量 | 协议 | 默认端口 |
|------|------|:---:|------|:---:|
| 1号线 | ST112 | 1 | FANUC FOCAS2，宏变量读写 | 8193 |
| 2号线 | ST606~ST610 | 5 | FANUC FOCAS2，宏变量读写 | 8193 |

设备 IP 和端口优先从数据库 `machine` 表读取。当前生产实现通过 `_sdk.GetMacro/SetMacro` 访问宏变量，不使用旧文档所写的 PMC F/G 地址换算。

## 2. CNC到上位机状态

| 宏变量 | 信号 | 当前代码用途 |
|:---:|------|------|
| #1000 | 机床准备就绪 | `IsMachineReadyAsync` |
| #1001 | 请求数据 | 斜床允许上位机下发加工参数 |
| #1002 | 请求上料 | 允许后天车送料 |
| #1003 | 尾座夹紧到位 | 上料退磁前必须确认 |
| #1004 | 请求下料 | 加工完成，允许后天车取料 |
| #1005 | 尾座分开到位 | 下料时Y轴退出顶尖前必须确认 |
| #1006 | 自动门开 | 地址已定义，当前后端主流程未单独派发检查 |
| #1007 | Y轴安全位置 | 地址已定义 |
| #1009 | Z轴安全位置 | 地址已定义 |
| #1010 | 刀架安全位置 | 地址已定义 |
| #1011 | X轴安全位置 | 地址已定义 |
| #1012 | 操作模式 | 0手动、1半自动、2全自动，地址已定义 |
| #1013/#1014 | 刀具寿命到期 | 地址已定义 |

`ReadSignalsAsync` 一次读取 #1001~#1005，并在同一个服务锁内形成快照；任何一次读取异常都不会发布半新半旧状态。

## 3. 上位机写入

### 3.1 加工参数

| 宏变量 | 内容 | 格式 |
|:---:|------|------|
| #800 | 版辊长度 | double，mm |
| #801 | 斜车成活直径 | double，已叠加站号直径补偿 |
| #802 | 堵孔尺寸/版孔类型 | double |
| #909 | 加工模式 | int |

`SendMachiningParamsAsync` 写入后会读回校验，最多3次。只有长度、直径、堵孔和模式全部匹配，才写 #1101=1。

### 3.2 握手输出

| 宏变量 | 信号 | 写入时机 |
|:---:|------|------|
| #1101 | 数据下发完成 | 参数写入并读回校验成功后 |
| #1102 | 天车上料到位 | 后天车已到装料位置，允许尾座夹紧 |
| #1103 | 天车上料完成 | 尾座夹紧、退磁、Z升安全后 |
| #1104 | 天车下料到位 | 后天车吸住工件，允许尾座分开 |
| #1105 | 天车下料完成 | 尾座分开、Y退出、Z升安全后 |
| #651 | 尾座停止 | 异常处理专用 |

正常握手会在进入下一阶段前清理上一个上位机输出，避免旧的1被下一循环误识别。人工应急清理会把 #800/#801/#802/#909/#1101~#1105 全部写0，但不控制天车或机床物理动作。

## 4. 上料握手

```text
#1001=1 请求数据
  -> 写 #800/#801/#802/#909并读回校验
  -> #1101=1 数据完成
  -> 等 #1002=1 请求上料
  -> 后天车到位并写 #1102=1
  -> 等 #1003=1 尾座夹紧
  -> 后天车退磁、Z升安全
  -> 清上一阶段输出并写 #1103=1 上料完成
```

## 5. 下料握手

```text
#1004=1 请求下料
  -> 后天车到位、充磁并由X11确认吸住
  -> 写 #1104=1 下料到位
  -> 等 #1005=1 尾座分开
  -> Y退出顶尖位置、Z升安全
  -> 清上一阶段输出并写 #1105=1 下料完成
```

## 6. 连接与异常

### 6.1 每台设备独立连接

- 每台 FANUC 斜床各有一个 `FanucSkewBedService`、一个 FOCAS 句柄和一条专用 Worker 线程。
- 一台未上电设备只会阻塞自己的连接 Worker，不会串行挡住另外4台机床，也不会在 UI 线程执行原生 SDK 调用。
- 正常连接、断开、#1000~#1105 读写、状态探测及500ms信号快照都排入该设备 Worker，由同一个 OS 线程串行执行。
- 业务层仍调用原来的异步方法，等待条件、宏变量地址、写入时机和引擎异常分支没有变化。

### 6.2 连接和操作超时

| 项目 | 当前值 | 说明 |
|------|:---:|------|
| 建立 FOCAS 连接 | 3秒 | `cnc_allclibhndl3` 的 timeout 原生单位就是秒，代码直接传3，不再按毫秒换算 |
| 已连接会话单次操作 | 3秒 | 连接成功后调用 `cnc_settimeout` |
| 普通信号/握手读写 | 最多3次 | 已连接会话读写失败后立即重建；连接未建立时等待1秒再试 |
| 页面信号快照 | 单轮1次 | 一次读取 #1001~#1005；失败后本轮快照标为无效并指数退避 |
| 快照正常周期 | 500ms | Worker没有业务命令时刷新 |
| 离线退避上限 | 30秒 | 500ms、1s、2s……最大30s，设备恢复后自动重新连接 |

原实现的构造参数名为 `timeoutMs=300`，又在 SDK 内除以10后把30传给 `cnc_allclibhndl3`。由于原生参数单位实际是秒，离线机床一次连接可能等待约30秒。当前已改为明确的 `connectTimeoutSeconds=3`。

### 6.3 `EW_HANDLE(-8)`

`-8` 表示 FOCAS 句柄无效，不代表 #1003 地址错误，也不代表 #1003 的值非法。原实现虽然用 `SemaphoreSlim` 防止两个调用同时进入 SDK，但 Worker轮询和后端引擎仍可能在不同 OS 线程交替使用同一个句柄：

```text
Worker线程建立句柄
  -> 业务线程读取#1003
  -> FOCAS返回EW_HANDLE(-8)
  -> 业务线程重建句柄并重试成功
  -> Worker线程再次使用这个新句柄
  -> 可能再次出现EW_HANDLE(-8)
```

当前实现改为：业务线程只把命令加入队列，句柄从创建、读写、重连到释放始终属于同一设备 Worker。日志包含 `PLC=IP:Port`、`Handle`、`WorkerTid`、操作名称和 `Attempt=当前/总次数`，可判断是连接失败、句柄失败还是最终三次均失败。

### 6.4 失败后的业务影响

- 第1或第2次失败后重连成功：原业务调用继续完成，不暂停引擎。
- 三次均失败：最后异常返回后端引擎，仍按原有业务上下文决定是否暂停、保留工件和释放锁；本次通信修复不改这些分支。
- #1003处于正常等待值0：只返回 `false`，不属于异常，不触发重连。
- #1003读取收到 `EW_HANDLE(-8)`：通信层重建会话并最多重试3次；只要某次成功，夹紧等待流程继续。
- 参数 #800/#801/#802/#909 保留原有写后读回校验；只有校验成功才写 #1101=1。
- 物理工件已被天车吸住或已放下但握手未确认时，后端引擎仍按原逻辑暂停并保留工件数据。

### 6.5 现场日志示例

```text
[FANUC-SDK] ⚠ 读 #1003失败 Attempt=1/3 PLC=192.168.x.x:8193 Handle=12 WorkerTid=27 Error=EW_HANDLE(FOCAS句柄无效)
[FANUC-SDK] 断开并准备重建会话 Reason=读 #1003第1次失败 ...
[FANUC-SDK] 准备立即重连并重试 读 #1003 ...
[FANUC-SDK] ✓ 连接成功 PLC=192.168.x.x:8193 Handle=13 WorkerTid=27
[FANUC-SDK] 读宏变量 #1003=1.0 → True
```

如果升级后仍持续出现 `EW_HANDLE(-8)`，应根据同一行的 IP、Handle 和 WorkerTid 检查设备端连接数量、FOCAS授权/版本及网络会话，而不应把它误判为宏变量 #1003 本身错误。
