## 1. 设备挂载关系

| IP | 设备 | M 区读写方式 | MitsubishiMcClient 配置 |
|------|------|:---:|------|
| 192.168.2.63:9000 | 总上料架 + 6个中转位 + ST019/ST020/ST021 后端料架握手 | **字读/写** (0x01/0x03) | UseBitReadForM = **false** (默认) |
| 192.168.2.88:9000 | 一号线货叉 | **位读/写** (0x00/0x02) + nibble编码 | UseBitReadForM = **true** |

| 192.168.2.65:9000 | 动平衡 ST008/ST009 + 研磨上料架 ST010/ST709 | 字读/写 | UseBitReadForM = false |

## 2. 帧头（12 字节，所有请求通用）

```
偏移  字节  字段
────────────────────
 0     1    Subheader: 0x00=位读  0x01=字读  0x02=位写  0x03=字写
 1     1    PLC 站号: 固定 0xFF
 2~3   2    监视定时器: 0x0A 0x00 (LE, 10 × 250ms = 2.5s)
 4~7   4    起始地址: 十进制, 4 字节 LE
 8~9   2    设备名: " D"=20 44   " M"=20 4D
10~11  2    点数: 字读→字数, 位读→nibble数 (LE)
12~   N×2  数据区: 仅写请求
```

## 3. D 寄存器（字设备）

### 读 D — 字读命令 0x01

```
01 FF 0A 00  地址(4B LE)  20 44  字数(2B LE)
```

示例 — 读 D200, 1 个字：
```
01 FF 0A 00  C8 00 00 00  20 44  01 00
```

示例 — 读 D200~D204, 5 个字：
```
01 FF 0A 00  C8 00 00 00  20 44  05 00
```

**响应（格式 B：`[EndCode 2B LE][数据...]`）：**
```
00 00  6F 00
└─OK  └─D200=111
```

### 写 D — 字写命令 0x03

```
03 FF 0A 00  地址(4B LE)  20 44  字数(2B LE)  数据(N×2B LE)
```

示例 — 写 D200 = 12345：
```
03 FF 0A 00  C8 00 00 00  20 44  01 00  39 30
                                          └─ 12345
```

示例 — 批量写 D200~D202 = [111, 222, 333]：
```
03 FF 0A 00  C8 00 00 00  20 44  03 00  6F 00  DE 00  4D 01
                                          └─111  └─222  └─333
```

**响应：** `00 00` = 成功

## 4. M 继电器（位设备）— nibble 编码

> **关键：FX3U-ENET-ADP 位数据使用 nibble 编码，并非标准 bit-packed！**

### nibble 编码规则

```
每字节 = 2 个 nibble
  高 4bit → 偶地址 (M0, M2, M4 ...)
  低 4bit → 奇地址 (M1, M3, M5 ...)
  0x1 = ON
  0x0 = OFF
```

**示例 — 当 M2=ON, M4=ON, M10=ON, M12=ON：**
```
数据: 00 10 10 00 00 10 10 00     (8 字节 = 16 nibble)

字节0 0x00 → [高:M0=OFF] [低:M1=OFF]
字节1 0x10 → [高:M2=ON ] [低:M3=OFF]
字节2 0x10 → [高:M4=ON ] [低:M5=OFF]
字节3 0x00 → [高:M6=OFF] [低:M7=OFF]
字节4 0x00 → [高:M8=OFF] [低:M9=OFF]
字节5 0x10 → [高:M10=ON] [低:M11=OFF]
字节6 0x10 → [高:M12=ON] [低:M13=OFF]
字节7 0x00 → [高:M14=OFF][低:M15=OFF]
```

### 读 M — 位读命令 0x00

**请求：**
```
00 FF 0A 00  地址(4B LE)  20 4D  nibble数(2B LE)
```

示例 — 读 M0~M15（16 nibble）：
```
00 FF 0A 00  00 00 00 00  20 4D  10 00
```

示例 — 读 M900~M914（16 nibble，当前只使用到 bit14）：
```
00 FF 0A 00  84 03 00 00  20 4D  10 00
```

示例 — 读 M100（1 nibble）：
```
00 FF 0A 00  64 00 00 00  20 4D  01 00
```

**响应（格式 A：`[Sub=0x80 1B][EndCode 1B]`）：**
```
80 00  [ (nibble数+1)/2 字节 ]
```

**解析代码（C#）：**
```csharp
int nibbleCount = count * 16;           // 1 word = 16 nibble
int byteCount = (nibbleCount + 1) / 2;  // 16 nibble → 8 字节
byte[] nibbleBytes = ...;

ushort val = 0;
for (int b = 0; b < 16; b++)
{
    int nibbleIdx = b;            // 当前 word 内的 nibble 索引
    int byteIdx = nibbleIdx / 2;
    int nibble = (nibbleIdx % 2 == 0)
        ? (nibbleBytes[byteIdx] >> 4)      // 偶→高nibble
        : (nibbleBytes[byteIdx] & 0x0F);   // 奇→低nibble
    if (nibble != 0) val |= (ushort)(1 << b);
}
result[w] = val;
```

### 写 M — 位写命令 0x02

**请求（n 字 = n×16 nibble = n×8 字节）：**
```
02 FF 0A 00  地址(4B LE)  20 4D  10 00  [8字节nibble数据]
```

**nibble 数据编码 — ushort → 8 字节：**
```csharp
var nibbleData = new byte[8];
for (int b = 0; b < 16; b++)
{
    bool on = (value & (1 << b)) != 0;
    int byteIdx = b / 2;
    if (b % 2 == 0)
        nibbleData[byteIdx] |= (byte)(on ? 0x10 : 0x00);  // 偶→高nibble
    else
        nibbleData[byteIdx] |= (byte)(on ? 0x01 : 0x00);  // 奇→低nibble
}
```

**响应：** `82 00` = 成功

## 8. MC63：总上料架、中转架与后端料架握手（192.168.2.63）

MC63 的 M 区按 `M800` 起始读取 2 个字：第1字覆盖 M800~M815，第2字覆盖 M816~M831。源码入口为 `CenteringRackService.ReadAllStatusAsync/ReadM816Async`。

| M/D地址 | 对齐字/位 | 方向 | 当前含义 |
|:---:|:---:|:---:|------|
| M800 | M800字 bit0 | PLC→中控 | 总上料架请求取料，1=请求 |
| M801 | M800字 bit1 | 中控→PLC | 总上料架取料完成，当前由 `SetPickupDoneAsync` 写 1、延时500ms后写0 |
| M811 | M800字 bit11 | PLC→中控 | 1号线中转架1 ST105 有板 |
| M812 | M800字 bit12 | PLC→中控 | 1号线中转架2 ST101 有板 |
| M813 | M800字 bit13 | PLC→中控 | 1号线中转架3 ST106 有板 |
| M814 | M800字 bit14 | PLC→中控 | 2号线中转架1 ST016 有板 |
| M815 | M800字 bit15 | PLC→中控 | 2号线中转架2 ST017 有板 |
| M816 | M816字 bit0 | PLC→中控 | 2号线中转架3 ST018 有板 |
| M817 | M816字 bit1 | PLC→中控 | 1号线动平衡下料架 ST019 有板（旧式单点状态） |
| M818 | M816字 bit2 | PLC→中控 | ST020 允许2号线后天车放料 |

| M825 | M816字 bit9 | PLC→中控 | ST021 允许机械手3取料 |
| M826 | M816字 bit10 | 中控→PLC | 机械手3已从 ST021 取料完成，只写1 |
| D100 | D100 | PLC→中控 | 总上料架板长，16位无符号，单位mm；前端当前只用于日志 |

### ST020/ST021 完整握手顺序

| 位置 | 放料允许 | 后天车放料完成 | 机械手取料允许 | 机械手取料完成 | 软件缓存键 |
|------|------|------|------|------|------|
| ST020（2号线动平衡下料架） | M818 | M819 | M823 | M824 | `_balWps["M818"]` |
| ST021（2号线短板中转位） | M820 | M821 | M825 | M826 | `_balWps["M821"]` |

流程为：PLC置放料允许 → 后天车二次确认并放料 → 上位机写放料完成并保存工件缓存 → PLC置机械手取料允许 → 机械手吸住且Z升安全 → 上位机写取料完成。缓存键沿用 M818/M821 只是历史命名，不能再解释成 PLC“有板位”。

## 9. MC64：研磨下料架 ST710（192.168.2.64）

| M/D地址 | 对齐字/位 | 方向 | 当前含义 |
|:---:|:---:|:---:|------|
| M720 | M720字 bit0 | PLC→中控 | 1=下料架无板且允许研磨天车向 ST710 放料 |
| M721 | M720字 bit1 | 中控→PLC | 研磨天车放料完成，只写1 |

研磨下料只判断 M720=1。主循环派发前检查一次，天车从研磨机取到工件、准备去 ST710 前再检查一次。工件退磁放到 ST710 并且 Z 升到安全高度后，中控只写 M721=1；MC64 不再使用 M730，也不再写 D200。旧文档中的“MC64 M824”不是当前代码使用的信号。

## 12. M字单bit写的并发保护

当前 `WriteMBitInWordAsync` 为兼容现场 FX 系列 PLC，仍使用按字读改写：读取目标所在的16位 M 字，修改一个 bit，再写回整个字。为了避免 Rear、Balancing、Grinding 以及独立页面客户端并发读取同一个旧值后互相覆盖，客户端使用进程级共享锁，锁键为：

```text
PLC IP + Port + 16位对齐M字地址
```

例如 MC63 的 M819、M821、M824、M826 共用 `192.168.2.63:9000:M816`；MC65 的 M721、M731 共用 `192.168.2.65:9000:M720`。MC64 的 M721 使用不同 IP，因此不会与 MC65 的 M720 字互相阻塞。

锁内执行顺序为：

```text
读取整字 → 合并目标bit → 写回整字 → 回读并校验目标bit
```

回读目标bit不等于期望值时，最多执行3次完整读改写，重试间隔20ms。首次成功不打印日志；发生重试或最终失败时使用 `[MC-RMW]` 前缀记录 PLC、M字、目标地址、bit偏移、期望值、实际值和次数。网络断开、协议超时等通信异常不在这里吞掉或自动重试，继续由引擎和 `McConnectionCache` 执行原有失效重连。

> 能力边界：共享锁只解决本进程中多个上位机写操作互相覆盖，不能锁住 PLC 扫描周期。如果 PLC 在“读取整字”和“写回整字”之间改变同字内其它位，仍可能被旧快照覆盖。彻底解决需要验证原生 MC 单bit写或在 PLC 程序中拆分双方拥有的字，本轮不修改 PLC 地址、bit定义和握手顺序。
