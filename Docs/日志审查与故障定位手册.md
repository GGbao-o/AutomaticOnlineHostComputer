# 日志审查与故障定位手册

> 适用范围：当前 1/2 号线前后端引擎、货叉与双头镗、斜床、动平衡、研磨、天车、机械手、打标机及料架通信。  
> 编写依据：2026-06-28 当前源码中的 `Console.WriteLine`、工件缓存和状态机实现。源码变化后，本文关键词也应同步更新。

## 一、日志文件和使用原则

### 1. 日志位置

- 文件：`D:\BSH\1.txt`
- 程序同时向控制台和该文件输出。
- 文件采用追加模式，程序重启不会清空旧日志。
- `DualWriter` 每次写入后立即刷新，因此程序异常退出前已经输出的内容通常仍可在文件中找到。
- 每次启动会写入：

```text
启动时间：yyyy-MM-dd HH:mm:ss.fff
日志文件：D:\BSH\1.txt
```

审查故障时，应先找到故障前最近一次“启动时间”，避免把上一次运行的日志混入本次判断。

### 2. 三条基本原则

1. **先搜版号和序号，再看最后一条成功日志。** 最后一条成功日志通常就是工件停留位置。
2. **动作日志必须和物理现场核对。** “已发命令”不等于设备已经运动，“退磁完成”才表示软件认为工件已经放下。
3. **出现高危提示时不要直接恢复。** 先确认工件在哪、磁铁是否吸住、天车/机械手/货叉实际位置，再处理缓存和握手位。

## 二、最常用的检索命令

以下命令可在 PowerShell 中直接使用。

### 1. 按版号和序号精确追踪

```powershell
rg -n -F "版号=ABC123 序号=01" "D:\BSH\1.txt"
```

查看匹配行前后各 10 行：

```powershell
rg -n -C 10 -F "版号=ABC123 序号=01" "D:\BSH\1.txt"
```

序号不确定时只搜版号：

```powershell
rg -n -F "版号=ABC123" "D:\BSH\1.txt"
```

只有序号时可以搜索：

```powershell
rg -n -F "序号=01" "D:\BSH\1.txt"
```

注意：序号可能在不同版号中重复，只搜序号不能唯一确定工件。

### 2. 实时查看最新日志

```powershell
Get-Content -Path "D:\BSH\1.txt" -Encoding UTF8 -Tail 100 -Wait
```

### 3. 搜索全部高风险信息

```powershell
rg -n -C 5 "⚠⚠⚠|❌|异常|失败|超时|已暂停|禁止|未闭环|未确认|已隔离" "D:\BSH\1.txt"
```

### 4. 搜索某条生产线

```powershell
rg -n "\[Line1Front\]|\[后引擎\]" "D:\BSH\1.txt"
rg -n "\[Line2Front\]|\[后引擎2\]" "D:\BSH\1.txt"
```

### 5. 搜索某类设备

```powershell
rg -n "\[CraneService\]|\[ForkSvc\]|\[BoringModbusSvc\]" "D:\BSH\1.txt"
rg -n "\[平衡引擎|\[GrindingEngine\]|\[GrinderSvc\]" "D:\BSH\1.txt"
```

如果电脑没有 `rg`，可使用：

```powershell
Select-String -Path "D:\BSH\1.txt" -SimpleMatch "版号=ABC123 序号=01" -Context 10,10
```

## 三、按版号/序号追踪一块板

工件统一标识由 `WorkpieceCache.IdentityText` 生成：

```text
版号=实际版号 序号=实际序号
```

如果软件没有拿到版号，则显示：

```text
版号=未知
```

### 1. 推荐审查步骤

1. 精确搜索 `版号=... 序号=...`。
2. 从第一条“入缓存”开始按行号向下阅读。
3. 找出该工件的最后一条成功日志。
4. 继续查看其后 20 至 50 行，寻找通信异常、条件不满足、等待锁或引擎暂停。
5. 同时搜索工件所在设备的服务前缀，例如 `[ForkSvc]`、`[CraneService]`。
6. 到现场确认工件物理位置与最后一条日志是否一致。

### 2. 正常工件链路关键词

一块板不一定经过所有环节，但正常日志大致按以下顺序出现：

```text
[ERP导入] / [FrontDispatch]
  → [Line1Front] 或 [Line2Front] 入缓存
  → M800=1 缓存有料
  → [机械手1] 取料送叉
  → [货叉] R6104=1 上料完成
  → [货叉] R6107=1 加工完成
  → [货叉] R6108=1 下料完成
  → [天车调度] 出队
  → [前天车] 天车流程开始
  → [打号机] 完成
  → [中转架] 放料完成
  → [后引擎] 或 [后引擎2] 工件缓存写入
  → 斜床上料、加工、下料
  → ST019/ST020/ST021 或 ST010
  → [平衡引擎] M2/M3
  → [GrindingEngine] 工件入缓存
  → 研磨上料、加工、下料完成
```

`SkipBoring` 工件不会经过双头镗加工，正常关键日志是：

```text
SkipBoring
  → M914=1
  → Pos3已到位
  → 工件入天车队列
```

### 3. 如何判断工件停在哪一步

| 最后一条工件日志 | 优先检查 |
|---|---|
| `入缓存`，之后没有 `M800=1` | 总上料架 M800、机械手1连接、货叉条件、引擎是否启动 |
| `M800=1 ... 启动机械手1` | 机械手锁、货叉待机/有板、机械手安全位置、X11 |
| `取料送叉完成` | 货叉/双头镗状态机、R6101/R6103、M912 |
| `R6104=1 上料完成` | 双头镗加工状态和 R6107 |
| `R6107=1 ... M913=1` | 货叉是否到 Pos3、M902、货叉有板 M900 |
| `R6108=1 ... 入天车队列` | 前天车连接、天车锁、目标中转架、打标机 |
| `天车流程开始`但无完成 | 天车是否吸住、打标交互、目标架缓存回调；重点搜 `⚠⚠⚠` |
| `中转架放料完成` | 对应后端缓存是否确认、后引擎是否启动 |
| `开始下料`但无完成 | 后天车、X11、目标料架允许位、缓存回调和完成位写入 |
| `[GrindingEngine] 工件入缓存` | 研磨机请求数据、分配条件、研磨天车锁 |
| `已放入研磨机但握手未完全闭环` | 工件已在设备内，必须现场确认后再恢复 |

## 五、从现象到关键词

| 现场现象 | 第一组关键词 | 第二组关键词 | 常见方向 |
|---|---|---|---|
| 整条线不动作 | `引擎启动|引擎已暂停|主循环异常|慢轮告警` | `未连接|重连|超时|已隔离` | 引擎暂停、主循环被慢IO拖延、关键设备离线 |
| 某一块板不再前进 | `版号=... 序号=...` | 最后所在模块前缀 | 最后成功步骤后的条件未满足 |
| 货叉不动 | `[ForkSvc]|[货叉]` | `M900|M901|M902|M911|M912|M913|M914` | 位置/有板组合不对、命令未写入、MC断线 |
| 双头镗不加工 | `[BoringModbusSvc]|R610` | `请求数据|请求上料|上料完成` | R6101/R6103未到、参数或完成位未写 |
| 双头镗加工完但不下料 | `R6107|M913|Pos3|R6108` | `未连接|异常|保持阶段` | 下料请求没读到、货叉未到Pos3、R6108未闭环 |
| 天车不取/不放 | `[CraneService]|天车锁|共享区锁` | `目标|到位|磁铁|超时` | 天车锁占用、目标条件不满足、编码器/到位异常 |
| 打标处卡住 | `[打号机]|[MarkerShare]` | `A.txt|B.txt|共享目录|不可访问` | UNC目录不可用、文件握手未完成 |
| 斜床不接板 | `[后引擎]|[后引擎2]` | `请求数据|请求上料|长度匹配|连接` | 无可用床、长度不匹配、CNC请求位或通信异常 |
| 斜床加工完不下板 | `开始下料|请求下料|完工记录` | `job1|job2|天车锁|X11` | 完工记录未落库、后天车或目标架条件不足 |
| 动平衡区不搬运 | `[平衡引擎]|[M2]|[M3]` | `M817|M823|M825|M710|M720` | 来源握手、缓存、目的位或路径安全条件不足 |
| 研磨机不接板 | `[GrindingEngine]` | `分配|请求数据|缓存|天车锁` | FIFO无板、请求数据未到、设备离线或天车锁忙 |
| 研磨成品不下料 | `开始下料流程|M720|M730|M721|D200` | `PendingWorkpiece|未闭环|已暂停` | 下料架不允许/不安全、完成通知失败 |
| 页面状态不更新 | `[HomeViewModel]|[StationCard]` | 设备服务前缀 | 引擎快照未刷新、服务断线；以设备日志和现场为准 |

## 六、货叉与双头镗故障定位

### 1. 正常握手顺序

```text
R6101=1 请求数据
  → 写 R2041/R2043/R2044/R2045/R2047
  → R6102=1 数据下发完成
  → R6103=1 请求上料
  → M912=1 货叉送料
  → M901=1 且 M900=0 货叉回待机且无板
  → R6104=1 上料完成
  → R6107=1 请求下料
  → M913=1 货叉取料并去Pos3
  → M902=1 到Pos3
  → R6108=1 下料完成
  → 工件进入前天车队列
  → 前天车Pos3下降并由X11确认吸住
  → 前天车Z回升到安全高度完成
  → M911=1 货叉回待机
```

R6102、R6104分别在数据下发和上料完成时写`1`；本轮下料完成时按`R6108=1 → R6102=0 → R6104=0`立即清理，R6108保持为1。

### 2. 关键词判断

| 日志停留点 | 判断 |
|---|---|
| 等待 `R6101` | 双头镗未请求数据，或Modbus连接异常 |
| 已写参数但没有 `R6102=1` | 参数写入或数据完成位写入失败 |
| 等待 `R6103` | 双头镗未进入请求上料状态 |
| 已发 `M912=1`但没有回待机 | 货叉动作未完成；核对 M900/M901/M902 |
| 已写 `R6104=1`，长期无 `R6107=1` | 双头镗仍加工、设备报警或请求下料未读到 |
| 已发 `M913=1`但无 `M902=1` | 货叉未到Pos3或状态读取异常 |
| `Pos3已到位, 但双头镗Modbus未连接` | 板已在Pos3，但R6108无法写入；待连接恢复 |
| 已看到 `X11=1 已吸到`，但未看到 `Z升安全高度` 完成 | 前天车Z回升命令、到位反馈或天车通信异常；此时不会发送M911 |
| 已完成Z回升，但未看到 `通知货叉回待机位 M911=1` | `_forkSvc`不可用、写M911异常，或流程已被取消/暂停；核对紧邻异常日志 |
| `握手异常`、`保持阶段`、`引擎已暂停` | 状态机故意保留现场阶段，禁止按普通空闲重新派发 |

Pos3正常交接的关键日志顺序必须是：`X11=1 已吸到` → `Z升安全高度` → `通知货叉回待机位 M911=1`。如果M911日志出现在Z回升日志之前，说明运行的不是当前版本。

### 3. SkipBoring

SkipBoring 仍要求双头镗在线并且 `R6101=1`，用于避免设备节拍冲突。之后货叉执行：

```text
M914=1 → 货叉从待机位直接送到Pos3 → 工件进入天车队列
```

搜索：

```powershell
rg -n -C 10 "SkipBoring|M914|Pos3已到位" "D:\BSH\1.txt"
```

## 七、前天车、打标和中转架

### 1. 正常关键词

```text
[天车调度] 出队
[前天车] 天车流程开始
[打号机] A.txt已写入
[打号机] B.txt已生成
[打号机] 完成
[中转架] 放料完成
[前天车] 天车流程完成
```

### 2. 高风险情况

| 关键词 | 含义和处理重点 |
|---|---|
| `天车已充磁但流程中断` | 板可能仍吸在天车上；立即核对磁铁和位置，不能把工件简单放回软件队列 |
| `工件已在...但后端缓存未确认` | 板已物理放到中转架，前端不会重派；必须核对后端缓存再处理 |
| `A.txt`成功但无`B.txt` | 打标文件握手未完成，检查共享目录和打标机 |
| `MarkerShare ... 不可访问` | 后台UNC探测发现目录离线；主循环读取缓存状态，实际打标前仍会再次确认 |
| 长期`等待...锁` | 查找同一把锁之前的“已获取”和“已释放”，确认是否有动作仍占用 |

## 八、后端、斜床和分流

1号线后端使用 `[后引擎]`，2号线后端使用 `[后引擎2]`。

### 1. 正常关键词

```text
工件缓存写入
触发上料
[上料] 开始
[握手] 写入加工参数
[握手] 全部完成
[上料] 完成
开始下料
[下料] 分流
[下料] 完成
```

### 2. 常见问题

| 关键词 | 含义 |
|---|---|
| `当前可用斜床无长度匹配` | 有板但当前空闲斜床长度能力不匹配，不是通信故障 |
| `完工记录未写入job1/job2` | CNC已到下料阶段，但完工记录未落库，本轮保守不下料 |
| `工件物理有板但无工件缓存` | 现场和软件缓存脱节，禁止自动动作 |
| `X11已确认工件离开斜床但未完成目标位放料/通知` | 板已离开机床但流程未闭环，引擎暂停，必须确认后天车和板的位置 |
| `[上料] 异常` / `[下料] 异常` | 结合该行的版号、床号和其后异常信息定位 |
| `共享区退避` | 防碰撞条件触发，通常是正常等待；持续不恢复时检查另一台天车位置 |

## 九、2号线ST020/ST021与动平衡M2/M3

### 1. ST020/ST021新握手含义

| 信号 | 含义 | 写入方/读取方 |
|---|---|---|
| M818 | ST020允许后天车放料 | PLC → 2号线后端 |
| M819 | ST020后天车放料完成 | 2号线后端 → PLC |
| M820 | ST021允许后天车放料 | PLC → 2号线后端 |
| M821 | ST021后天车放料完成 | 2号线后端 → PLC |
| M823 | ST020允许机械手2取料 | PLC → M2 |
| M824 | ST020机械手2取料完成 | M2 → PLC |
| M825 | ST021允许机械手3取料 | PLC → M3 |
| M826 | ST021机械手3取料完成 | M3 → PLC |

注意：代码中的 `M818`、`M821` 也保留为软件缓存键和锁名。看到日志时应结合上下文区分：

- `M818允许放料`：PLC信号。
- `M818缓存`、`M818锁`：软件缓存键或区域锁。
- `M821放料完成`：PLC信号。
- `M821缓存`、`M821锁`：软件缓存键或区域锁。

### 2. M2正常链路

```text
M817有板，或 M823=1 + M818缓存存在
  → 获取来源位置锁
  → 机械手2取料、X11确认、Z回升
  → ST020来源写M824=1（M817来源无M824）
  → 二次确认M710
  → 放到ST008
  → 退磁、Z回升
  → M711=1
```

### 3. M3正常链路

```text
M700有板，或 M825=1 + M821缓存存在
  → 获取M821/M720锁
  → 机械手3取料、X11确认、Z回升
  → M700来源写M701=1；ST021来源写M826=1
  → 二次确认M720
  → 放到ST010
  → 退磁、Z回升
  → M721=1
  → 通知研磨引擎入FIFO
```

### 4. 故障搜索

```powershell
rg -n -C 8 "\[M2\]|\[M3\]|M817|M818|M819|M820|M821|M823|M824|M825|M826|M710|M711|M700|M701|M720|M721" "D:\BSH\1.txt"
```

| 关键词 | 重点判断 |
|---|---|
| `等待 M817锁/M818锁/M821锁/M720锁` | 另一动作仍在相邻区域；查锁的获取和释放 |
| `缓存未到` | PLC允许取料已到，但后天车回调的工件数据尚未写入 |
| `二次确认...失败/未允许` | 派发后目的位状态发生变化，流程保守暂停 |
| `旧动作已被应急取消` | 人工应急已使旧动作版本失效，旧任务不会继续回写 |
| `已吸住工件但未放` | 工件在机械手磁铁上，必须现场确认 |
| `已放...但M711/M721未确认` | 工件已物理放下，但PLC不知道，禁止当作普通未执行处理 |

## 十、研磨流程故障定位

### 1. 正常关键词

```text
[GrindingEngine] 工件入缓存
分配 ... 请求数据=1
开始取料送料流程
M731=1 通知PLC取料完成
上料完成，研磨机开始加工
开始下料流程
MC64 M721=1 通知放版完成
MC64 D200=... 工件直径已写入
下料完成，研磨机空闲
```

### 2. 关键故障

| 关键词 | 含义 |
|---|---|
| `等待下料但天车锁忙` | 研磨机已请求下料，5号天车被其他研磨动作占用；属于排队等待 |
| `研磨机状态扫描超过3s` | 本轮有研磨机状态读取过慢，未完成读被取消，旧触发信号被清空以防误动作 |
| `保留 PendingWorkpiece` | 软件刻意保留在途工件，不回Idle、不清缓存 |
| `WpRecoveryNeeded` | 需要按现场状态恢复工件归属，不能直接重新分配 |
| `已放入研磨机但握手未完全闭环` | 板已在研磨机内，软件暂停等待人工确认 |
| `ST710/M720/M730动作前确认失败` | 成品仍由天车保持，未满足下料架允许/安全条件 |
| `已放到ST710但无法写M721/D200` | 板已放下但PLC通知未完成，需核对MC64通信和寄存器 |

## 十一、通信、重连和慢循环

### 1. 通信关键词

```powershell
rg -n -C 5 "未连接|连接失败|重连|失效连接|超时|Socket|ACK|通信Worker已隔离" "D:\BSH\1.txt"
```

| 关键词 | 解释 |
|---|---|
| `[McCache]`连接创建/复用 | 三菱MC连接缓存状态 |
| `已失效连接等待重连` | 当前连接已被移除，后续由重连逻辑恢复 |
| `通信Worker已隔离` | 同步CNC调用超时后，该设备Worker被隔离；当前线路停止使用该CNC，另一线路不应受影响 |
| `ACK`超时 | MC写入未收到响应，上层应进入异常和锁释放逻辑 |
| `ModbusTcpClient`异常 | 检查IP、端口、设备在线状态和是否被设备端断开 |

### 2. 慢轮告警

前端主循环出现以下日志，表示本轮IO或业务耗时超过阈值：

```text
[Line1Front] 慢轮告警: IO/业务耗时=...ms 轮次=... 货叉阶段=... 缓存=...
[Line2Front] 慢轮告警: IO/业务耗时=...ms 轮次=... 货叉阶段=... 缓存=...
```

处理顺序：

1. 查看告警前后是哪一个设备服务正在读写。
2. 搜索同时间附近的 `超时`、`未连接`、`MarkerShare`、`状态扫描超过3s`。
3. 如果只有偶发一条且生产继续，记录观察。
4. 如果持续出现并且节拍下降，优先检查对应设备网络和SDK调用。

## 十二、日志节流后的正确解读

为降低磁盘IO和重复日志，部分高频状态只在“状态变化”或心跳周期到达时输出：

| 日志类型 | 当前规则 |
|---|---|
| 天车通用状态 | 关键状态变化立即输出；不变时约10秒心跳一次 |
| 货叉M900~M914原始状态 | 原始字变化立即输出；不变时约10秒心跳一次 |
| MC63料架M800~M831/D100 | 原始值变化立即输出；不变时约10秒心跳一次 |
| 前端货叉状态机快照 | 阶段或关键状态变化立即输出；不变时约10秒心跳一次 |
| 研磨等待天车锁 | 同类等待约10秒输出一次 |
| 打标共享目录状态 | 连接变化立即输出；不变时约30秒心跳一次 |
| 前端慢轮告警 | 最多约10秒输出一次，避免故障时刷屏 |

因此：

- 两条相邻状态日志间没有每500ms记录，不代表中间没有读取。
- PLC位变化、动作命令、完成通知、暂停和异常仍应保留关键日志。
- 判断“读不到请求下料”时，不要仅凭缺少重复状态行；应同时查设备连接、状态变化日志、状态机阶段和后续动作日志。

## 十三、高危日志处理清单

出现下列日志时，先暂停自动处理并核对现场：

| 高危关键词 | 必须确认 |
|---|---|
| `天车已充磁但流程中断` | 哪台天车、磁铁是否吸板、X/Y/Z位置、软件在途工件 |
| `已吸住工件但未放` | 哪台机械手、X11、工件目标位是否空闲 |
| `工件已在...但后端缓存未确认` | 板实际在哪个中转架、后端缓存是否已有同一版号序号 |
| `已放...但M711/M721未确认` | 板已放下，PLC完成位是否补写成功，禁止重复放板 |
| `已放入研磨机但握手未完全闭环` | 研磨机内是否有板、请求位和完成位、PendingWorkpiece |
| `已放到ST710但无法写M721/D200` | ST710实物、MC64连接、M721和D200实际值 |
| `通信Worker已隔离` | 对应CNC是否仍在线；通常需要重启上位机恢复该Worker |
| `旧动作已被应急取消` | 应急动作是否与当前物理状态一致，旧任务已不会继续写状态 |

不要只清PLC位或只清软件缓存。物理工件、PLC握手和软件缓存三者必须重新对齐。

## 十四、锁等待和疑似卡死判断

常见锁关键词：

```text
机械手锁
天车锁
共享区锁
中转架锁
M817锁 / M818锁 / M821锁 / M720锁
```

判断方法：

1. 搜索锁名，找到最近一次“获取/已获取”。
2. 查看持锁动作是否有对应“完成/释放”。
3. 如果动作仍有状态变化或周期等待日志，通常是条件等待，不一定死锁。
4. 如果长时间没有动作、没有异常、也没有释放日志，再检查占锁任务是否停在设备IO。
5. 多把锁场景要同时检查第二把锁等待期间，第一把锁是否在异常或取消后释放。

## 十六、当前日志的边界

1. 日志文件中的每一行没有统一时间戳，只有部分业务日志自行带时间。排查时需借助启动时间、行号和上下文判断先后。
2. 文件为追加写入，同一个版号在不同启动批次可能重复出现。
3. 状态日志经过节流，不能用“没有每500ms输出”推断“程序没有读取”。
4. `ReportStage` 成功回调不一定写入日志文件；工件追踪应以各引擎带 `IdentityText` 的动作日志为主。
5. `版号=未知` 表示当前工件数据没有完整身份，必须结合站位、直径、长度和现场确认，不能仅靠该关键词区分多块板。
6. 页面是状态展示，不是唯一事实来源。故障判断应综合日志、PLC/CNC实时值和物理现场。

## 十七、维护规则

发生以下代码变化时必须同步更新本文：

1. 新增或修改日志前缀。
2. 工件身份文本格式变化。
3. 状态机阶段、握手顺序或PLC地址变化。
4. 新增日志节流、超时、重连或应急恢复策略。

本文只描述当前源码实际输出，不作为PLC地址和完整业务协议的唯一依据。地址和握手细节仍以《全线业务逻辑详解》及 `02-通信协议手册` 为准。
