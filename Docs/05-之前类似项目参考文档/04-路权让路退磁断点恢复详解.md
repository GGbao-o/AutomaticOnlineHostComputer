## 1. 路权冲突检测算法

### 第一层：与已有路权比对（WayRightHash）

```csharp
// 已有路权: [wspos, wepos]  新任务: [spos, epos]
if (((wspos <= spos) && (wepos >= spos))   // 已有路权终点覆盖新任务起点
 || ((wspos <= epos) && (wepos >= epos))   // 已有路权起点覆盖新任务终点
 || ((spos <= wspos) && (epos >= wspos))   // 新任务覆盖已有路权起点
 || ((spos <= wepos) && (epos >= wepos)))  // 新任务覆盖已有路权终点
{
    移除该任务;  // 任何形式的重叠都算冲突
}
```

**结论**：不是简单的 StartX~EndX 重叠，而是**四种重叠情况完备检测**——包含、部分重叠、完全重叠全部覆盖。

### 第二层：新任务之间的路径交叉检测

```csharp
// 任务列表按 SourceEPos 降序排列
if (_CraneTaskInfos[index].SourceEPos > _CraneTaskInfos[index - 1].TargetEPos)
{
    移除后面的任务;  // 路径交叉冲突
}
```

后一个任务的起点比前一个任务的目标点还远 → 路径交叉 → 移除。

## 2. 障碍物让路的触发条件

**检测时机**：任务分配时（任务生成时），不是天车移动时才检测。

**检测代码**：

```csharp
foreach (CraneDGBP DGBP in CraneDGBPHash.Values)  // 遍历所有天车！
{
    int pos = DGBP.getEpos();           // 天车当前位置
    long cwidth = DGBP.getConf().Width; // 天车宽度

    if ((pos >= (task.TaskStartPos - cwidth))
     && (pos <= (task.TaskEndPos + cwidth)))
    {
        if (DGBP.getID() != task.CraneID)  // 不是执行任务的天车自己
        {
            obstacle.IsObstacle = true;     // → 判定为障碍物
        }
    }
}
```

**判定条件**：
- 天车当前位置 `pos` 落在 `[TaskStartPos - Width, TaskEndPos + Width]` 区间
- 且该天车 ≠ 被分配执行此任务的天车
- **空闲天车和忙碌天车都检测**，只要在路径区间就算挡路

**让路决策**：
- 空闲天车 → `CraneMovePosX` 移开
- 忙碌天车 → 任务被取消（加入 obstask），让路给主任务
- 让路目标 = 任务路径左边界 - 2×Width 或 右边界 + 2×Width

## 3. 退磁卡料处理

```csharp
case 28:
    if (crane.Magnetization(false))  // 退磁成功
    {
        TaskProgress = 29;
    }
    else
    {
        MagTCount++;
        if (MagTCount > 10)  // 10次失败
        {
            MagTCount = 0;
            crane.Magnetization(true);  // 先充磁一次再试
        }
    }
    break;
```

| 特性 | 说明 |
|------|------|
| 计数范围 | 每个 CraneTask 局部变量，从0开始，不是全局累计 |
| 10次 ≈ | 5秒（每次循环 Thread.Sleep(500)） |
| 超过10次 | 充磁一次 + 计数器归零 → 继续尝试退磁，**无限循环** |
| 超时保护 | **没有**！如果退磁一直失败，天车永远卡在步骤28 |
| 中断方式 | 只能操作员切手动模式（TaskPause=true） |

> ⚠️ 这是参考项目的潜在 BUG：退磁卡死无超时退出机制。

## 4. 任务断点恢复

**结论：没有断点恢复。每次重启全部从零扫描状态重建。**

### 断电后数据存活情况

| 数据 | 存储位置 | 断电后 |
|------|---------|:---:|
| 工件任务数据 | 数据库 WorkInfoList | ✅ 保留 |
| 机器状态(idle/over等) | PLC 寄存器 | ✅ 保留（PLC断电保持） |
| 天车当前位置 | 编码器 | ✅ 保留（绝对值编码器） |
| 工艺路线 | 数据库 | ✅ 保留 |
| 天车任务进度(TaskProgress) | 程序内存 | ❌ 丢失 |
| 路权信息(WayRightHash) | 程序内存 | ❌ 丢失 |
| 机器预约状态 | 程序内存 | ❌ 丢失 |

### 实际恢复行为

```
重启后：
  → 调度系统扫描所有 PLC 机器状态
  → 机器加工完了→生成下料任务
  → 机器空闲+有待处理任务→生成上料任务
  → 本质上无状态，靠轮询 PLC 重建全局状态
  → 任务进度从零开始（天车回零→重新分配任务）
```

### 启动时的安全检查

```csharp
if (GetALLCraneGoHomeSta() == false)  // 天车没回零
{
    // 超过10次检测未回零 → 切手动模式
}
// 重新扫描所有机器状态
// 重新生成任务列表
// 重新分配天车
```
