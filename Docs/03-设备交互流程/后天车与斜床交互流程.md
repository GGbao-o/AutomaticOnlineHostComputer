# 后天车与斜床交互流程

> 依据 `Line1RearFlowEngine`、`Line2RearFlowEngine`、`ModbusSkewBedService`、`FanucSkewBedService` 整理，更新时间：2026-10-11。

## 1. 设备与协议

| 线路 | 后天车 | 斜床 | 协议 |
|------|------|------|------|
| 1号线 | Crane#2（数据库站号ST102） | ST108、ST109、ST111、ST110 | 锦州迅捷PLC，Modbus TCP |
| 1号线 | Crane#2 | ST112 | FANUC FOCAS宏变量 |
| 2号线 | Crane#4（ST904） | ST606~ST610 | FANUC FOCAS宏变量 |

斜床IP和端口从数据库 `machine` 表读取；Modbus默认端口502，FANUC默认端口8193。

## 2. 调度原则

1. 主循环每500ms刷新斜床快照，然后先生成上料候选和下料候选，再决定本轮后天车执行上料、下料或等待。
2. 只有本轮信号读取成功的斜床才能参与派发，不沿用旧请求位。
3. 上料候选只检查：中转架本轮物理有板、同架位软件缓存存在、该架位未来源冻结，以及至少一台斜床为 Idle/连接正常/本轮信号新鲜/请求数据且可加工当前长度。后天车锁和 Zone 锁不属于锁外候选条件，见 2.1.1。
4. 下料必须满足：请求下料、斜床保存的 `Wp` 存在、目的料架本轮状态有效且允许放料。
5. ST108/ST606靠近中转架-斜床1碰撞区，使用 `ZoneTS`；进入中转架取料必须同时使用 `ZoneMT + ZoneTS`。
6. 调度只选择“本轮先做哪类动作”，不改变 `DoLoad` 和 `DoUnload` 的正常业务步骤、PLC地址、坐标公式、握手顺序。

### 2.1 后天车动态调度规则（2026-07-08）

后天车不再固定“下料永远优先”。当前实现先构建两个候选列表：

- 上料候选：中转架物理有板、软件缓存存在，且至少一台当前可用斜床能加工该板长度。
- 下料候选：斜床等待下料、工件身份存在、完工记录已写入或本轮写入成功、目标下料位允许放料。

然后按以下顺序决策：

1. 没有下料候选，但有上料候选：执行上料。
2. 没有上料候选，但有下料候选：执行下料。
3. 中转架物理满3个，并且存在上料候选：强制上料，给前天车腾中转架位置。
4. 中转架“可匹配板数” ≥ 2，并且下料候选少于高下料压力阈值：优先上料。
5. 下料候选数达到高下料压力阈值，并且中转架可匹配板数 ≤ 1：优先下料。
6. 其他普通情况：默认下料优先。

高下料压力阈值不是固定3，因为斜床可能坏掉或断线。当前按有效斜床数量动态折算：

| 有效斜床数量 | 高下料压力阈值 | 含义 |
|---|---:|---|
| 0~1台 | 1 | 只剩一台有效斜床时，只要它等下料就优先下料 |
| 2~3台 | 2 | 坏1~3台时，两台等下料已经是较高压力 |
| 4~5台 | 3 | 大部分斜床正常时，三台等下料才算高压力 |

这里的“有效斜床”指本轮连接正常且信号新鲜的斜床。坏床、断线床或信号未刷新成功的斜床不参与压力基数。

### 2.1.1 后天车上料前置条件（按实际执行阶段）

| 阶段 | 检查内容 | 不满足时 |
|---|---|---|
| 主循环 | 后端 `_paused=false`。 | 后端本轮不调度；不是来源冻结。 |
| 锁外候选扫描 | ① 中转架本轮物理有板；② `_rackLedger` 有该架位缓存；③ `IsHeldForManualResolution=false`；④ 存在 `Idle + Ok + SignalFresh + RqData` 且版长匹配的斜床。 | 该架位不成为候选；物理有板无缓存、长度不匹配或来源冻结均只跳过该架位，继续扫描其它架位。 |
| 派发复核 | 非阻塞取得 `_craneRearLock`，天车坐标通过启动前检查，再重新生成候选。 | 锁忙/候选变化/坐标未就绪，本轮结束；不预约来源、不删缓存。 |
| 动作内正式取料 | `TryReserve` 成功、长度再次校验、天车 X11=0，随后按 `ZoneMT → ZoneTS` 实际取得区域锁并在锁内复核预约/缓存/现场条件。 | 未发物理命令前失败：解除预约、下轮再试；已发命令后结果未知：暂停并进入人工确认。 |

**来源冻结**只表示“该中转架在 X11=1 之前发生了最终异常，不能再次取同一块板”。它不占后天车锁或 Zone 锁，不冻结整线，也不再阻止主页启动线路；恢复后只跳过该来源位。来源结案仅接受“仍在来源位”（解除冻结）和“已人工移走”（删除同一缓存）。

### 2.2 中转架顺序和不可加工板跳过

中转架仍按前天车放板到达顺序扫描，顺序来自后端缓存的 `_wpArrivalSeqs`。调度不会为了效率改变已经可加工板之间的先后顺序。

但候选扫描允许跳过“当前没有任何可用斜床能加工”的板。例如：

```text
ST105: A板, 长度超出当前所有空闲斜床能力
ST101: B板, 当前ST109可加工
ST106: C板, 当前ST110可加工
```

此时 A板不会阻塞整个后端。候选扫描会记录“ST105长度不匹配”，然后继续生成 B板、C板的上料候选。这样可以避免一根当前不可加工的板把中转架和前天车都堵住。

注意：如果 A板和 B板都能加工，仍按 A板优先，不跳到 B板。

## 3. 中转架到斜床上料

### 3.1 来源

| 线路 | 中转架 | PLC信号 |
|------|------|------|
| 1号线 | ST105/ST101/ST106 | MC63 M811/M812/M813 |
| 2号线 | ST016/ST017/ST018 | MC63 M814/M815/M816 |

后天车按缓存到达序号选择最早工件，不按固定架号抢后到工件。现场有板但软件缓存缺失、或该架位仍来源冻结时禁止盲取；后二者只跳过这个架位，不阻塞其它中转架。

### 3.2 锁顺序（2026-07-08 ZoneMT/ZoneTS）

- 主循环不再预先取得 `_transferRackLock`，该锁不再作为中转架业务互斥条件。
- `DoLoad` 内部按 `ZoneMT -> ZoneTS` 进入中转架。
- 在 `ZoneMT + ZoneTS` 持锁期间，后天车必须重新确认中转架物理有板，并确认软件缓存存在。
- 取完板、X11确认、Z轴升到0位或配置安全高度后：
  - 普通斜床：释放 `ZoneTS + ZoneMT`；
  - ST108/ST606：释放 `ZoneMT`，继续持有 `ZoneTS` 到斜床1上料交互和X+1000/配置退避完成。
- 所有Zone锁都登记在动作令牌中，正常finally和应急路径最多释放一次。

### 3.3 动作与握手

```text
读取来源缓存和坐标
  -> 后天车X11=0检查
  -> XY到中转架、Z下降、充磁
  -> X11确认吸住并CommitPickup，Z升安全
  -> XY到斜床中心并微调成功，绑定bed.Wp
  -> 等斜床请求数据
  -> 写长度/直径/堵孔/模式并确认数据完成
  -> 等请求上料
  -> Z下降，Y进入顶尖位置
  -> 写天车上料到位
  -> 等尾座夹紧
  -> 退磁，Z升安全
  -> 写天车上料完成
  -> Z回0，进入Machining，登记Completed
  -> finally按守卫完成斜床1ZoneTS侧退避及释放锁
```

锦州Modbus和FANUC地址不同，但业务顺序相同。详细地址分别见 `02-通信协议手册/斜床协议/`。

### 3.4 上料X11连续三次为0的安全恢复

后天车在中转架完成XY到位、微调、Z下降和充磁后，最多读取三次X11，后两次各下探5mm重试。三次均为有效读取0时：

1. 记录明确的“上料取板失败”状态并抛出异常；
2. 尽力退磁，然后用不可取消的动作将Z回到0位/安全位置；
3. 只有确认Z安全后，ST108/ST606才允许执行ZoneTS侧X+1000/配置距离退避；Z可能低位时禁止X横移；
4. 无论退磁、Z回升或退避是否成功，都由finally释放本动作持有的`ZoneTS`、`ZoneMT`和后天车锁；
5. 锁释放完成后暂停对应整线并弹窗，要求人工确认中转架、磁铁、Z轴、天车和工件位置，禁止自动进入下一轮。工件缓存恢复仅表示软件保留了待处理身份，不代表现场已经安全。
6. 安全告警回调完成后只生成一条`CRANE_X11_NOT_CONFIRMED`最终结构化事件。事件包含板号/序号、来源中转架、目标斜床、三次X11值、退磁、Z回安全、ST108/ST606退避、三把锁释放和暂停证据；不会把异常点与finally收尾统计成两次异常，也不会为同一弹窗额外生成`LEGACY_SAFETY_ALARM`重复行。

结构化事件中的“恢复完成”只表示所有适用的软件收尾步骤成功或按安全策略跳过，不代表磁铁、工件或设备位置已经获得现场确认。物理结论始终保持“需要人工确认”。

## 4. 斜床下料

```text
本轮读取到请求下料
  -> 获取后天车锁；ST108/ST606还要ZoneTS
  -> XY到斜床，Z下降，充磁
  -> X11确认吸住
  -> 写天车下料到位
  -> 等尾座分开
  -> Y退出顶尖位置
  -> Z升安全
  -> 写天车下料完成
  -> ST108/ST606按配置距离完成ZoneTS侧退避后释放ZoneTS
  -> 按长度/强制动平衡标志分流
```

尾座未确认分开时Y轴不能退出。工件已吸住但尚未放到下游时发生异常，后端引擎按原裁决暂停；catch可能暂存bed.Wp，但本次下料未Completed时finally会自动作废该斜床，最终Wp=null、St=Idle。

### 4.1 X11连续无板的安全恢复

后天车下降取料后最多读取三次 X11，后两次分别下探 5mm 重试。第三次仍为0时，按“工件仍在斜床、后天车未持件”处理，并且必须在仍持有后天车锁时执行：

1. 发送退磁。
2. Z轴升到配置的安全高度。
3. 两步都成功：该局部恢复曾暂存Wp/WaitingUnload并记录恢复警告；统一裁决仍会暂停本线前后端，最终finally作废为Wp=null、Idle，不会继续下料同一板。
4. 任一步失败：暂停本线并显示工件/步骤/收尾结果；最终仍自动清软件状态，但磁铁和Z位置必须人工确认，不因Idle推断安全。

该恢复只处理“X11有效读取且连续三次为0”。通信失败、X11已经确认有板、工件已离开斜床等情况仍走原来的物理阶段异常处理，不会被当成普通无板重试。

## 5. 下料分流

`Length >= 800` 或任务 `ForceBalancing=true` 走动平衡；其余走研磨上料路径。

### 5.1 1号线

| 工件 | 目标 | 前置条件 | 完成动作 |
|------|------|------|------|
| 需动平衡 | ST019 | MC63 M817=0（空闲），拿锁后二次确认；暂时不可放料持锁等待 | 放料并写 `_balWps["M817"]` |
| 不需动平衡 | ST010 | MC65 M720=1（允许放料），拿锁后二次确认；暂时不可放料持锁等待 | 放料、Z升安全、写M721=1并入研磨FIFO |

1号线分流区统一取得 `_lockM817 + _lockM720`，因为两条路径位于同一相邻区域。

### 5.2 2号线 ST020/ST021

| 工件 | 目标 | 放料允许 | 后天车完成 | 缓存 | 后续取料 |
|------|------|------|------|------|------|
| 需动平衡 | ST020 | M818=1 | 放料并Z升安全后写M819=1 | `_balWps["M818"]` | M823=1后M2取，完成写M824 |
| 不需动平衡 | ST021 | M820=1 | 放料并Z升安全后写M821=1 | `_balWps["M821"]` | M825=1后M3取，完成写M826 |

M818/M821缓存键和位置锁名称是历史命名，不代表对应PLC位仍是“有板”。2号线分流区统一取得 `_lockM818 + _lockM821`，并在拿锁后二次读取放料允许位。

## 6. Y/Z坐标

斜床顶尖Y偏移由运行配置实时计算：

```text
Y偏移 = (centerDistances[站号] - 工件长度) / 2
        + (大孔 ? largeBoreOffset : smallBoreOffset)
```

每台斜床还必须通过 `maxWorkpieceLengthMm` 长度能力检查。目标坐标叠加数据库天车偏移；取放Z按照当前引擎的直径公式计算，不能使用默认直径。

## 7. ZoneTS退出

ST108/ST606正常上料或下料完成后，后天车读取当前X，并按 `skewBed.sharedAreaRetreatX[站号]` 向右退离。配置名仍沿用历史的`sharedAreaRetreatX`，但当前实际释放的是 `ZoneTS`。

异常收尾时，如果读取位置失败、X退避失败，或因为Z已经下降/可能下降而禁止X横移，程序仍释放后天车锁和动作任务牌持有的 `ZoneTS`，并暂停弹窗说明“退避失败/未执行、ZoneTS和后天车锁已释放”。此时软件互斥已经解除，但ST108/ST606侧物理位置不一定安全，必须人工确认后再恢复或执行斜床应急。

## 8. 归位与最终清理

正常动作只在关键交接、通知与主动作归位完成后登记Completed。上料包括CNC握手后Z回0；下料包括目标交接及末尾HomeX/HomeZ。因此已启动加工或已经放下，末尾归位失败也可能触发自动作废，不能凭实物已放就判断状态会保留。

DoLoad/DoUnload的finally在Disposition!=Completed时，用CancellationToken.None尝试清该床PLC/CNC输出与参数；设备清零异常记录失败，但软件仍回Idle、Wp=null，请求/夹紧/新鲜度和恢复标记重置，清后天车任务牌。Modbus清10300～10305、10370～10374；FANUC清#800/#801/#802/#909/#1101～#1105。

不清中转架来源冻结与身份，不回滚已经写入的下游缓存/FIFO及M819/M821/M721，不撤销CNC可能已启动的加工。上料只结同线同目标的PauseOnCarrier/目标待交接；下料只结同线同来源PauseOnCarrier，目标待交接记录仍可能存在。详细过滤范围见[主文档第15章](../全线业务逻辑详解.md)。

### 8.1 Completed后的finally退避告警

ST108/ST606上料在DoHandshake及末尾Z回0成功后先登记Completed，然后进入finally的ZoneTS退避/释放。自动作废判断在这段退避之前已执行；若退避此时失败/未确认而新增暂停告警，床仍可能Machining、Wp仍存在，不能套用“告警后床必定Idle”。固定告警尾句也可能沿用自动作废提示，应以实际收尾和床状态为准。

### 8.2 分流前本线启动门禁

斜床取出并到安全Z后，在取得分流锁、发目标XY或退磁之前，EnsureLineRunningBeforeDivertAsync等待本后端_paused=false。等待持件但不拿新的分流位置锁；默认上限grinding.lineStartWaitTimeoutMs=120000ms。超时专门catch清床并告警，finally再次尝试自动清理；两次清理日志不表示两个动作。

M817/M818/M820/M720锁内二次确认暂时不可放料时保持持件、安全Z及已取得的位置锁轮询等待，不立即报异常。目的位允许后仍复核机械手2/3安全Y，再进入分流区；读失败、取消等另走原异常路径。

## 9. 下压保护与通信结果未知（当前实现边界）

后天车的 Z 下降会由公共 `CraneService` 监视 X2。X2 触发后服务急停、复位触发位并在停止稳定后读取实际 Z；实际 Z 与目标差在 `safety.pressureStopNormalPositionToleranceMm`（默认15mm）内时，服务恢复伺服并作为本次下降成功返回。超差、实际 Z 读取失败或恢复失败才抛出 `PressureStopException`，此时才由后天车按当时阶段记录 Z 可能未知并进入暂停/人工确认。无论是否正常到位，X2 本身都不表示“工件一定在磁铁上/目标位”，后续仍以充退磁和 X11/交接反馈为准。

## 10. 运动超时、来源冻结与重新启动

参与轴在配置阶段期限内未进入显示坐标容差（默认120秒、±5mm）时，CraneService尝试D4518停止并抛CraneMotionTimeoutException。原物理阶段裁决暂停，禁止未知位置下继续自动横移、回零或退磁；本次finally释放动作租约所持后天车/Zone/分流锁，并执行上述自动作废。旧版“运动超时必须保留区域锁直到人工应急”不再是当前最终行为。

来源尚未X11确认取走而被冻结时，自动作废不删除中转架账本；人工丢板后需对应来源结案。目标已经收到身份或通知时，自动作废不反向撤销这些事实；人工丢板也要核对下游身份。

主页启动不调用动作账本门禁，检查天车启动坐标后恢复前后端。请求数据=1只是候选的一项，还需要连接/新鲜度、长度匹配、有效中转架身份、来源未冻结和资源可用。不能只看到Idle就恢复：先确认旧动作退出、板去向、天车和磁铁安全、设备清零结果；再按实际来源/下游残留补做结案或应急。见[分场景现场处置](../运维/异常弹窗与现场故障处置.md)。
