# 货叉与双头镗交互流程

> 依据 `ForkService`、`BoringModbusService`、`Line1FrontFlowEngine`、`Line2FrontFlowEngine` 整理，更新时间：2026-06-27。

## 1. 设备对应

| 线路 | 货叉站号 | 双头镗站号 | 货叉协议 | 双头镗协议 |
|------|------|------|------|------|
| 1号线 | ST711 | ST103 | 三菱MC 1E，192.168.2.88:9000 | Modbus TCP，IP取数据库 |
| 2号线 | ST712 | ST402 | 三菱MC 1E，192.168.2.89:9000 | Modbus TCP，IP取数据库 |

## 2. 货叉信号

| M地址 | 方向 | 含义 |
|:---:|:---:|------|
| M900 | 货叉→中控 | 1=货叉上有板 |
| M901 | 货叉→中控 | 1=货叉在待机位 |
| M902 | 货叉→中控 | 1=货叉在Pos3天车取料位 |
| M911 | 中控→货叉 | 写1：回待机位 |
| M912 | 中控→货叉 | 写1：去双头镗送料并自动回待机 |
| M913 | 中控→货叉 | 写1：去双头镗取料并自动到Pos3 |
| M914 | 中控→货叉 | 写1：SkipBoring从待机直接到Pos3 |

中控写运动命令时先清 M911~M914，再把目标命令写1；不是对同一个命令写1后再写0。

## 3. 双头镗地址

Modbus地址=`R编号*2+1`。

| R地址 | Modbus地址 | 方向 | 格式 | 含义 |
|:---:|---:|:---:|:---:|------|
| R2041 | 4083 | 写 | uint16 | 长度，ERP整数原值，不乘100 |
| R2043 | 4087 | 写 | int | 直径*100 |
| R2044 | 4089 | 写 | int | 左堵厚*100 |
| R2045 | 4091 | 写 | int | 右堵厚*100 |
| R2046 | 4093 | 写 | int16 | 任务内孔锥度，按*100写入 |
| R2047 | 4095 | 写 | int | 内孔成活/版孔*100 |
| R2048 | 4097 | 写 | int16 | 任务圆角大小，按*100写入 |
| R6101 | 12203 | 读 | int | 请求数据 |
| R6102 | 12205 | 写1 | int | 数据下发完成 |
| R6103 | 12207 | 读 | int | 请求上料 |
| R6104 | 12209 | 写1 | int | 上料完成 |
| R6107 | 12215 | 读 | int | 请求下料 |
| R6108 | 12217 | 写1 | int | 下料完成 |

本轮下料完成时固定执行：R6108=1 → R6102=0 → R6104=0，R6108保持为1，不等待双头镗反馈。

## 4. 状态机

| 阶段 | 条件或动作 | 下一阶段 |
|------|------|------|
| Idle | M900=1、M901=1、有在途工件、当前任务机械手放行门闩=ON | Load_WriteParams或SkipBoring_GoPos3 |
| Load_WriteParams | 持续等R6101=1；写参数并写R6102=1 | WaitingRequestLoad |
| WaitingRequestLoad | 持续等R6103=1 | GoingToBoring |
| GoingToBoring | M912只发送一次，等M901=1且M900=0 | Load_WriteDone |
| Load_WriteDone | 写R6104=1 | WaitingMachine |
| WaitingMachine | 持续等R6107=1 | Unload_GoPos3 |
| Unload_GoPos3 | 写M913=1，等M902=1且M900=1，写R6108=1 | WaitingForkReturnFromBoring |
| SkipBoring_GoPos3 | 写M914=1，等M902=1且M900=1 | WaitingForkReturnFromSkip |
| WaitingForkReturnFromBoring/Skip | 前天车X11确认取走后，Z回升安全与写M911=1并行；等M901=1且M900=0 | Idle |

## 5. 正常加工顺序

```text
R6101=1
  -> 写R2041/R2043/R2044/R2045/R2046/R2047/R2048
  -> R6102=1
  -> 等R6103=1
  -> M912=1送料，货叉自动回待机
  -> 等M901=1且M900=0
  -> R6104=1
  -> 等R6107=1
  -> M913=1取料并去Pos3
  -> 等M902=1且M900=1
  -> R6108=1
  -> 立即清R6102/R6104，R6108保持为1
  -> 工件进入前天车取料阶段
  -> 前天车X11确认吸住
  -> 前天车Z回升到安全高度 与 M911=1让货叉回待机 并行
  -> 两边完成后前天车继续后续流程
```

R6101、R6103、R6107均由前端500ms主循环持续读取，不设置业务等待超时。信号未到只保持当前阶段，不暂停引擎；Modbus单次读写硬超时和写入失败暂停保护仍保留。

## 6. SkipBoring

SkipBoring不写加工参数，也不写R6102/R6104/R6108。机械手1放到货叉后写M914=1，货叉直接送Pos3。为防双头镗节拍冲突，机械手1从总上料架取料前仍要求双头镗连接正常且R6101=1。

## 7. 启动与异常条件

货叉状态机启动必须同时满足：货叉有板、在待机位、有 `_currentWp`、状态机空闲、当前任务 `_manipulatorClearedFork=true`。门闩只在退磁放板、Z回0、本线首次安全Y到位（1线默认11500、2线默认1000）且M801写入成功后打开；新任务绑定时立即关闭，不能沿用上一任务状态。

1号线门闩打开后，机械手仍持有共享锁并从11500继续回取板待机Y=1000，货叉状态机同时开始R6101/R6102/R6103/M912流程。货叉不再实时要求机械手当前Y仍等于11500，否则会错过短暂到位窗口。2号线首次安全点就是1000，门闩打开后直接释放共享锁。

前天车的判断不同于货叉启动：当前现场确认机械手1只在ST711/ST712待机端工作，前天车只进入Pos3（ST713/ST714）取料，两者物理区域不重叠。因此1/2号线前天车进入Pos3区域前不再等待机械手安全Y。机械手安全Y仍是货叉门闩打开条件的一部分：退磁放板、Z回0、本线首次安全Y到位且M801写入成功后，货叉状态机才允许启动。

首次安全点、Z回0或M801失败时门闩保持关闭，即使板已放在货叉也暂停并弹窗，不进入货叉状态机。1号线第二段回1000失败时，若实际Y仍为1000/11500安全端点则只记录警告；若处于中间或读不到位置，则同步暂停1/2号线新派发，但不回退已经打开的货叉阶段。

货叉/双头镗独立握手异常保持原暂停和阶段规则。Pos3交给前天车后，前天车的新严重异常清本趟任务、不回队，不清下一板current/货叉；持件后的原Z回升与M911并行任一失败都严重作废本趟，实物人工处理。

### 命令、反馈与缓存不能混同

- M912/M913/M914 是货叉动作命令；服务写命令时清同组其它命令位，只保留本次一位=1。它们不是“已经到双头镗/Pos3”的反馈。
- M900/M901/M902 是货叉反馈；R6101/R6103/R6107 是双头镗请求；R6102/R6104/R6108 是上位机保持型完成写。流程只有在相应反馈到达后才推进。
- current、货叉阶段、前天车队列须按动作归属处理：机械手1交接前严重失败作废本轮，独立货叉握手异常保持原阶段；前天车不因旧趟失败清新货叉周期。软件身份不能替代实物。
- 写R或写M成功仅表示本次通信成功返回。CNC/货叉是否真正消费命令，以后续请求、位置和前天车X11交接为准；响应未知时进入原异常暂停处理。

## 8. 页面状态

- 货叉：M900、M901/M902、当前M911~M914命令。
- 双头镗：R6101、R6102、R6103、R6104、R6107、R6108。

R6108置1后保持，500ms页面快照应持续显示R6108=1；日志会记录“下料完成已发送，R6108保持为1，R6102/R6104已清零”。

## 9. 近期新增：ST007长度校验与手动货叉

机械手1取板前读D100比对Length，误差大于配置容差拒取；D100=0不可比对仅日志，任务Length/Diameter非正严重拒取。严重异常清匹配current/来源、暂停；仍属本周期且无货叉握手执行时尝试清M911～914/R6102/4/8。总派发仍等真实M800=0，不复活旧入线任务。

运动参数设置页增加独立1/2号货叉选择、刷新状态及M911回待机、M912送料回待机、M913取料到Pos3、M914待机直接到Pos3四按钮。手动发送同组清其他命令再置目标位；不补写双头镗参数/完成位，不重置自动阶段、缓存或业务锁，也不等待动作整体完成。界面自身Busy不等于与自动引擎互锁，现场须先暂停并确认旧自动动作退出。详见[货叉PLC协议](../02-通信协议手册/货叉及辅助PLC协议_三菱MC.md)。

取板、严重作废及已交接保护的现行规则见[X11统一说明](../运维/X11充磁前探测与异常作废.md)，包括先探测再充磁、来源代次和动作版本保护；本文件的信号地址及正常握手顺序保持。
