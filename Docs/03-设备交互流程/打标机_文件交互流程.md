## 动作与文件并行

```text
Pos3放磁三位置探测 → 有板后充磁/后X11确认 → Z上升与M911并行完成
 → ZoneMT内XY到打标位/微调 → Z下降/退磁
 → Z升打标退让高度 与 删除旧B并写A 并行
 → 两任务成功 → 每500ms等B，最长1小时
 → 打标位XY/微调、确认放磁后Z下降、三位置探测、充磁/后X11确认、Z回升
 → 删除B → 拿ZoneTS并在ZoneMT+ZoneTS内选择/复核中转架
 → 放板、Z安全、写后端OnRackPlaced身份 → 释放区域锁/归位
```

A只携带MarkingContent与Diameter，不是全套ERP身份传递。身份由当前前天车WorkpieceCache继续保存；B仅存在判断。打号期Z目标为markerZ−300加偏移，中转架安全释放条件按对应前端实现，不能替换为任意“安全高度”。

## 分阶段异常

1. Pos3取板尚未发物理命令且明确未取：原裁决可将同一工件放回前天车队头；不是所有异常都弹窗停线。
2. 已放打标位但A失败/B超时：冻结弹窗显示打标机→打标机；业务账本最后运动目标可仍是之前记录，弹窗另列失败步骤，避免误认失败发生在上一次运动。
3. 打标取回失败：来源为打标机，目标中转架尚未选择时明确显示未确定；选择后冻结实际目标。
4. 中转架放板与写缓存失败：若实物已放下，不自动当作Pos3未取回队；须对齐实际架位及后端身份。
5. 所有阶段按原finally释放本次已取得的ZoneMT/ZoneTS和前天车锁；释放锁不表示现场已经退出碰撞区。

前天车弹窗只读独立连接的XYZ、X6/X7/X11/X2，不发运动或握手。不得因旧板位于打标机就清下一块板的_currentWp或货叉阶段。具体处置见[现场故障说明](../运维/异常弹窗与现场故障处置.md)。

## 当前严重异常收尾

本趟严重失败暂停本线前后端、不回Pos3队列，清匹配旧队列残留、本趟任务牌和人工续搬入口；原事故阶段/板号/文件原因保留详情。保护下一板current/货叉及已成功中转缓存交付，不猜测回滚。A/B文件清理仍按原协议，异常不统一删文件；现场须核对旧文件与实物。详见[统一取板规则](../运维/X11充磁前探测与异常作废.md)。

取板、严重作废及已交接保护的现行规则见[X11统一说明](../运维/X11充磁前探测与异常作废.md)，包括先探测再充磁、来源代次和动作版本保护；本文件的信号地址及正常握手顺序保持。
