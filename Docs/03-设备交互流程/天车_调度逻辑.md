## 1/2号线及研磨启动与恢复准入（2026-10-23）

主页面启动/恢复1号线实时读天车1/2，2号线读天车3/4；两台D5006、D5007、D5008全部严格等于1才执行本线前后端Start/Resume。任一非1或读失败/超时，弹窗列出两台实际结果，本次不启动，不清工件或PLC输出。

研磨启动/恢复只读取配置`grinding.craneNo`的天车（默认5号），同样要求D5006/7/8三值全==1；非1、读取失败或5秒超时均弹窗拒绝，不改变FIFO/Pending或机床状态。

1/2号线启动、前天车出队、后天车上下料派发，以及研磨启动和上下料派发前的旧XYZ显示坐标全零保护均已删除，显示0/0/0不再据此阻止上述线路。不新增运行中回原点轮询，其他运动/下压/业务检查保留。细节、界面非0显示与启动==1的区别见[线路启动回原点状态检查](../运维/2026-10-23线路启动回原点状态检查.md)。

## 绝对位移调度流程

上位机自行控制移动的完整流程（`CraneService.MoveAbsoluteAsync`）：

```
1. EnsureManualModeAsync: D4001=2, D4500=2
2. 写目标坐标（DINT 小端）:
   X → D3102~D3103
   Y → D3104~D3105
   Z → D3106~D3107
3. 读当前 Z，判断升降方向
4. Z↓ → 开接液盘(D4512=2→0) → 等500ms
5. 按方向触发:
   Z↓: 先触发XY(D4522/D4521=2) → 等XY到位 → 再触发Z(D4520=2)
   Z↑: 先触发Z(D4520=2) → 等Z到位 → 再触发XY(D4522/D4521=2)
   Z不变: 同时触发XYZ
6. 轮询 D5018/D5022/D5025，等全部到位(容差±5)
   Z下降的最终轮询每约200ms检查 X2 下压限位；没有Z目标或Z上升时约500ms轮询
   超时仍未到位 → 抛出异常，由上层按工件物理状态暂停或人工处理
7. finally: 用不可取消令牌复位本次参与轴的触发(D4520~D4522=0)
   Z↑ → 关接液盘(D4513=2→0)
```

## 当前引擎调度层（2026-10-11）

实际自动入口是Line1/2FrontFlowEngine、Line1/2RearFlowEngine、GrindingFlowEngine及BalancingFlowEngine。前天车只从货叉Pos3取料，双头镗送料/取料由货叉执行。

各引擎读取station_coords/machine的缓存坐标、叠加天车偏移、按任务直径计算Z并设置本趟速度。共享机械手1锁、前后天车动作锁、ZoneMT/ZoneTS及分流位置锁约束跨设备动作；CraneService本身不提供同设备全程运动互斥。

ProductionFlowEngine.MoveCraneToStationAsync、MoveManipulatorToStationAsync及ReserveStation等通用封装仍保留在源码，但没有接入主页当前生产启动链路。它们的工位预约、30秒等待及CheckSafetyAsync不能写成所有当前天车自动动作的准入条件。

机械手同样复用CraneService，X传-1跳过；Y/Z和充退磁/接液盘调用按具体流程决定。手动页连接与自动引擎未统一运动锁，不能从页面Busy推断自动设备已停。

正常取放XY后共享XAbsFineTuneHelper按配置对X/Y绝对编码器做联合稳定检查和微调。斜床下料按板长/孔型修正Y绝对目标，研磨四处调用不叠加该斜床Y偏移。见[配置与微调核对](../运维/配置生效与XY微调核对.md)。

## 当前源码的确认边界

### 到位的定义

`MoveAbsoluteAsync` 不以“写了触发位”或固定延时作为到位。它持续读取 D5018/D5022/D5025 的实际显示坐标，所有参与轴进入目标 `±tolerance`（默认 ±5）才返回。读状态失败不会按到位处理，而是在本次等待期限内继续尝试；最终仍无法满足则抛超时。

### X2 下压的定义

X2 只在 Z 下降的最终轮询期间读取。触发后由上位机写 D4523=2→0、D4518=2→0、复位绝对触发位，等待停止稳定并读取实际 Z。实际 Z 与本次目标差在 `safety.pressureStopNormalPositionToleranceMm`（默认15mm）内时，公共服务恢复伺服并把本次下降作为成功返回；超出阈值、读不到 Z 或恢复失败才抛出 `PressureStopException`。它不是 PLC 自动置位的握手，也不证明工件已被磁铁吸住；正常到位后仍必须继续原流程的充/退磁与 X11 证据。

### 并发与触发残留

`CraneService` 只有连接/断线串行化，没有每台设备的运动互斥锁。同一天车/机械手的动作目标和触发位必须由引擎动作锁、位置锁或页面互斥保证不并发写入。若通信故障使旧触发位 `2→0` 的复位结果未知，下一次动作前不能仅凭内存认为旧命令已清除；应先确认实际XYZ、报警/伺服状态和相关触发位，再恢复自动流程。

### 超时口径（2026-07-28）

自动天车（#1~#5）从 `motion_settings.json` 的 `absMove.xyTimeoutMs`、`absMove.zTimeoutMs` 读取超时；默认都为 **120000ms**。这两个值是阶段上限：XY-only 最多120秒，Z-only最多120秒；复合动作先完成的阶段最多120秒，后续阶段重新计时最多120秒。`±5mm` 到位容差不变。机械手仍可通过调用参数覆盖超时，不能把天车的120秒默认值误套到机械手。

超时不再抛普通 `TimeoutException`，而是抛 `CraneMotionTimeoutException`，其中包含天车名、阶段、目标XYZ、最后成功状态、未到位轴和D4518停止命令结果。服务会先以不可取消令牌尝试 `D4518=2→0` 停止运动，再读取一次最终状态；随后 finally 仍复位本次D4520~D4522触发位。上层不得因“目标已写入”推断天车已到位。

后天车动作运动超时按原裁决暂停，未知位置下不继续自动运动；finally释放动作租约持有的锁，并在非Completed时尝试设备清零、清本床Wp及Idle。来源冻结/下游身份仍可能残留。前天车异常不执行该自动作废；研磨上/下料非Completed清目标机Pending及Idle。软件锁释放与Idle都不是现场安全证明，必须先确认实物、位置、磁铁及设备清零结果。
