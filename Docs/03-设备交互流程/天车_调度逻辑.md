# 天车调度逻辑

> 本项目使用「绝对位移模式」：上位机直接写目标坐标 + 触发绝对移动，自行控制整个到位流程。
> 详细寄存器定义见 `Docs/02-通信协议手册/天车手动控制协议_完整寄存器.md`。

## 绝对位移调度流程

上位机自行控制移动的完整流程（`CraneService.MoveAbsoluteAsync`）：

```
1. EnsureManualModeAsync: D4001=2, D4500=2
2. 写目标坐标（DINT 小端）:
   X → D3102~D3103
   Y → D3104~D3105
   Z → D3106~D3107
3. 读当前 Z，判断升降方向
4. Z↓ → 开接液盘(D4512=2→0) → 等500ms
5. 按方向触发:
   Z↓: 先触发XY(D4522/D4521=2) → 等XY到位 → 再触发Z(D4520=2)
   Z↑: 先触发Z(D4520=2) → 等Z到位 → 再触发XY(D4522/D4521=2)
   Z不变: 同时触发XYZ
6. 轮询 D5018/D5022/D5025，等全部到位(容差±5)
   Z下降的最终轮询每约200ms检查 X2 下压限位；没有Z目标或Z上升时约500ms轮询
   超时仍未到位 → 抛出异常，由上层按工件物理状态暂停或人工处理
7. finally: 用不可取消令牌复位本次参与轴的触发(D4520~D4522=0)
   Z↑ → 关接液盘(D4513=2→0)
```

## 引擎调度层

`ProductionFlowEngine.MoveCraneToStationAsync` 在天车绝对移动之上增加：

1. 查 `station_coords` 缓存取目标坐标（数据库 `machine` 表）
2. 预约目标工位（防多天车同时去同一工位）
   - 已被占 → 等待最多 30s → 超时放弃
3. `CheckSafetyAsync` 安检（忙闲 D5006 / 故障 D5009 / 伺服报警 D5011 / 有版 D5029）
4. `SetAbsSpeedAsync` 写入 9 个速度寄存器
5. `MoveAbsoluteAsync` 执行绝对移动
6. 读到位坐标 → 偏差日志
7. finally: 释放工位预约；实时坐标只显示和参与安全判断，不写数据库

## 机械手调度

三台小机械手同样使用 CraneService（PLC 寄存器地址完全相同），但 X 轴传 -1 跳过：

- `MoveManipulatorToStationAsync`: 只取 Y/Z 坐标，`MoveAbsoluteAsync(-1, yTarget, zTarget)`
- 机械手与天车复用同一寄存器布局；是否调用充磁、退磁或接液盘由具体流程决定，不能由服务类型推断。

## 预约互斥

- 天车/机械手去工位前先 `ReserveStation(stationCode, ownerName)`
- 操作完成或异常后在 finally 中 `ReleaseStation`
- 同一预约者重复预约同一工位幂等（直接返回 true）

## 当前源码的确认边界

### 到位的定义

`MoveAbsoluteAsync` 不以“写了触发位”或固定延时作为到位。它持续读取 D5018/D5022/D5025 的实际显示坐标，所有参与轴进入目标 `±tolerance`（默认 ±5）才返回。读状态失败不会按到位处理，而是在本次等待期限内继续尝试；最终仍无法满足则抛超时。

### X2 下压的定义

X2 只在 Z 下降的最终轮询期间读取。触发后由上位机写 D4523=2→0、D4518=2→0、复位绝对触发位并抛出 `PressureStopException`。它不是代码中“PLC 自动置D4523=1”的握手，也不是物理到位确认。下压后的恢复方法不复核实际 XYZ、不自动抬Z；上层必须按当时工件和Z状态决定暂停、受控抬升或人工确认。

### 并发与触发残留

`CraneService` 只有连接/断线串行化，没有每台设备的运动互斥锁。同一天车/机械手的动作目标和触发位必须由引擎动作锁、位置锁或页面互斥保证不并发写入。若通信故障使旧触发位 `2→0` 的复位结果未知，下一次动作前不能仅凭内存认为旧命令已清除；应先确认实际XYZ、报警/伺服状态和相关触发位，再恢复自动流程。

### 超时口径（2026-07-28）

自动天车（#1~#5）从 `motion_settings.json` 的 `absMove.xyTimeoutMs`、`absMove.zTimeoutMs` 读取超时；默认都为 **120000ms**。这两个值是阶段上限：XY-only 最多120秒，Z-only最多120秒；复合动作先完成的阶段最多120秒，后续阶段重新计时最多120秒。`±5mm` 到位容差不变。机械手仍可通过调用参数覆盖超时，不能把天车的120秒默认值误套到机械手。

超时不再抛普通 `TimeoutException`，而是抛 `CraneMotionTimeoutException`，其中包含天车名、阶段、目标XYZ、最后成功状态、未到位轴和D4518停止命令结果。服务会先以不可取消令牌尝试 `D4518=2→0` 停止运动，再读取一次最终状态；随后 finally 仍复位本次D4520~D4522触发位。上层不得因“目标已写入”推断天车已到位。

后天车上/下料收到该异常时进入“位置未知安全占用”：暂停引擎、红色告警、保留工件身份/来源缓存和动作租约所持的后天车、ZoneMT、ZoneTS、分流锁；不回零、不退磁、不恢复缓存、不自动重试。只有操作员确认现场并执行斜床应急恢复后，才释放这些锁。
