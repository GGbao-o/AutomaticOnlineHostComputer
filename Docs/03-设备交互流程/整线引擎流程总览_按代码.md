# 整线引擎流程总览（按当前代码）

> 本文只保留跨引擎数据流和关键握手，详细前置条件与异常分支见根目录《全线业务逻辑详解》和《全线设备运动前置条件检查表》。更新时间：2026-06-28。

## 1. 引擎组成

| 引擎 | 主要设备 | 输出到下游 |
|------|------|------|
| Line1FrontFlowEngine | 机械手1、1号线货叉、ST103双头镗、天车1、打号机1、1号线中转架 | Line1Rear中转架缓存 |
| Line2FrontFlowEngine | 机械手1、2号线货叉、ST402双头镗、天车3、打号机2、2号线中转架 | Line2Rear中转架缓存，同时发布MC63后端握手快照 |
| Line1RearFlowEngine | 天车2、ST108~ST112 | M817缓存或研磨FIFO |
| Line2RearFlowEngine | 天车4、ST606~ST610 | M818/M821缓存 |
| BalancingFlowEngine | 机械手2、机械手3、MC63、MC65 | 动平衡入口或研磨FIFO |
| GrindingFlowEngine | 天车5、ST701~ST704、MC64、MC65 | ST710研磨下料架 |

## 2. 正常工件数据流

```text
任务队列
  -> 总上料架M800
  -> 机械手1
  -> 货叉待机位
  -> 双头镗（或SkipBoring）
  -> 货叉Pos3
  -> 前天车
  -> 打号机
  -> 中转架
  -> 后天车
  -> 斜床
  -> 长板/强制动平衡：ST019或ST020 -> M2 -> ST008 -> 人工动平衡 -> ST009
  -> 短板：1号线直接ST010；2号线ST021 -> M3 -> ST010
  -> 传送带测长 -> ST709
  -> 研磨天车 -> ST701~ST704
  -> ST710
```

每次物理交接同时包含PLC信号和 `WorkpieceCache` 软件缓存。PLC负责“允许/完成”，缓存负责“这块板是谁和参数是多少”，两者不能互相替代。

## 3. 前端流程

### 3.1 机械手1

两条线共享同一个机械手锁。只有总上料架请求取料、缓存有任务、货叉在待机且无板、双头镗在线并请求数据、机械手1已空闲时才取料。机械手放到货叉并回安全Y后才写M801取料完成。

### 3.2 货叉与双头镗

正常路径：`R6101 -> 参数 -> R6102 -> R6103 -> M912 -> R6104 -> R6107 -> M913 -> R6108`。SkipBoring写M914直接去Pos3，但取总上料架前仍要求双头镗在线且R6101=1。详细状态机见《货叉与双头镗交互流程》。

前端主循环对货叉普通状态和双头镗R6101~R6108采用“单轮一次读取、多处复用”。快照不会跨轮保存；取料前货叉确认、R6103紧轮询、机械手安全位、锁内目的位和X11仍直接读取设备。写入货叉动作命令后，本轮旧货叉快照立即失效。

### 3.3 前天车

前天车从Pos3取料，经打号机后选择第一个空中转位。进入打号/中转共享区前取得 `SharedAreaLock`，放料成功后把同一个工件对象写入对应后端缓存。

打号机UNC共享目录的页面在线状态由独立后台线程每5秒单飞探测，探测阻塞不会占住前端主循环；真正开始文件握手前仍实时确认共享目录可访问。

## 4. 后端流程

后端主循环下料优先。上料时必须同时有中转架现场有板和软件缓存，并选择当前请求数据且能加工该长度的斜床。ST108/ST606额外参与共享区互斥。

斜床下料后：

| 线路/工件 | 去向 | 关键通知 |
|------|------|------|
| 1号线长板或强制动平衡 | ST019 | M817=0空闲后放料，写M817缓存 |
| 1号线短板 | ST010 | M720=1后放料，写M721和研磨FIFO |
| 2号线长板或强制动平衡 | ST020 | M818允许，放后写M819和M818缓存 |
| 2号线短板 | ST021 | M820允许，放后写M821和M821缓存 |

详细斜床握手、锁顺序和共享区退避见《后天车与斜床交互流程》。

## 5. ST020/ST021 双握手

| 位置 | 后天车放料允许 | 后天车放料完成 | 机械手取料允许 | 机械手取料完成 |
|------|------|------|------|------|
| ST020 | M818 | M819 | M823 | M824 |
| ST021 | M820 | M821 | M825 | M826 |

八个位都来自MC63的M816对齐字。M818/M821软件缓存键继续保留历史名称，但M818/M821这两个PLC位已经分别是“ST020允许放料”和“ST021放料完成”。

## 6. 动平衡流程

### 6.1 M2

- 来源：ST019的M817有板，或ST020满足M823=1且M818缓存存在。
- 目的：ST008，必须M710=1允许放料，拿锁后再次确认。
- ST020来源吸住并Z升安全后写M824=1。
- 放到ST008并Z升安全后写M711=1。

### 6.2 M3

- 来源：ST009的M700=1，或ST021满足M825=1且M821缓存存在。
- ST021缓存存在时优先处理，防止抱板穿越实体工件。
- 目的：ST010，必须M720=1，拿锁后再次确认。
- M700来源吸住并Z升安全后写M701；ST021来源写M826。
- 放到ST010并Z升安全后写M721，再写研磨FIFO。

MC63或MC65任一本轮快照失败时，M2/M3本轮都不派发。

## 7. 研磨流程

研磨主循环先处理下料，再处理上料：

1. MC65 M730=1确认ST709有板，研磨FIFO必须有对应工件。
2. 研磨天车从ST709取料，吸住后写MC65 M731=1。
3. 空闲且请求数据的研磨机接收参数并完成上料握手。
4. 研磨机请求下料时，必须先确认MC64 M720=1且M730=1。
5. 天车把成品放到ST710，Z升安全后写MC64 M721=1并写D200直径。

## 8. 锁与安全原则

- 机械手1锁在1/2号线前端共享。
- 每条线的前后天车共享中转架锁和共享区锁。
- ST019/ST020/ST021/ST010使用独立位置锁，跨区域路径按固定顺序拿锁。
- X11读取失败按通信异常处理，不能等价为“磁铁无板”。
- 目的位在真正放料前必须二次确认。
- 工件已经吸住、已经放下但PLC未确认、或关键缓存写入失败时，暂停并保留现场状态。
- 应急任务牌只阻止旧任务继续回写软件状态，不能代替现场物理停机确认。
