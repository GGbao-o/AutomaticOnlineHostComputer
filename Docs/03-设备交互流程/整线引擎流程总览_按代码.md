## 2. 正常工件数据流

```text
主页面任务行（ERP导入/人工新增）
  -> 点击启动后进入总上料架全局FIFO
  -> 全局调度器确认M800=1并选择1/2号线
  -> 对应线路前端缓存
  -> 机械手1
  -> 货叉待机位
  -> 双头镗（或SkipBoring）
  -> 货叉Pos3
  -> 前天车
  -> 打号机
  -> 中转架
  -> 后天车
  -> 斜床
  -> 长板/强制动平衡：ST019或ST020 -> M2 -> ST008 -> 人工动平衡 -> ST009
  -> 短板：1号线直接ST010；2号线ST021 -> M3 -> ST010
  -> 传送带测长 -> ST709
  -> 研磨天车 -> ST701~ST704
  -> ST710
```

每次物理交接同时包含PLC信号和 `WorkpieceCache` 软件缓存。PLC负责“允许/完成”，缓存负责“这块板是谁和参数是多少”，两者不能互相替代。

> 阅读路径：设备地址、功能码和单设备写入语义见 `02-通信协议手册`；跨设备交接、锁和缓存见本目录；总上料派发、异常暂停与页面任务终点见《全线业务逻辑详解》。若历史文档与源码不一致，以地址定义、设备服务和对应流程引擎为准。

### 2.1 ERP任务、页面任务行与制造终点

ERP 文件中一行成功导入后即生成主页面任务行，并从待导入文件中移除；这仅表示任务已被软件接收。任务行启动后才进入全局 FIFO，物理流程由此开始。

主页面任务行的自动隐藏也不是统一的“完工删除”：长板或强制动平衡任务在机械手2已放至 `ST008/M710`、且 M711 成功写入后，上报 `动平衡加工中 ST008/M710` 并结束原任务行的可追踪显示；人工动平衡后的 `M700/ST009` 输出顺序可能改变，不能可靠映射回原 ERP 行。未做动平衡的短板则保持任务行，直到研磨完成、工件下至 `ST710`、完成 M721 和研磨机下料完成确认后才上报 `已完成` 并隐藏。

上述自动隐藏只影响页面显示，不清 PLC 信号、软件缓存、位置锁或引擎状态。完整的路由条件、失败时保留任务行的规则，见《全线业务逻辑详解》“ERP任务文件、主页面任务行与实际制造完成是三件不同的事”。

## 3. 前端流程

### 3.1 总上料架全局调度器

全局调度器是M800物理板与软件任务之间的唯一绑定点。它只处理全局FIFO队头，不跳过任务；M800=1且线路能力、运行状态和前端准入均满足时，才把队头写入某条线路前端缓存。两条线路前端不能直接从主页面任务列表取任务。

每次成功派发后，调度器进入M800复位门：必须读取到M800=0，才能接受下一次M800=1。复位门独立于FIFO，即使一批任务的最后一块已经派发、FIFO为空，调度器仍持续读取M800，避免在批次空档漏掉复位。FIFO为空且复位门已解除时才停止主动读取。

关键状态顺序：

```text
任务启动 -> 入全局FIFO
  -> 等上一块M800复位（如有）
  -> 确认M800=0，解除复位门
  -> 等新板M800=1
  -> 判断任务启动状态、线路能力、线路运行状态和前端准入
  -> 两条线都可接时按压力选择，压力相同交替选择
  -> 写入1/2号线前端缓存
  -> 再次进入M800复位门
```

禁止在FIFO为空时直接清复位门；上一块物理板可能仍保持M800=1，这样做会产生重复派发风险。

2026-07-07补充：全局调度器每1秒读取一次M800/D100并重新评估队头任务。线路前端准入由 `GetFrontDispatchReadiness()` 返回，只消费线路引擎已经维护的内存快照，不直接读货叉、双头镗PLC，也不拿机械手或天车动作锁。硬性准入包括：线路运行未暂停、前端缓存为空、`_currentWp=null`、`_forkPhase=Idle`、货叉快照有效且待机无板、双头镗快照有效且R6101=1。R6103不参与分线，因为R6103依赖写参数和R6102完成，分线前等待它会死等。

前天车队列和正在执行的前天车任务只计入压力，不直接禁止接板：工件进入前天车/打号/中转架通道后，货叉和双头镗前段可以继续流水。真正写入线路缓存前会二次读取选中线路准入快照，若状态变化则保持全局FIFO队头等待。主页面任务栏会显示具体原因，例如“物理板已到位，等待可接线路：1号线=货叉仍有板；2号线=双头镗R6101未请求数据”。

#### 当前分线规则（以运行配置和代码为准）

分线只在总上料架的全局 FIFO 队头、M800=1 且上一块的 M800 复位门已解除时执行；不会跳过队头把后面的任务先分到空闲线。

1. **大直径优先级最高**：运行配置 `skewBed.largeDiameterLine1OnlyMm` 当前为 **280mm**。直径 `>=280mm` 的工件强制只走 1 号线，原因是机械手1去 2 号线货叉时会穿越该区域，需避免大板与 2 号线货叉区域内工件发生干涉。即使 2 号线空闲、且其斜床能加工，也**不得**改派 2 号线；1 号线没有相应长度能力或暂不可接板时，队头保持等待。配置设为 `0` 或负数可关闭这条强制规则。
2. **先看版长能力**：每条线只要至少有一台本线斜床的 `maxWorkpieceLengthMm >= 任务版长`，即视为该线具备加工能力。当前运行配置为：

   | 线路 | 斜床与最大版长(mm) |
   |---|---|
   | 1号线 | ST108=1350，ST109=1300，ST111=1300，ST110=1300，ST112=1170 |
   | 2号线 | ST606=1280，ST610=1255，ST607/ST608/ST609=1200 |

   如果仅一条线具备长度能力，只能等待该线可接板；两条线都没有能力则不派发。
3. **两线都有长度能力时再看前端准入**：只有一条线可接就选那条；两条都不可接则等待。准入条件是：线路运行未暂停、前端缓存为空、`_currentWp` 为空、货叉/双头镗阶段为 Idle、货叉快照新鲜且待机无板、双头镗快照新鲜且 `R6101=1`。
4. **两线都可接时负载均衡**：前端压力较小的线路优先。压力 = 前端缓存数 + 前段在途 `_currentWp` + 前天车队列数 + 前天车当前活动标志；压力相同则按上一次成功分线结果交替，首次平压会选 1 号线。
5. **最终二次确认**：选线后、写入线路前端缓存前再读取一次该线路准入快照；若已变化为不可接，工件仍留在全局 FIFO 队头，不会误派。

### 3.2 机械手1

两条线共享同一个机械手锁。只有总上料架请求取料、缓存有任务、货叉在待机且无板、双头镗在线并请求数据、机械手1已空闲时才取料。机械手放到货叉后先退磁并确认Z回0，再到本线货叉释放安全Y：1号线ST711先到11500，2号线ST712到1000。成功写M801后打开当前任务货叉门闩；1号线货叉立即开始握手，机械手保持共享锁继续从11500回取板待机Y=1000，到位后才释放锁。2号线无需第二段回位。

### 3.3 货叉与双头镗

正常路径：`R6101 -> 参数 -> R6102 -> R6103 -> M912 -> R6104 -> R6107 -> M913 -> R6108`。SkipBoring写M914直接去Pos3，但取总上料架前仍要求双头镗在线且R6101=1。详细状态机见《货叉与双头镗交互流程》。

前端主循环对货叉普通状态和双头镗R6101~R6108采用“单轮一次读取、多处复用”。快照不会跨轮保存；取料前货叉确认、R6103紧轮询、锁内目的位和X11仍直接读取设备。写入货叉动作命令后，本轮旧货叉快照立即失效。

### 3.4 前天车

当前现场确认机械手1活动端为ST711/ST712，前天车取料端为Pos3（1号线ST713、2号线ST714），两者物理区域不重叠。前天车进入货叉Pos3区前不再读取/等待机械手1安全Y；机械手1的安全Y仍用于机械手送叉后打开货叉门闩和页面状态诊断。

前天车从Pos3取料，经打号机后选择第一个空中转位。Pos3交接时，1、2号线都必须先由X11确认吸住；现场确认Pos3低位持板时货叉回待机不会碰天车/工件/取料夹具，因此X11确认后天车Z轴回升到安全高度与M911货叉回待机并行执行，两边都完成后才继续去打号机。打号阶段只持有 `ZoneMT`，进入中转架前再取得 `ZoneTS`，中转架放料完成且Z安全后释放 `ZoneTS + ZoneMT`；放料成功后把同一个工件对象写入对应后端缓存。

打号机UNC共享目录的页面在线状态由独立后台线程每5秒单飞探测，探测阻塞不会占住前端主循环；真正开始文件握手前仍实时确认共享目录可访问。

## 4. 后端流程

后端主循环已改为动态调度：先生成上料候选和下料候选，再按中转架压力、下料压力和长度匹配决定本轮上料或下料。锁外上料候选必须同时有中转架本轮物理有板、软件缓存、未来源冻结，以及 `Idle + Ok + SignalFresh + RqData` 且可加工该长度的斜床；后天车锁和 Zone 锁在派发/动作内才实际取得。当前第一块板无可用斜床能加工、无缓存或来源冻结时，候选期只跳过该架位，继续寻找后续可加工板。来源冻结不再拦截线路启动，只阻止同一架位被重复取料。ST108/ST606使用 `ZoneTS`，进入中转架上料使用 `ZoneMT + ZoneTS`。

斜床下料后：

| 线路/工件 | 去向 | 关键通知 |
|------|------|------|
| 1号线长板或强制动平衡 | ST019 | M817=0空闲后放料，写M817缓存 |
| 1号线短板 | ST010 | 取得M817/M720锁后二次读M720；M720=0时持板等待，恢复为1后放料，写M721和研磨FIFO |
| 2号线长板或强制动平衡 | ST020 | M818允许，放后写M819和M818缓存 |
| 2号线短板 | ST021 | M820允许，放后写M821和M821缓存 |

详细斜床握手、锁顺序和共享区退避见《后天车与斜床交互流程》。

### 自动天车运动超时

天车XY和Z均以实际显示坐标目标`±5mm`到位，默认每阶段120秒。超时公共层会尝试D4518伺服停止并上报目标、最后XYZ和未到位轴。前天车、后天车、研磨天车均暂停所属引擎并禁止自动重试；后天车还保留当前动作的区域/分流锁为安全占用，必须斜床应急恢复后才可释放。

## 6. 动平衡流程

### 6.1 M2

- 来源与优先级：ST020（M823=1且M818软件缓存存在）优先；仅M818缓存不存在时，才允许从 ST019（M817=1且M817缓存存在）取料。两个缓存都是工件身份与直径，不把M818 PLC位当有板信号。
- 派发共用前提：MC63、MC65本轮完整快照有效，M2不忙、机械手2已连接、M710=1允许放料。
- 路径安全：M817→ST008会经过ST020区域，必须等2号和4号后天车均在 `X <= RearCraneSafeX`；ST020来源只等4号后天车离开。
- 锁和二次确认：M817拿M817+M818路径锁；ST020只拿M818锁，且拿锁后再次确认M823。取料前必须有来源缓存、读坐标并确认X11无残留。
- 速度：每趟任务在首次Y移动前按 `manipulatorSpeeds.2` 完整写一次三轴绝对速度；同趟后续Y/Z、X11重试、放料和回安全位不重复写。
- 闭环：取料→X11确认→Z升安全；ST020来源写M824=1。抱板去ST008前二次确认M710；退磁放料后释放来源/路径锁、Z升安全、清来源缓存、写M711=1，最后Y回安全位。已持件、已放但M711未确认等状态均暂停并保留人工确认信息。

### 6.2 M3

- 来源与优先级：ST021（M825=1且M821软件缓存存在）优先于 ST009/M700，防止从M700抱板穿越ST021实体工件。仅M821缓存不存在时才取M700。
- 派发共用前提：MC63、MC65本轮完整快照有效，M3不忙、机械手3已连接、M720=1允许放料。M821来源还必须等4号后天车在 `X <= RearCraneSafeX`；M700来源不经过后天车区域。
- 锁和数据：无论来源均先按M821→M720顺序拿两把锁。M821来源拿锁后再次确认M825并从缓存取完整身份/直径；M700来源从MC65 D100取直径，身份未知、长度先记0，任何数据缺失均暂停而不用默认直径。
- 速度：每趟任务在首次Y移动前按 `manipulatorSpeeds.3` 完整写一次三轴绝对速度；同趟后续Y/Z、X11重试、放料和回安全位不重复写。
- 闭环：取料→X11确认→Z升安全；M821来源写M826=1，M700来源写M701=1。抱板去ST010前二次确认M720；退磁放料并Z升安全后写M721=1、通知研磨FIFO，M821来源最后清缓存，随后Y回安全位并释放两把位置锁。已持件、M721未确认或FIFO未写入均暂停并保留人工确认信息。

MC63或MC65任一本轮快照失败时，M2/M3本轮都不派发。

### 6.3 在制工件只读快照

“在制工件”页面沿正常数据流复制当前内存身份，位置对应关系如下：

| 数据流阶段 | 页面证据来源 |
|------|------|
| 尚未分线 | Home全局FIFO |
| 已分线、机械手1/货叉/双头镗处理中 | 1/2号线前端缓存与`_currentWp` |
| 等待或正在执行前天车 | 前天车FIFO与天车任务快照 |
| 前后端交接 | 中转架软件缓存 + 前端最近维护的物理有板内存信号 |
| 斜床加工/等待下料 | 斜床状态机工件上下文 |
| 后天车动作 | 后天车任务快照 |
| 动平衡等待 | `_balWps`缓存 |
| M2/M3已从缓存取出、动作尚未结束 | 带动作版本的显示专用工件上下文 |
| 研磨等待/加工/天车动作 | 研磨FIFO、研磨机`PendingWorkpiece`、研磨天车任务快照 |

M2/M3显示上下文只在动作版本仍有效时更新。正常完成和明确未持件失败在`finally`中按版本清理；X11已确认持件、已放目标但M711/M721未闭环、或M721已确认但研磨FIFO未写入时保留并标记人工确认。对应应急超时/失败继续保留，软件清理成功后按版本清除。显示字段不参与来源选择、目的位判断、PLC握手、锁释放、异常恢复或缓存增删。

页面把相同且完整的“版号+序号”多处记录标成黄色“交接中”，但交接中可能是正常的上下游短暂重叠；页面不会自动合并或删除。版号/序号任一缺失时不归并。中转架物理信号只在前端整轮展示快照5秒内有效且未暂停时作为当前证据；暂停或过期时只标“证据不足”，保留软件身份，不推断现场无板，也不生成新的身份不一致结论。

该快照链路没有协议客户端和设备服务引用，只复制现有内存；页面仅可见时每1秒刷新，隐藏后停止，内容不变时不重建表格行。它不新增设备通信、数据库写入或控制命令，也不参与任何引擎准入和状态迁移。

## 7. 研磨流程

研磨主循环先处理下料，再处理上料：

1. MC65 M730=1确认ST709有板，研磨FIFO必须有对应工件。
2. 研磨天车从ST709取料，吸住后写MC65 M731=1。
3. 空闲且请求数据的研磨机接收参数并完成上料握手。
4. 研磨机请求下料时，必须先确认MC64 M720=1；M720同时表示下料架无板且允许放料，去ST710前再确认一次。
5. 天车把成品放到ST710，Z升安全后只写MC64 M721=1，不写MC64 D200。

## 8. 锁与安全原则

- 机械手1锁在1/2号线前端共享。
- 每条线的前后天车通过 `ZoneMT`（打号机 ↔ 中转架）和 `ZoneTS`（中转架 ↔ ST108/ST606）两把相邻碰撞区锁互斥；中转架动作必须同时持有 `ZoneMT + ZoneTS`。
- ST019/ST020/ST021/ST010使用独立位置锁，跨区域路径按固定顺序拿锁。
- X11读取失败按通信异常处理，不能等价为“磁铁无板”。
- 目的位在真正放料前必须二次确认。
- 工件已经吸住、已经放下但PLC未确认、或关键缓存写入失败时，暂停并保留现场状态。
- 应急任务牌只阻止旧任务继续回写软件状态，不能代替现场物理停机确认。
- 应急中心页面使用统一防重入门闩，防止前端、斜床、动平衡、研磨操作被连点并发调用；该门闩不改变各引擎应急实现。
